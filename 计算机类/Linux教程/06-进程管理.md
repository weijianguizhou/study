
# 进程管理

> **MOC**：[[00-Linux教程MOC|Linux 教程目录]] | **前置**：[[05-用户与权限管理|用户与权限管理]] | **后续**：[[07-Shell脚本基础|Shell 脚本]]

进程是 Linux 系统中活动的主体。每当你在终端敲下一条命令、双击一个图标，或者系统在后台默默执行定时任务，都是在操作**进程**。理解进程的生命周期和管理方式是系统管理和排障的核心能力。

---

## 1. 进程概念

### 1.1 程序 vs 进程

| | 程序（Program） | 进程（Process） |
|------|------|------|
| 在哪里 | 磁盘上 | 内存中 |
| 状态 | 静态的文件 | 动态的执行实例 |
| 可执行 | 不能直接运行 | 正在运行 |
| 类比 | 菜谱 | 正在炒菜 |

```bash
# 程序：磁盘上的文件
$ file /usr/bin/sleep
/usr/bin/sleep: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), ...

$ ls -l /usr/bin/sleep
-rwxr-xr-x 1 root root 35128 Feb  6  2024 /usr/bin/sleep

# 进程：运行中的 sleep
$ sleep 100 &
[1] 12345

$ ps -p 12345 -o pid,ppid,cmd
  PID  PPID CMD
12345  9876 sleep 100
```

### 1.2 PID 与 PPID

**PID（Process ID）**：操作系统分配给每个进程的唯一标识号。

**PPID（Parent PID）**：创建该进程的父进程的 PID。

```bash
# 查看当前 shell 的 PID
$ echo $$
5678

# 查看当前进程的父进程 PID
$ echo $PPID
1234

# 查看 PID 为 1 的进程（所有进程的祖先）
$ ps -p 1 -o pid,ppid,user,cmd
  PID  PPID USER     CMD
    1     0 root     /sbin/init splash
#            ^^
#          PPID=0，因为它是内核直接启动的第一个进程，没有"父进程"
```

### 1.3 进程的家族树：`init` / `systemd`

Linux 启动后，内核会创建 PID=1 的进程。在现代 Linux 发行版中，这通常是 **systemd**（旧系统用 SysV init 或 Upstart）。

```bash
# 查看 PID=1 的进程
$ ps -p 1 -o pid,cmd
  PID CMD
    1 /sbin/init splash
# 或
    1 /lib/systemd/systemd --system --deserialize 42
```

所有其他进程都是 PID=1 的直接或间接后代。

```bash
# 用 pstree 直观查看进程树
$ pstree -p 1 | head -20
systemd(1)─┬─ModemManager(752)─┬─{ModemManager}(776)
           │                   └─{ModemManager}(778)
           ├─accounts-daemon(758)─┬─{accounts-daemon}(769)
           │                      └─{accounts-daemon}(807)
           ├─cron(791)
           ├─dbus-daemon(788)
           ├─gnome-keyring-d(6499)─┬─{gnome-keyring-d}(6504)
           │                       ├─{gnome-keyring-d}(6505)
           │                       └─{gnome-keyring-d}(6506)
           ├─NetworkManager(793)─┬─{NetworkManager}(865)
           │                     └─{NetworkManager}(906)
           ├─polkitd(883)─┬─{polkitd}(892)
           │              └─{polkitd}(893)
           ├─rsyslogd(860)─┬─{rsyslogd}(907)
           │               ├─{rsyslogd}(908)
           │               └─{rsyslogd}(909)
           ├─sshd(847)
           ├─systemd(1482)─┬─(sd-pam)(1486)
           │               ├─dbus-daemon(1501)
           │               ├─gvfs-afc-volume(3712)─┬─{gvfs-afc-volume}(3713)
           │               │                       └─{gvfs-afc-volume}(3717)
```

### 1.4 前台进程 vs 后台进程

```bash
# 前台进程：占据终端，阻塞输入
$ sleep 30
# 光标停在这里，你不能输入别的命令，直到 30 秒后或 Ctrl+C

# 后台进程：用 & 放到后台，终端立即返回
$ sleep 30 &
[1] 13579
$ # 立即可以输入下一条命令！

# 挂起前台进程：Ctrl+Z
$ sleep 300
^Z
[1]+  Stopped                 sleep 300
$ # 进程被暂停（Stopped），终端恢复可用
```

### 1.5 守护进程（Daemon）

守护进程是在后台运行、不关联任何终端、通常提供系统服务的进程。

```bash
# 常见的守护进程
$ ps aux | grep -E "(sshd|cron|rsyslog|nginx)" | grep -v grep
root       847  0.0  0.0 121796  5924 ?        Ss   Sep10   0:00 /usr/sbin/sshd -D
root       791  0.0  0.0  30656  3124 ?        Ss   Sep10   0:01 /usr/sbin/cron -f
syslog     860  0.0  0.0 260988  4624 ?        Ssl  Sep10   0:05 /usr/sbin/rsyslogd -n

# 注意：TTY 字段是 ? —— 说明它们不属于任何终端
```

## 2. 查看进程

### 2.1 `ps` —— 进程快照

#### BSD 风格：`ps aux`

```bash
$ ps aux | head
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.1 169356 13384 ?        Ss   09:00   0:03 /sbin/init splash
root           2  0.0  0.0      0     0 ?        S    09:00   0:00 [kthreadd]
root           3  0.0  0.0      0     0 ?        I<   09:00   0:00 [rcu_gp]
root           4  0.0  0.0      0     0 ?        I<   09:00   0:00 [rcu_par_gp]
root           5  0.0  0.0      0     0 ?        I<   09:00   0:00 [slub_flushwq]
root           6  0.0  0.0      0     0 ?        I<   09:00   0:00 [netns]
root           8  0.0  0.0      0     0 ?        I<   09:00   0:00 [kworker/0:0H-events_highpri]
root          10  0.0  0.0      0     0 ?        I<   09:00   0:00 [mm_percpu_wq]
root          13  0.0  0.0      0     0 ?        I    09:00   0:00 [rcu_tasks_kthread]
```

**各列含义**：

| 列 | 含义 | 说明 |
|----|------|------|
| `USER` | 进程所有者 | 谁启动的 |
| `PID` | 进程 ID | 唯一标识 |
| `%CPU` | CPU 使用率 | 占单个 CPU 核心的百分比 |
| `%MEM` | 物理内存使用率 | 占总内存的百分比 |
| `VSZ` | 虚拟内存大小 | 单位 KB，包含 swap 和共享库 |
| `RSS` | 常驻物理内存大小 | 单位 KB，实际占用的物理内存 |
| `TTY` | 控制终端 | `?` 表示无终端（守护进程），`pts/0` 表示伪终端 |
| `STAT` | 进程状态 | 见下方状态码表 |
| `START` | 启动时间 | 日期或时间 |
| `TIME` | 累积 CPU 时间 | 进程自启动以来消耗的 CPU 总时间 |
| `COMMAND` | 命令行 | 启动该进程的命令 |

> 方括号 `[kthreadd]` 表示内核线程。

#### Unix 风格：`ps -ef`

```bash
$ ps -ef | head
UID          PID    PPID  C STIME TTY          TIME CMD
root           1       0  0 09:00 ?        00:00:03 /sbin/init splash
root           2       0  0 09:00 ?        00:00:00 [kthreadd]
root           3       2  0 09:00 ?        00:00:00 [rcu_gp]
root           4       2  0 09:00 ?        00:00:00 [rcu_par_gp]
```

| 列 | 含义 |
|----|------|
| `UID` | 用户名 |
| `PID` | 进程 ID |
| `PPID` | 父进程 ID |
| `C` | CPU 使用率（整数，过时的格式） |
| `STIME` | 启动时间 |
| `TTY` | 控制终端 |
| `TIME` | CPU 时间 |
| `CMD` | 命令 |

#### 进程状态码

```bash
$ ps aux | awk '{print $8}' | sort | uniq -c | sort -rn
    150 I<
    120 S
     50 I
     30 Ss
     15 Ssl
     10 R
      5 Z
      2 D
      1 T
```

| 状态码 | 全称 | 含义 |
|--------|------|------|
| `R` | Running / Runnable | 正在运行或在运行队列中等待 |
| `S` | Interruptible Sleep | 可中断睡眠（等待事件完成，如等待 I/O） |
| `D` | Uninterruptible Sleep | 不可中断睡眠（通常在等待 I/O，接收不到信号） |
| `Z` | Zombie | 僵尸进程：已终止但父进程尚未回收（wait） |
| `T` | Stopped | 被作业控制信号暂停（如 Ctrl+Z） |
| `I` | Idle | 内核空闲线程 |
| `<` | 高优先级（nice 值更低） | 不是独立状态，附加在其他状态码后 |
| `N` | 低优先级（nice 值更高） | |
| `s` | Session Leader | 会话领导者 |
| `l` | Multi-threaded | 多线程进程 |
| `+` | Foreground | 前台进程组中 |

```bash
# 查看僵尸进程
$ ps aux | awk '$8 ~ /Z/ {print $2, $8, $11}'
13456 Z [defunct] <defunct>
# 僵尸进程的 COMMAND 通常显示为 <defunct> 或 [程序名] <defunct>
```

#### 自定义输出

```bash
# 按内存使用率排序，显示前 10
$ ps -eo pid,ppid,user,%mem,%cpu,comm --sort=-%mem | head -11
  PID  PPID USER     %MEM %CPU COMMAND
 3474  1482 john     12.3  0.0 chrome
 3456  1482 john      8.5  0.0 code
 3580  1482 john      5.2  0.0 slack
 2560  2456 john      4.1  0.0 gnome-shell
 1498  1482 john      3.8  0.0 Xorg

# 按 CPU 使用率排序
$ ps -eo pid,user,%cpu,%mem,args --sort=-%cpu | head -10

# 显示完整命令行（不截断）
$ ps -eo pid,args --width 2000 | grep nginx

# 查看某个用户的全部进程
$ ps -u john -o pid,%cpu,%mem,cmd
```

#### 查找特定进程

```bash
# 按 PID 查看
$ ps -p 12345 -o pid,ppid,user,cmd

# 按名称查找
$ ps -C nginx -o pid,user,cmd

# 组合使用
$ ps aux | grep nginx
$ ps -ef | grep sshd
```

### 2.2 `top` —— 实时进程监视器

```bash
$ top
top - 14:23:15 up  5:23,  3 users,  load average: 0.45, 0.32, 0.28
Tasks: 285 total,   1 running, 283 sleeping,   0 stopped,   1 zombie
%Cpu(s):  2.3 us,  1.0 sy,  0.0 ni, 96.5 id,  0.2 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :  15894.2 total,   3456.7 free,   7890.3 used,   4547.2 buff/cache
MiB Swap:   2048.0 total,   1532.1 free,    515.9 used.   6234.2 avail Mem

  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
 3474 john      20   0 4687236 543216 123456 S   2.0  12.3   5:23.12 chrome
 3456 john      20   0 3678900 324567  65432 S   1.5   8.5   3:12.45 code
    1 root      20   0  169356  13384   8764 S   0.0   0.3   0:03.12 systemd
```

**top 首行（系统概览）解读**：

| 内容 | 含义 |
|------|------|
| `14:23:15` | 当前系统时间 |
| `up 5:23` | 系统自上次启动以来运行了 5 小时 23 分 |
| `3 users` | 当前登录用户数 |
| `load average: 0.45, 0.32, 0.28` | 过去 1、5、15 分钟的平均负载（可运行+不可中断状态进程数 / CPU 核心数的反映） |

**CPU 行解读**：

| 字段 | 含义 |
|------|------|
| `us` | 用户空间 CPU 时间（用户程序） |
| `sy` | 内核空间 CPU 时间（系统调用） |
| `ni` | 低优先级（nice）用户空间 CPU 时间 |
| `id` | 空闲 CPU 时间 |
| `wa` | 等待 I/O 的 CPU 时间 |
| `hi` | 硬件中断处理时间 |
| `si` | 软件中断处理时间 |
| `st` | 被虚拟机偷走的时间（运行在虚拟化环境中才有意义） |

**内存行解读**：

| 字段 | 含义 |
|------|------|
| `total` | 物理内存总量 |
| `free` | 完全未使用的内存 |
| `used` | 已使用的内存 |
| `buff/cache` | 用作缓冲区和缓存的内存（需要时可回收用于程序） |
| `avail Mem` | 可供新程序使用的估算值（= free + 可回收的 buff/cache） |

> Linux 的内存管理非常激进：它会把空闲内存用于缓存文件，以提高性能。因此 `free` 很小不一定是内存不足，关键看 `available`。

**进程信息列**：

| 列 | 含义 |
|----|------|
| `PID` | 进程 ID |
| `USER` | 进程所有者 |
| `PR` | 进程优先级（内核视角，`rt` 表示实时优先级） |
| `NI` | nice 值（-20 到 19） |
| `VIRT` | 虚拟内存总量 |
| `RES` | 常驻物理内存（= 非 swap 部分） |
| `SHR` | 共享内存 |
| `S` | 进程状态（R/S/D/Z/T） |
| `%CPU` | CPU 使用率 |
| `%MEM` | 物理内存使用率 |
| `TIME+` | 累积 CPU 时间 |
| `COMMAND` | 命令名 |

#### `top` 交互命令

| 按键 | 功能 |
|------|------|
| `h` | 显示帮助 |
| `q` | 退出 |
| `k` | 杀死进程（会提示输入 PID 和信号类型） |
| `r` | renice（更改进程优先级） |
| `1` | 切换显示每个 CPU 核心的使用率（展开/折叠） |
| `t` | 切换 CPU 显示模式（指标/条形图/隐藏） |
| `m` | 切换内存显示模式（指标/条形图/隐藏） |
| `M` | 按内存使用率排序（`%MEM` 降序） |
| `P` | 按 CPU 使用率排序（`%CPU` 降序） |
| `N` | 按 PID 排序 |
| `T` | 按运行时间排序（`TIME+` 降序） |
| `c` | 切换显示完整命令行（显示/隐藏程序路径和参数） |
| `V` | 树状视图（父子进程关系） |
| `u` | 按用户名过滤 |
| `o` | 自定义排序列 |
| `f` | 选择显示哪些列 |
| `d` | 设置刷新间隔（秒） |
| `W` | 保存当前配置到 `~/.toprc` |
| `Z` | 更改配色方案 |

```bash
# 启动 top 并指定刷新间隔 2 秒
$ top -d 2

# 只显示特定用户的进程
$ top -u john

# 启动时按内存排序
$ top -o %MEM

# 批处理模式（适合脚本中抓取）
$ top -b -n 1 | head -20
```

### 2.3 `htop` —— 增强版 top

```bash
# 安装 htop
$ sudo apt install htop    # Debian/Ubuntu
$ sudo dnf install htop    # Fedora/CentOS

# 启动
$ htop
```

`htop` 的优势：
- 彩色显示，直观易读
- 支持鼠标点击操作（选择进程、排序列等）
- 可以水平/垂直滚动
- 树状视图（`F5`）
- 直接按 `F9` 杀死进程（列出可用信号）
- 按 `F7` / `F8` 调整 nice 值
- 支持搜索（`F3`）、过滤（`F4`）

**快捷键**：

| 功能键 | 功能 |
|--------|------|
| `F1` | 帮助 |
| `F2` | 设置 |
| `F3` | 搜索进程 |
| `F4` | 过滤 |
| `F5` | 树状视图 |
| `F6` | 切换排序方式 |
| `F7` | 降低 nice 值（提高优先级，需 root） |
| `F8` | 提高 nice 值（降低优先级） |
| `F9` | 杀死进程（信号选择） |
| `F10` | 退出 |

```bash
# htop 的命令行选项
$ htop -u john           # 只显示 john 的进程
$ htop -p 1234,5678      # 只显示指定 PID 的进程
$ htop -d 10             # 刷新间隔 0.1 秒（单位是 1/10 秒）
$ htop -t                # 树状视图启动
```

## 3. 进程控制

### 3.1 后台运行：`&`

```bash
# 在命令末尾加 & 即可放到后台
$ sleep 100 &
[1] 23456

# [1] 是作业号（job number），23456 是 PID

# 查看后台作业
$ jobs
[1]+  Running                 sleep 100 &

# 启动多个后台作业
$ sleep 200 &
[2] 23457
$ sleep 300 &
[3] 23458

$ jobs
[1]   Running                 sleep 100 &
[2]-  Running                 sleep 200 &
[3]+  Running                 sleep 300 &
# + 号标注的是"当前作业"（fg 默认操作的对象）
# - 号标注的是"上一个作业"
```

### 3.2 `jobs` —— 查看后台作业

```bash
$ jobs
[1]   Done                    sleep 100
[2]-  Running                 sleep 200 &
[3]+  Stopped                 sleep 300

# jobs 常用选项
$ jobs -l    # 同时显示 PID
[1]  23456 Done                    sleep 100
[2]- 23457 Running                 sleep 200 &
[3]+ 23458 Stopped                 sleep 300

$ jobs -r    # 只显示运行中的作业
$ jobs -s    # 只显示暂停的作业
$ jobs -p    # 只显示作业的 PID
```

### 3.3 `fg` —— 将后台作业调回前台

```bash
# 将当前作业（带 + 号）调回前台
$ fg
sleep 300
# 现在 sleep 300 占据终端

# 将指定作业号调回前台
$ fg %2
sleep 200

# 按作业号前缀匹配
$ fg %sl     # 匹配以 sl 开头的命令
```

### 3.4 `bg` —— 让暂停的后台作业继续运行

```bash
# 启动一个前台进程
$ sleep 500
^Z
[1]+  Stopped                 sleep 500

# 让它继续在后台运行
$ bg
[1]+ sleep 500 &

$ jobs
[1]+  Running                 sleep 500 &
```

### 3.5 `Ctrl+Z` 与 `Ctrl+C`

| 快捷键 | 发送信号 | 效果 |
|--------|----------|------|
| `Ctrl+C` | SIGINT (2) | 中断（终止）前台进程 |
| `Ctrl+Z` | SIGTSTP (20) | 挂起（暂停）前台进程 |
| `Ctrl+\` | SIGQUIT (3) | 退出并产生 core dump |
| `Ctrl+D` | EOF | 不是信号！输入结束标记，通常退出 shell |

```bash
# 测试 Ctrl+C vs Ctrl+Z 的区别
$ sleep 300
^C        # Ctrl+C：进程被终止
$

$ sleep 300
^Z        # Ctrl+Z：进程被暂停
[1]+  Stopped                 sleep 300
$         # 终端恢复可用

$ fg      # 把暂停的进程调回来
sleep 300 # 继续执行
```

### 3.6 `nohup` —— 忽略挂断信号

当终端关闭或 SSH 断开时，shell 会向所有子进程发送 SIGHUP 信号。`nohup` 让进程忽略此信号。

```bash
# 格式：nohup 命令 &
$ nohup long_running_script.sh &
[1] 25678
nohup: ignoring input and appending output to 'nohup.out'

# 输出默认重定向到 nohup.out
$ cat nohup.out
Starting processing...
Processing file 1/100...
Processing file 2/100...
...

# 自定义输出文件
$ nohup ./backup.sh > backup.log 2>&1 &

# 验证进程仍在运行
$ ps aux | grep backup.sh
john   25678  0.5  1.2  345678  56789 ?  S  15:00  0:05 ./backup.sh

# TTY 字段变成 ? —— 说明已经脱离终端
```

### 3.7 `disown` —— 从作业列表中移除

```bash
# 场景：你已经启动了一个后台进程，忘记用 nohup
# 现在需要注销，但不想让进程死亡

$ long_task &
[1] 34567

# 方法1：disown 该作业
$ disown %1
$ jobs    # 作业不再出现在列表中
# 但 PID=34567 的进程仍在运行，且已脱离终端控制

# 方法2：disown 所有作业
$ disown -a

# 方法3：标记作业使其在 shell 退出时不收到 SIGHUP
$ disown -h %1
```

> `disown` vs `nohup`：
> - `nohup`：启动时就给进程设置忽略 SIGHUP
> - `disown`：事后补救，让作业从 shell 的作业控制中脱离

## 4. 终止进程与信号

### 4.1 信号（Signal）概念

信号是 Linux 中进程间通信的一种异步通知机制。当某个事件发生时，内核向目标进程发送一个信号，进程可以：
1. 执行默认操作（终止、核心转储、忽略）
2. 捕获信号并执行自定义处理函数
3. 忽略信号（某些信号不可忽略，如 SIGKILL、SIGSTOP）

### 4.2 常见信号速查

```bash
# 列出所有信号
$ kill -l
 1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL       5) SIGTRAP
 6) SIGABRT      7) SIGBUS       8) SIGFPE       9) SIGKILL     10) SIGUSR1
11) SIGSEGV     12) SIGUSR2     13) SIGPIPE     14) SIGALRM     15) SIGTERM
16) SIGSTKFLT   17) SIGCHLD     18) SIGCONT     19) SIGSTOP     20) SIGTSTP
21) SIGTTIN     22) SIGTTOU     23) SIGURG      24) SIGXCPU     25) SIGXFSZ
26) SIGVTALRM   27) SIGPROF     28) SIGWINCH    29) SIGIO       30) SIGPWR
31) SIGSYS      34) SIGRTMIN    35) SIGRTMIN+1  ...           64) SIGRTMAX
```

**最常用的信号**：

| 编号 | 名称 | 含义 | 默认行为 | 可否捕获 |
|:----:|------|------|----------|:--------:|
| 1 | `SIGHUP` | 挂断（终端关闭/配置重载） | 终止 | 是 |
| 2 | `SIGINT` | 中断（Ctrl+C） | 终止 | 是 |
| 3 | `SIGQUIT` | 退出（Ctrl+\），生成 core dump | 终止+core | 是 |
| 9 | `SIGKILL` | 强制杀死 | **终止（不可捕获/忽略）** | **否** |
| 15 | `SIGTERM` | 终止（kill 默认） | 终止 | 是 |
| 17 | `SIGCHLD` | 子进程状态改变 | 忽略 | 是 |
| 18 | `SIGCONT` | 继续执行（恢复暂停的进程） | 继续 | 是 |
| 19 | `SIGSTOP` | 暂停 | **暂停（不可捕获/忽略）** | **否** |
| 20 | `SIGTSTP` | 终端暂停（Ctrl+Z） | 暂停 | 是 |

### 4.3 `kill` —— 向进程发送信号

```bash
# 基本用法：kill [-signal] PID

# 1. 优雅终止（默认 SIGTERM = 15）
$ kill 12345

# 2. 强制杀死（SIGKILL = 9）—— 最后的杀手锏
$ kill -9 12345
$ kill -KILL 12345    # 等价

# 3. 重新加载配置（SIGHUP = 1）
$ kill -HUP 12345
$ kill -1 12345

# 4. 暂停进程（SIGSTOP = 19）
$ kill -STOP 12345

# 5. 恢复暂停的进程（SIGCONT = 18）
$ kill -CONT 12345

# 6. 中断（等价于 Ctrl+C，SIGINT = 2）
$ kill -INT 12345

# 测试：看不同信号的实际效果
$ sleep 500 &
[1] 23456

$ kill 23456       # 默认 SIGTERM
[1]+  Terminated              sleep 500

$ sleep 500 &
[1] 23457

$ kill -9 23457    # SIGKILL
[1]+  Killed                  sleep 500
```

### 4.4 `killall` —— 按名称杀死进程

```bash
# 杀死所有名为 nginx 的进程
$ sudo killall nginx

# 等价于：先 pgrep 再逐个 kill
$ pgrep nginx | xargs kill

# 强制杀死
$ sudo killall -9 nginx

# 确认杀的进程（交互模式）
$ killall -i nginx
Kill nginx(45678) ? (y/N) y
Kill nginx(45679) ? (y/N) n

# 只杀死属于某用户的进程
$ killall -u john bad-app

# 只杀死运行超过指定时间的进程
$ killall -o 10m myapp    # 杀死运行超过 10 分钟的
$ killall -y 30m myapp    # 杀死运行不到 30 分钟的
```

### 4.5 `pkill` —— 按模式杀死进程

```bash
# pkill 比 killall 更灵活，支持正则匹配

# 杀死所有名称以 nginx 开头的进程
$ pkill nginx

# 杀死某用户的所有进程
$ pkill -u john

# 杀死某终端的所有进程
$ pkill -t pts/2

# 杀死父进程为某 PID 的所有子进程
$ pkill -P 1482

# 发送 SIGHUP 给所有匹配的进程
$ pkill -HUP nginx

# 列出匹配的进程但不杀（安全预览）
$ pgrep -l nginx
45678 nginx
45679 nginx
$ pkill nginx
```

### 4.6 信号实战案例

```bash
# ★ 案例1：优雅重启 Nginx
$ sudo kill -HUP $(cat /var/run/nginx.pid)
# SIGHUP 告诉 nginx master 重新加载配置文件，不中断现有连接

# ★ 案例2：杀掉程序时给它清理的机会
$ kill 54321               # 先发 SIGTERM，让它有机会保存状态
$ sleep 2                  # 等 2 秒
$ kill -0 54321 && kill -9 54321   # 如果还活着，强制杀死
# kill -0 不发信号，只检查进程是否存在（常用于 shell 脚本测试）

# ★ 案例3：暂停一个占用 CPU 的编译任务
$ kill -STOP 12345         # 暂停
# ... 做其他事情 ...
$ kill -CONT 12345         # 恢复

# ★ 案例4：处理僵尸进程
$ ps aux | grep Z
john   13456  0.0  0.0      0     0 ?        Z    Sep15   0:00 [process] <defunct>
# 僵尸进程的 PPID 就是罪魁祸首——父进程没有 wait()
$ ps -o pid,ppid,stat,cmd -p 13456
  PID  PPID STAT CMD
13456  9876 Z    [process] <defunct>
# 找到父进程 PID=9876
$ kill -CHLD 9876          # 向父进程发 SIGCHLD，提示它回收子进程
# 如果无效，只能杀死父进程（子进程会被 init/systemd 收养并回收）
$ kill -9 9876
```

## 5. 进程优先级

### 5.1 nice 值与优先级

| 概念 | 范围 | 含义 |
|------|:----:|------|
| **nice 值** | -20（最高优先级） ~ 19（最低优先级） | 用户友好的优先级偏移量 |
| **默认值** | 0 | 普通优先级的基准 |
| **权限** | 普通用户只能调高（降低自己的优先级，做"好"事） | root 可以任意调整 |

```bash
# nice 值高 = 对其他进程更 nice = 自己让出 CPU = 优先级低
# nice 值低 = 对 CPU 更 greedy = 优先级高

# 查看进程的 nice 值
$ ps -eo pid,ni,comm | grep -E "PID|nginx"
  PID  NI COMMAND
  847   0 nginx
  848   0 nginx

# top 中的 NI 列
$ top -b -n 1 | head -20
```

### 5.2 `nice` —— 以指定优先级启动程序

```bash
# 语法：nice -n N command

# 以低优先级（nice=10）启动一个压缩任务
$ nice -n 10 tar -czf backup.tar.gz /home/john/projects/

# 以最高用户级优先权启动（需要 root）
$ sudo nice -n -10 /usr/local/bin/critical-task

# 查看效果
$ nice -n 10 sleep 100 &
[1] 34567
$ ps -l -p 34567
F S   UID     PID    PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1000   34567    1482  0  90  10 -  ...  -      pts/0    00:00:00 sleep
#       PRI = 90, NI = 10
```

### 5.3 `renice` —— 调整运行中进程的优先级

```bash
# 语法：renice -n N -p PID

# 降低一个正在运行的任务优先级
$ renice -n 10 -p 34567
34567 (process ID) old priority 0, new priority 10

# 提高优先级（需要 sudo）
$ sudo renice -n -5 -p 34567
34567 (process ID) old priority 10, new priority -5

# 调整某用户所有进程的优先级
$ sudo renice -n 5 -u john
1000 (user ID) old priority 0, new priority 5

# 调整某进程组所有进程的优先级
$ sudo renice -n -10 -g 1482
1482 (process group ID) old priority 0, new priority -10
```

### 5.4 优先级实战

```bash
# ★ 案例：在不影响交互式工作的情况下运行 CPU 密集型计算
# 启动计算任务，nice 值设为 19（最低优先级）
$ nice -n 19 python3 crunch_numbers.py > results.txt 2>&1 &
[1] 56789

# 监控影响
$ top -p 56789
# 你会看到 %CPU 很高，但系统的交互响应依然流畅
# 因为 nice 19 的任务在调度时会被 nice 0 的任务抢占

# ★ 案例：加速关键服务
# 查看当前 Web 服务器优先级
$ ps -eo pid,ni,comm | grep nginx
  847   0 nginx
  848   0 nginx

# 提高 Web 服务器的 CPU 调度优先级
$ sudo renice -n -10 -p 847
$ sudo renice -n -10 -p 848

# 验证
$ ps -eo pid,ni,comm | grep nginx
  847 -10 nginx
  848 -10 nginx
```

## 6. systemd 服务管理

### 6.1 什么是 systemd

systemd 是现代 Linux 发行版（Ubuntu 15.04+、Debian 8+、CentOS 7+、Fedora 15+）的标准 init 系统。它负责：

- **系统初始化**：启动时挂载文件系统、启动基础服务
- **服务管理**：启动、停止、重启、监控系统服务
- **日志管理**：通过 `journald` 收集统一日志
- **定时任务**：通过 timer 单元替代 cron
- **设备管理**、**网络管理**、**登录管理**等

```bash
# 确认你的系统使用的是 systemd
$ ps -p 1 -o pid,cmd
  PID CMD
    1 /sbin/init splash
# 或
    1 /lib/systemd/systemd --system --deserialize ...
```

### 6.2 `systemctl` —— 服务管理

#### 查看服务状态

```bash

     Active: active (running) since Mon 2024-09-15 09:00:23 CST; 5h 24min ago

             man:sshd_config(5)
```

**状态解读**：

**子状态**：


```bash

$ sudo systemctl reload nginx
# 注意：不是所有服务都支持 reload，取决于服务的实现

# 如果支持 reload 就 reload，否则 restart（智能重启）
$ sudo systemctl reload-or-restart nginx

# 重载 systemd 自身配置（修改了 .service 文件后需要）
$ sudo systemctl daemon-reload
```

```bash
$ sudo systemctl disable --now nginx
```

## 7. 定时任务

### 7.1 `crontab` —— 设置定时任务

```bash
# 编辑当前用户的 crontab（首次需选择编辑器）
$ crontab -e
# 选择一个编辑器。更改时请选择数字。我们建议您选择 1、2 或 3
#   1. /bin/nano  <---- 最简单的
#   2. /usr/bin/vim.basic
#   3. /usr/bin/vim.tiny
```

#### crontab 格式

```
# ┌───────────── 分钟 (0 - 59)
# │ ┌───────────── 小时 (0 - 23)
# │ │ ┌───────────── 日 (1 - 31)
# │ │ │ ┌───────────── 月 (1 - 12)
# │ │ │ │ ┌───────────── 星期 (0 - 7, 0和7都表示周日)
# │ │ │ │ │
# * * * * * 命令
```

```bash
# ★ 经典示例
# 每天凌晨 2:00 数据库备份
0 2 * * * /home/john/scripts/backup_db.sh >> /var/log/backup.log 2>&1

# 每 5 分钟检查服务状态
*/5 * * * * /home/john/scripts/healthcheck.sh

# 每小时的第 0 分钟
0 * * * * /home/john/scripts/hourly_task.sh

# 工作日（周一到周五）上午 9 点到下午 5 点，每小时执行一次
0 9-17 * * 1-5 /home/john/scripts/work_hours.sh

# 每月 1 号和 15 号凌晨 3:30
30 3 1,15 * * /home/john/scripts/biweekly_report.sh

# 每年 1 月 1 日 0:00
0 0 1 1 * echo "Happy New Year!" >> ~/newyear.log

# 每 30 秒（cron 最小精度是 1 分钟，小于 1 分钟需用 sleep 技巧）
* * * * * /path/to/script.sh
* * * * * sleep 30; /path/to/script.sh

# ★ 特殊时间关键字
@reboot     /path/to/script.sh          # 系统启动时执行
@yearly     0 0 1 1 *                   # 每年 1 月 1 日 0:00
@annually   0 0 1 1 *                   # 同 @yearly
@monthly    0 0 1 * *                   # 每月 1 日 0:00
@weekly     0 0 * * 0                   # 每周日 0:00
@daily      0 0 * * *                   # 每天 0:00
@midnight   0 0 * * *                   # 同 @daily
@hourly     0 * * * *                   # 每小时 0 分
```

### 7.2 `crontab` 常用操作

```bash
# 从文件导入 crontab

$ crontab -l
# 会显示 my-crontab-file.txt 的内容（覆盖已有内容！）
```

### 7.4 systemd Timer（现代替代方案）

```bash
# systemd 也提供定时任务功能，可以替代 cron
# 优点：精确到秒、与 systemd 生态集成、日志由 journalctl 统一管理

# 示例：创建一个每 5 分钟运行一次的 timer
$ sudo cat /etc/systemd/system/healthcheck.service
[Unit]
Description=Health Check Service

[Service]
Type=oneshot
ExecStart=/home/john/scripts/healthcheck.sh
User=john

$ sudo cat /etc/systemd/system/healthcheck.timer
```

### 场景一：追查 CPU 杀手

```bash
# 用户反映服务器 CPU 100%，找到并终止罪魁祸首

# 1. 用 top 快速定位
$ top
```

### 场景二：安全地终止一组相关进程

```bash
# 需求：一个 complex-app 产生了多个子进程，全部终止
# 错误做法：ps aux | grep complex-app | awk '{print $2}' | xargs kill -9
# 风险：可能误杀 grep 进程或其他包含该关键词的无关进程

# 正确做法1：找到进程组 leader，用负数 PID 向整个进程组发信号
$ pgrep -o complex-app   # 找最早的（可能是 leader）
12345
$ kill -TERM -12345      # 注意是 -12345（负数），向进程组发信号

# 正确做法2：用 pkill
$ pkill complex-app

# 正确做法3：推荐——优雅终止：先 TERM，等 5 秒，再 KILL
#!/bin/bash
pids=$(pgrep -f complex-app)
if [ -n "$pids" ]; then
    echo "Sending SIGTERM to: $pids"
    kill $pids
    sleep 5
    # 检查还有没有存活的
    pids=$(pgrep -f complex-app)
    if [ -n "$pids" ]; then
        echo "Sending SIGKILL to: $pids"
        kill -9 $pids
    fi
fi
```

### 场景三：编写进程监控脚本

```bash
#!/bin/bash
# process_monitor.sh - 监控进程内存使用，超过阈值报警

THRESHOLD_MB=2000            # 阈值 2000MB
CHECK_INTERVAL=10            # 检查间隔 10 秒
TARGET_PROCESS="chrome"      # 目标进程名（部分匹配）
LOG_FILE="/var/log/proc_monitor.log"

while true; do
    # 查找目标进程
    pids=$(pgrep -f "$TARGET_PROCESS")
    if [ -z "$pids" ]; then
        echo "$(date): $TARGET_PROCESS is not running" >> "$LOG_FILE"
        sleep "$CHECK_INTERVAL"
        continue
    fi

    for pid in $pids; do
        # 获取 RSS（常驻内存，单位 KB）
        rss_kb=$(ps -p "$pid" -o rss= 2>/dev/null)
        if [ -z "$rss_kb" ]; then
            continue    # 进程可能在查询瞬间退出了
        fi

        rss_mb=$((rss_kb / 1024))
        if [ "$rss_mb" -gt "$THRESHOLD_MB" ]; then
            echo "[ALERT] $(date): PID=$pid RSS=${rss_mb}MB exceeds ${THRESHOLD_MB}MB" >> "$LOG_FILE"

            # 可选：自动处理
            # kill -TERM "$pid"
        fi
    done

    sleep "$CHECK_INTERVAL"
done
```

## 总结

| 层面 | 命令 | 核心功能 |
|------|------|----------|
| **进程信息** | `ps`, `top`, `htop`, `pstree` | 查看系统中有哪些进程、它们的状态和资源占用 |
| **进程搜索** | `pgrep`, `pidof` | 按名称或其他属性查找特定进程 |
| **前后台控制** | `&`, `jobs`, `fg`, `bg`, `Ctrl+Z`, `Ctrl+C` | 管理进程在哪个"舞台"上运行 |
| **信号发送** | `kill`, `killall`, `pkill` | 向进程发送各类信号：终止、暂停、重载等 |
| **进程优先级** | `nice`, `renice` | 调整进程的 CPU 调度优先级 |
| **脱离终端** | `nohup`, `disown` | 让进程在终端关闭后继续存活 |
| **服务管理** | `systemctl`, `journalctl` | 管理系统服务（守护进程）的生命周期和日志 |
| **定时任务** | `crontab`, `systemd timer` | 在指定时间自动执行命令 |

**核心法则**：

1. **`ps aux` 是第一反应**：系统出问题时先看进程列表
2. **绝不滥用 `kill -9`**：`SIGKILL` 不给进程任何清理的机会，文件可能不完整、锁可能残留
3. **优雅终止三步走**：`SIGTERM`（15）→ 等待 → `SIGKILL`（9），给进程一个体面的告别
4. **后台任务注意脱离终端**：`nohup` 或 `disown`，否则登出后任务也会退出
5. **`top` 的 `load average` 不只看数字大小，要看相对 CPU 核心数的比例**
6. **用 `journalctl -xeu service` 排查服务故障**，而不是去翻 /var/log 的各个角落
