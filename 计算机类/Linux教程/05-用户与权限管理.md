
# 用户与权限管理

> **MOC**：[[00-Linux教程MOC|Linux 教程目录]] | **前置**：[[04-文本处理|文本处理]] | **后续**：[[06-进程管理|进程管理]]

Linux 是一个多用户操作系统，多个用户可以同时登录同一台机器、执行各自的任务而互不干扰。用户与权限管理是 Linux 系统安全体系的基石——**什么人**有权对**什么文件**执行**什么操作**，都由这套机制精确控制。

---

## 1. 用户与组的概念

### 1.1 用户（User）

每个使用 Linux 系统的人都被分配一个**用户账号**。操作系统通过数字 ID 来标识用户，而非用户名。

**UID（User ID）**：用户标识号，是 Linux 内核识别用户的唯一凭据：

| UID 范围 | 用途 |
|-----------|------|
| `0` | root 超级管理员 |
| `1` ~ `999` | 系统用户（服务账户），如 `sshd`、`mysql`、`www-data` |
| `1000+` | 普通用户 |

> 现代发行版（CentOS 7+、Ubuntu）预留 1~999 给系统用户；旧版可能只到 499。

```bash
# 查看当前用户的 UID
$ id -u
1000

# root 的 UID 永远是 0
$ echo $UID
1000
```

你可以同时属于多个**组**。每个用户有且只有一个**主组（primary group）**，及零到多个**附加组（supplementary groups）**。

### 1.2 组（Group）

**GID（Group ID）**：组标识号，把具有相同权限的用户组织在一起。

- 主组：用户创建文件时默认所属的组（写在 `/etc/passwd` 中）
- 附加组：用户额外拥有的组身份（写在 `/etc/group` 中）

```bash
# 查看当前用户所属的所有组
$ groups
john sudo docker developers
```

### 1.3 `/etc/passwd` —— 用户账户数据库

```bash
$ cat /etc/passwd | head -5
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
```

每一行代表一个用户，由 `:` 分隔为 7 个字段：

| 位置 | 字段名 | 含义 | 示例 |
|------|--------|------|------|
| 1 | 用户名 | 登录名 | `john` |
| 2 | 密码 | `x` 表示密码已移至 `/etc/shadow` | `x` |
| 3 | UID | 用户 ID | `1000` |
| 4 | GID | 主组 ID | `1000` |
| 5 | GECOS | 描述信息（全名/电话/办公地址/其他） | `John Doe,,,` |
| 6 | 家目录 | 用户登录后的起始目录 | `/home/john` |
| 7 | Shell | 用户默认登录 shell | `/bin/bash` |

> `nologin` 或 `false` 表示该账户不可交互登录（如系统服务账户）。

### 1.4 `/etc/shadow` —— 加密密码存储

```bash
$ sudo cat /etc/shadow | grep john | head -1
john:$y$j9T$...HASH...:19600:0:99999:7:::
```

只有 root 可以读取。字段（以 `:` 分隔）：

| 位置 | 字段 | 含义 |
|------|------|------|
| 1 | 用户名 | 与 `/etc/passwd` 对应 |
| 2 | 加密密码 | `$y` 表示 yescrypt，`$6$` 为 SHA-512，`$1$` 为 MD5，`!!` 表示无密码（锁定） |
| 3 | 上次修改 | 从 1970-01-01 起的天数 |
| 4 | 最小天数 | 两次改密码的最小间隔 |
| 5 | 最大天数 | 密码有效期（99999 = 不过期） |
| 6 | 警告天数 | 到期前多少天警告 |
| 7 | 不活动 | 到期后多少天禁用账户 |
| 8 | 过期日期 | 从 1970-01-01 起的天数，到期后锁定账户 |
| 9 | 保留字段 | 暂未使用 |

```bash
# 查看某用户密码状态
$ sudo passwd -S john
john P 01/01/2024 0 99999 7 -1
# P=有密码, L=锁定, NP=无密码
```

### 1.5 `/etc/group` —— 组信息

```bash
$ cat /etc/group | head -5
root:x:0:
daemon:x:1:
bin:x:2:
sys:x:3:
adm:x:4:syslog,john
```

每行格式：`组名:密码:GID:用户列表`（密码通常为 `x` 或空）

```bash
# 查看某个用户所属的所有组
$ groups john
john : john adm cdrom sudo dip plugdev docker

# 或
$ id john
uid=1000(john) gid=1000(john) groups=1000(john),4(adm),24(cdrom),27(sudo),998(docker)
```

## 2. 用户管理

### 2.1 `useradd` —— 创建用户

```bash
# 最简单的创建（系统自动分配 UID、默认家目录，但不够）
$ sudo useradd alice

# 检查用户是否创建成功
$ id alice
uid=1001(alice) gid=1001(alice) groups=1001(alice)

# 查看家目录是否创建
$ ls -la /home/
total 16
drwxr-xr-x  4 root  root  4096 Sep 15 10:30 .
drwxr-xr-x 20 root  root  4096 Sep 15 09:00 ..
drwxr-xr-x 18 alice alice 4096 Sep 15 10:30 alice   # <-- 默认创建
drwxr-xr-x 22 john  john  4096 Sep 15 09:00 john
```

**常用选项**：

| 选项 | 含义 | 示例 |
|------|------|------|
| `-m` | 强制创建家目录（即使默认不创建） | `useradd -m bob` |
| `-s SHELL` | 指定登录 shell | `useradd -s /bin/bash bob` |
| `-u UID` | 指定 UID | `useradd -u 1500 bob` |
| `-g GROUP` | 指定主组 | `useradd -g developers bob` |
| `-G GROUP1,GROUP2` | 指定附加组 | `useradd -G sudo,docker bob` |
| `-d DIR` | 指定家目录路径 | `useradd -d /opt/apps/bob bob` |
| `-c "COMMENT"` | 添加描述 | `useradd -c "Bob Smith" bob` |
| `-e DATE` | 账户过期日期（YYYY-MM-DD） | `useradd -e 2025-12-31 bob` |

```bash
# 完整示例：创建一个用户，指定 shell、家目录、附加组、描述
$ sudo useradd -m -s /bin/bash -G sudo,docker -c "Bob Smith,Developer" bob

$ id bob
uid=1002(bob) gid=1002(bob) groups=1002(bob),27(sudo),998(docker)

$ grep bob /etc/passwd
bob:x:1002:1002:Bob Smith,Developer:/home/bob:/bin/bash

$ ls -la /home/bob/
total 32
drwxr-xr-x 2 bob  bob  4096 Sep 15 10:45 .
drwxr-xr-x 5 root root 4096 Sep 15 10:45 ..
-rw-r--r-- 1 bob  bob   220 Sep 15 10:45 .bash_logout
-rw-r--r-- 1 bob  bob  3771 Sep 15 10:45 .bashrc
-rw-r--r-- 1 bob  bob   807 Sep 15 10:45 .profile
```

> `/etc/skel/` 目录下的文件会被复制到新用户的家目录中（如 `.bashrc`、`.profile` 等）。

```bash
# 查看可用的 shell 列表
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/bin/dash
/usr/bin/dash
/bin/zsh
/usr/bin/zsh
```

### 2.2 `passwd` —— 设置与修改密码

```bash
# root 修改任意用户密码
$ sudo passwd alice
New password: ********
Retype new password: ********
passwd: password updated successfully

# 用户自己改密码（不需要 sudo）
$ passwd
Changing password for john.
Current password: ********
New password: ********
Retype new password: ********
passwd: password updated successfully

# 锁定用户（禁止登录）
$ sudo passwd -l alice
passwd: password expiry information changed.

# 查看锁定状态
$ sudo passwd -S alice
alice L 09/15/2024 0 99999 7 -1   # L = Locked

# 解锁
$ sudo passwd -u alice
passwd: password expiry information changed.

# 强制用户在下次登录时修改密码
$ sudo passwd -e alice
passwd: password expiry information changed.

# 删除密码（无密码也可登录，极不安全！）
$ sudo passwd -d alice
passwd: password expiry information changed.
```

```bash
# 查看所有密码状态
$ sudo passwd -S -a
john P 09/10/2024 0 99999 7 -1
alice P 09/15/2024 0 99999 7 -1
root P 08/20/2024 0 99999 7 -1
```

### 2.3 `usermod` —— 修改用户属性

```bash
# 查看 usermod 所有选项
$ usermod --help
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-l NEWNAME OLDNAME` | 更改用户名 | `usermod -l bob2 bob` |
| `-d DIR -m` | 更改家目录并移动内容 | `usermod -d /home/bobnew -m bob` |
| `-s SHELL` | 更改默认 shell | `usermod -s /bin/zsh bob` |
| `-u UID` | 更改 UID | `usermod -u 1550 bob` |
| `-g GROUP` | 更改主组 | `usermod -g developers bob` |
| `-aG GROUP` | 追加附加组（关键！不加 `-a` 会覆盖） | `usermod -aG docker bob` |
| `-c "COMMENT"` | 更改描述 | `usermod -c "Bob Updated" bob` |
| `-L / -U` | 锁定/解锁账户 | `usermod -L bob` |

```bash
# 示例1：改用户名——需要同时改家目录
$ sudo usermod -l bobby bob
$ sudo usermod -d /home/bobby -m bobby
$ sudo groupmod -n bobby bob   # 组名也一起改

# 示例2：将用户加入多个附加组（务必用 -aG，G是大写！）
$ sudo usermod -aG sudo,docker,developers alice

$ groups alice
alice : alice sudo docker developers

# 错误示范：忘记 -a 会被覆盖掉原有附加组！
$ sudo usermod -G docker alice    # 现在 alice 只有 docker 组了！
$ groups alice
alice : alice docker

# 示例3：锁定账户
$ sudo usermod -L alice
$ sudo grep alice /etc/shadow
alice:!$y$j9T$...   # 密码哈希前多了一个 ! 号

# 解锁
$ sudo usermod -U alice
$ sudo grep alice /etc/shadow
alice:$y$j9T$...    # ! 号消失
```

### 2.4 `userdel` —— 删除用户

```bash
# 只删除用户账户，保留家目录和邮件池
$ sudo userdel alice

# 同时删除家目录和邮件池（推荐！）
$ sudo userdel -r alice

# 强制删除（即使用户已经登录）
$ sudo userdel -rf alice
```

> 删除前建议先检查该用户是否还拥有其他文件：
> ```bash
> $ sudo find / -user alice -ls 2>/dev/null
> ```

### 2.5 `su` —— 切换用户

```bash
# 切换到 root（需要 root 密码）
$ su -
Password: ********
#

# 切换到指定用户
$ su - alice
Password: ********
$

# 带 - 和不带 - 的区别
$ su alice       # 不加载 alice 的环境变量，当前目录不变
$ su - alice     # 完整切换：加载环境、切换到 alice 的家目录

# 以 root 身份执行一条命令（不需要切换到 root shell）
$ su -c "apt update"
Password: ********
```

> `-` 的实际含义是 `-l`（login shell），它会：
> - 清空大多环境变量，重新加载目标用户的 `.bashrc`、`.profile`
> - 切换工作目录到目标用户的家目录

### 2.6 `sudo` —— 以 root 身份执行命令

```bash
# 以 root 身份执行单条命令（需要输入当前用户密码，不是 root 密码！）
$ sudo apt update
[sudo] password for john: ********
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
...

# 获取 root shell（等同于 su -）
$ sudo -i
#

# 以 root 身份执行上一条命令（经典技巧！）
$ apt install vim
E: Could not open lock file /var/lib/dpkg/lock-frontend - open (13: Permission denied)
$ sudo !!
sudo apt install vim
[sudo] password for john: ********
...

# 以指定用户身份执行命令
$ sudo -u alice whoami
alice

# 以指定用户身份获取 shell
$ sudo -u alice -s
$ whoami
alice

# 查看当前用户有哪些 sudo 权限
$ sudo -l
Matching Defaults entries for john on ubuntu-server:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:...

User john may run the following commands on ubuntu-server:
    (ALL : ALL) ALL
```

**`/etc/sudoers` 配置**：

> 绝对不要直接编辑 `/etc/sudoers`！请使用 `visudo`（会做语法检查，防止被锁死）。

```bash
$ sudo visudo
```

```bash
# 格式：用户  主机=(以谁的身份)  可执行的命令
root    ALL=(ALL:ALL) ALL
%admin  ALL=(ALL) ALL         # %admin 表示 admin 组的所有成员
%sudo   ALL=(ALL:ALL) ALL     # sudo 组的成员可以执行任何命令

# 允许某用户免密码执行特定命令
john    ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

# 允许某用户以特定身份执行特定命令
deploy  ALL=(www-data) /usr/bin/rsync

# 限制某用户只能执行查看类命令
monitor ALL=(ALL) /usr/bin/cat, /usr/bin/ls, /usr/bin/tail, /usr/bin/less
```

```bash
# 将用户加入 sudo 组（Ubuntu 默认）
$ sudo usermod -aG sudo john

# 将用户加入 wheel 组（CentOS / RHEL 默认）
$ sudo usermod -aG wheel john

# 验证
$ groups john
john : john sudo docker
```

### 2.7 `chsh` —— 更改默认 shell

```bash
# 查看当前 shell
$ echo $SHELL

# 查看可用 shell 列表
$ cat /etc/shells
/bin/sh

# 更改为 zsh（需先安装 zsh）
```

## 3. 组管理

### 3.1 `groupadd` —— 创建组

```bash
# 创建系统组
$ sudo groupadd developers

# 指定 GID
$ sudo groupadd -g 1500 developers

# 创建系统组（GID 自动在系统范围内分配）
$ sudo groupadd -r myservice
```

### 3.2 `groupmod` —— 修改组

```bash
# 更改组名
$ sudo groupmod -n dev developers

# 更改 GID
$ sudo groupmod -g 2000 dev
```

### 3.3 `groupdel` —— 删除组

```bash
# 删除组（不能是任何用户的主组，不能有任何用户正在使用它作为有效组）
$ sudo groupdel developers
```

### 3.4 `gpasswd` —— 组成员管理

```bash
# 将用户加入组（最常用）
$ sudo gpasswd -a john docker
Adding user john to group docker

# 将用户从组中移除
$ sudo gpasswd -d john docker
Removing user john from group docker

# 设置组管理员（组管理员可以自行管理组成员，不需要每次找 root）
$ sudo gpasswd -A john developers    # 设 john 为 developers 组的管理员

# 设置组密码（极少用，允许非组成员临时加入）
$ sudo gpasswd developers
Changing the password for group developers
New Password: ********
```

### 3.5 `newgrp` —— 临时切换有效组

```bash
# 查看当前有效组
$ id
uid=1000(john) gid=1000(john) groups=1000(john),27(sudo),998(docker)

# 临时让新建文件属于 docker 组
$ newgrp docker
$ id
uid=1000(john) gid=998(docker) groups=1000(john),27(sudo),998(docker)

# 现在创建的文件默认属于 docker 组
$ touch test_file
$ ls -l test_file
-rw-r--r-- 1 john docker 0 Sep 15 11:00 test_file
```

> `newgrp` 会启动一个新的子 shell。退出用 `exit` 或 `Ctrl+D`。

## 4. 文件权限

这是 Linux 安全模型中**最核心**的概念。每个文件和目录都有三类权限，分别面向三类人员。

### 4.1 `ls -l` 输出详解

```bash
$ ls -l /etc/hosts
-rw-r--r-- 1 root root 224 Sep 10 08:30 /etc/hosts
```

我们把最前面的 10 个字符拆开来看：

| 位 | 含义 | 值 |
|----|------|-----|
| 1 | 文件类型 | `-` 普通文件，`d` 目录，`l` 软链接，`c` 字符设备，`b` 块设备，`s` socket，`p` 管道 |
| 2-4 | 所有者权限（user） | `rw-` |
| 5-7 | 所属组权限（group） | `r--` |
| 8-10 | 其他人权限（other） | `r--` |

```
   -   r w x   r w x   r w x
   │   ─┬───   ─┬───   ─┬───
   │   owner   group   other
 类型
```

每组的三个权限位：

| 权限 | 字母 | 数值 | 对文件 | 对目录 |
|------|------|------|--------|--------|
| 读 | `r` | 4 | 可以读取文件内容 | 可以列出目录内容（`ls`） |
| 写 | `w` | 2 | 可以修改文件内容 | 可以在目录内创建/删除/重命名文件 |
| 执行 | `x` | 1 | 可以作为程序运行 | 可以进入目录（`cd`）、访问目录内文件 |

> 对于目录而言，`x` 是最关键的权限！没有 `x`，你就无法 `cd` 进去，也无法访问目录内的任何文件（即使你有读权限也看不到内容）。

```bash
# 示例：理解目录权限
$ mkdir test_dir
$ touch test_dir/hello.txt
$ echo "Hello" > test_dir/hello.txt

$ chmod 600 test_dir        # 只给所有者 rw-，没有 x
$ cat test_dir/hello.txt
cat: test_dir/hello.txt: Permission denied

$ ls test_dir
ls: cannot access 'test_dir/hello.txt': Permission denied
ls: cannot access 'test_dir/..': Permission denied
ls: cannot access 'test_dir/.': Permission denied
total 0

$ chmod 700 test_dir        # 加上 x
$ cat test_dir/hello.txt
Hello
```

### 4.2 权限的数字表示法

```
r = 4    w = 2    x = 1
```

**数字权限速查表**：

| 数字 | 权限 | 含义 |
|------|------|------|
| 0 | `---` | 无任何权限 |
| 1 | `--x` | 仅执行（能 cd 进目录，能执行程序） |
| 2 | `-w-` | 仅写（极少用） |
| 3 | `-wx` | 写+执行 |
| 4 | `r--` | 仅读 |
| 5 | `r-x` | 读+执行 |
| 6 | `rw-` | 读+写 |
| 7 | `rwx` | 全部权限 |

**组合成三位数**：

```
755 = 7(rwx) 5(r-x) 5(r-x) = rwxr-xr-x
644 = 6(rw-) 4(r--) 4(r--) = rw-r--r--
700 = 7(rwx) 0(---) 0(---) = rwx------
600 = 6(rw-) 0(---) 0(---) = rw-------
```

```bash
# 常用的八进制权限组合
$ ls -l
-rwx------ 1 john john   24 Sep 15 11:00 private.sh      # 700 = 只有自己可读写执行
-rw-r--r-- 1 john john  120 Sep 15 11:00 public.txt      # 644 = 所有人可读，只有自己可写
-rwxr-xr-x 1 john john  340 Sep 15 11:00 script.sh       # 755 = 所有人可执行，只有自己可写
-rw------- 1 john john 2048 Sep 15 11:00 ssh.key         # 600 = SSH 私钥标准权限
drwxr-xr-x 2 john john 4096 Sep 15 11:00 shared/         # 755 = 目录，别人可进入并查看
drwx--x--x 2 john john 4096 Sep 15 11:00 semiprivate/    # 711 = 别人可以进入但看不到文件列表
```

### 4.3 `chmod` —— 更改权限

#### 符号法（推荐给新手，直观）

语法：`chmod [ugoa][+-=][rwx] file`

| 符号 | 含义 |
|------|------|
| `u` | user，所有者 |
| `g` | group，所属组 |
| `o` | other，其他人 |
| `a` | all，所有人（相当于 ugo） |

```bash
$ ls -l script.sh
-rw-r--r-- 1 john john 340 Sep 15 11:00 script.sh

# 给所有者加执行权限
$ chmod u+x script.sh
$ ls -l script.sh
-rwxr--r-- 1 john john 340 Sep 15 11:00 script.sh

# 给组和其他人也加执行权限
$ chmod go+x script.sh
$ ls -l script.sh
-rwxr-xr-x 1 john john 340 Sep 15 11:00 script.sh

# 去掉其他人读权限
$ chmod o-r script.sh
$ ls -l script.sh
-rwxr-x--x 1 john john 340 Sep 15 11:00 script.sh

# 所有人加上读权限（一个人都不能少）
$ chmod a+r script.sh
$ ls -l script.sh
-rwxr-xr-x 1 john john 340 Sep 15 11:00 script.sh

# 取消所有人的写权限
$ chmod a-w script.sh
$ ls -l script.sh
-r-xr-xr-x 1 john john 340 Sep 15 11:00 script.sh

# 精确设置：所有者=rwx，组=rx，其他=无
$ chmod u=rwx,g=rx,o= file.txt
$ ls -l file.txt
-rwxr-x--- 1 john john 0 Sep 15 11:00 file.txt
```

#### 数字法（推荐给熟手，精确）

```bash
$ ls -l file.txt
-rw-r--r-- 1 john john 120 Sep 15 11:00 file.txt

# 设为 rwxr-xr-x（755）
$ chmod 755 file.txt
$ ls -l file.txt
-rwxr-xr-x 1 john john 120 Sep 15 11:00 file.txt

# SSH 私钥必须为 600
$ chmod 600 ~/.ssh/id_rsa
$ ls -l ~/.ssh/id_rsa
-rw------- 1 john john 2610 Sep 15 11:00 /home/john/.ssh/id_rsa

# 目录常用 755
$ chmod 755 shared/
$ ls -ld shared/
drwxr-xr-x 2 john john 4096 Sep 15 11:00 shared/

# 程序文件常用 755（可执行）
$ chmod 755 /usr/local/bin/myapp

# 配置文件常用 644（不可执行）
$ chmod 644 /etc/myapp/config.ini

# 数据目录常用 700（只有自己可以访问）
$ chmod 700 ~/secrets/

# Web 服务器：目录 755，文件 644
$ find /var/www -type d -exec chmod 755 {} \;
$ find /var/www -type f -exec chmod 644 {} \;
```

#### `-R` 递归修改

```bash
$ ls -lR myproject/
myproject/:
total 4
drwx------ 2 john john 4096 Sep 15 11:00 src

myproject/src:
total 4
-rw------- 1 john john 100 Sep 15 11:00 main.c
-rwx------ 1 john john 200 Sep 15 11:00 build.sh

# 递归修改整个目录树
$ chmod -R 755 myproject/

$ ls -lR myproject/
myproject/:
total 4
drwxr-xr-x 2 john john 4096 Sep 15 11:00 src

myproject/src:
total 4
-rwxr-xr-x 1 john john 100 Sep 15 11:00 main.c
-rwxr-xr-x 1 john john 200 Sep 15 11:00 build.sh
```

> `chmod -R` 很有用，但会把 `x` 执行权限均匀地加到所有文件上。如果是源代码，这通常没什么问题；但如果目录里有数据文件，建议分两条命令：
> ```bash
> $ find myproject -type d -exec chmod 755 {} \;
> $ find myproject -type f -exec chmod 644 {} \;
> ```

### 4.4 `chown` —— 更改所有者

```bash
# 基本用法：chown 所有者:组 文件
$ ls -l file.txt
-rw-r--r-- 1 root root 120 Sep 15 11:00 file.txt

# 只改所有者
$ sudo chown john file.txt
$ ls -l file.txt
-rw-r--r-- 1 john root 120 Sep 15 11:00 file.txt

# 只改组
$ sudo chown :developers file.txt
$ ls -l file.txt
-rw-r--r-- 1 john developers 120 Sep 15 11:00 file.txt

# 同时改所有者和组
$ sudo chown john:developers file.txt
$ ls -l file.txt
-rw-r--r-- 1 john developers 120 Sep 15 11:00 file.txt

# 只改所有者，组用冒号但不指定（使用目标用户的主组）
$ sudo chown john: file.txt

# 递归修改整个目录
$ sudo chown -R www-data:www-data /var/www/myapp/
$ ls -la /var/www/myapp/
total 16
drwxr-xr-x 3 www-data www-data 4096 Sep 15 11:00 .
drwxr-xr-x 5 www-data www-data 4096 Sep 15 11:00 ..
drwxr-xr-x 2 www-data www-data 4096 Sep 15 11:00 public
-rw-r--r-- 1 www-data www-data  120 Sep 15 11:00 index.html
```

### 4.5 `chgrp` —— 更改所属组

```bash
# chgrp 是 chown :group 的等价命令
$ sudo chgrp developers file.txt
$ ls -l file.txt
-rw-r--r-- 1 john developers 120 Sep 15 11:00 file.txt

# 递归
$ sudo chgrp -R developers myproject/
```

### 4.6 `umask` —— 默认权限掩码

创建新文件/目录时，默认权限由 **umask** 决定。umask 是一个"减法掩码"——它指定了**要去掉**的权限。

```
目录默认权限 = 777 - umask
文件默认权限 = 666 - umask
```

> 为什么文件是 666？因为文件创建时默认不应有执行权限（安全原因）。

```bash
# 查看当前 umask
$ umask
0022

# 分别用数字格式和符号格式查看
$ umask -S
u=rwx,g=rx,o=rx
```

**umask 计算示例**：

| umask | 目录（默认 777） | 文件（默认 666） | 说明 |
|-------|:------------:|:------------:|------|
| `000` | `777` = `rwxrwxrwx` | `666` = `rw-rw-rw-` | 最宽松，不推荐 |
| `002` | `775` = `rwxrwxr-x` | `664` = `rw-rw-r--` | 组内协作常用 |
| `022` | `755` = `rwxr-xr-x` | `644` = `rw-r--r--` | 默认值，最常见 |
| `027` | `750` = `rwxr-x---` | `640` = `rw-r-----` | 更安全，组只读 |
| `077` | `700` = `rwx------` | `600` = `rw-------` | 最严格，只有自己 |

```bash
# 临时更改 umask
$ umask 027
$ touch newfile_a
$ mkdir newdir_a
$ ls -l
drwxr-x--- 2 john john 4096 Sep 15 11:30 newdir_a
-rw-r----- 1 john john    0 Sep 15 11:30 newfile_a

# 恢复默认
$ umask 022
$ touch newfile_b
$ mkdir newdir_b
$ ls -l
drwxr-xr-x 2 john john 4096 Sep 15 11:31 newdir_b
-rw-r--r-- 1 john john    0 Sep 15 11:31 newfile_b
```

**永久设置 umask**：

```bash
# 全局：/etc/profile 或 /etc/bash.bashrc（Ubuntu）
# 个人：~/.bashrc 或 ~/.profile

$ echo "umask 027" >> ~/.bashrc
$ source ~/.bashrc
$ umask
0027
```

## 5. 特殊权限

除了 `rwx` 三位常规权限，还有三种**特殊权限**，用数字表示法时放在三位常规权限**前面**。

### 5.1 SUID（Set User ID）—— 数值 4

**效果**：当用户执行一个有 SUID 的文件时，进程的**有效用户 ID** 会变成文件**所有者**的 UID，而非执行者自身的 UID。

```bash
# 经典例子：passwd 命令
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 59976 Feb  6  2024 /usr/bin/passwd
#  ^
#  注意：所有者执行位不是 x 而是 s！

# 为什么 passwd 需要 SUID？
# passwd 命令需要修改 /etc/shadow（只有 root 可写），
# 普通用户通过 SUID 临时获得 root 权限来完成密码修改。
```

```bash
# 另一个常见例子：ping（需要原始 socket 权限）
$ ls -l /usr/bin/ping
-rwsr-xr-x 1 root root 72776 Feb  6  2024 /usr/bin/ping

# 设置 SUID
$ chmod u+s myprogram
# 或数字法（4 开头）
$ chmod 4755 myprogram

$ ls -l myprogram
-rwsr-xr-x 1 root john 12345 Sep 15 12:00 myprogram

# 移除 SUID
$ chmod u-s myprogram
$ ls -l myprogram
-rwxr-xr-x 1 root john 12345 Sep 15 12:00 myprogram

# 如果文件本身没有 x 权限，SUID 显示为 S（大写）
$ chmod 4644 myprogram
$ ls -l myprogram
-rwSr--r-- 1 root john 12345 Sep 15 12:00 myprogram
#  ^
# 大写 S 表示 SUID 位设置但无执行权限（通常是无意义的配置）
```

> SUID 只对二进制可执行文件有效，对脚本通常无效（大多数 shell 出于安全忽略 SUID 位）。

### 5.2 SGID（Set Group ID）—— 数值 2

#### 对文件

执行时进程的有效组 ID 变成文件**所属组**的 GID。

```bash
$ ls -l /usr/bin/wall
-rwxr-sr-x 1 root tty 23008 Feb  6  2024 /usr/bin/wall
#  组执行位显示为 s，不是 x
```

#### 对目录（更常用！）

目录内新创建的文件会**自动继承目录的组**，而不是创建者自己的主组。

```bash
# 场景：一组开发人员共享一个项目目录
$ sudo groupadd devteam

$ sudo mkdir /shared/project
$ sudo chgrp devteam /shared/project
$ sudo chmod 2775 /shared/project        # 2 = SGID

$ ls -ld /shared/project
drwxrwsr-x 2 root devteam 4096 Sep 15 12:00 /shared/project
#     ^
#   组执行位显示为 s

# 现在任何用户在目录内创建的文件都会自动属于 devteam 组
$ whoami
john
$ cd /shared/project
$ touch readme.txt
$ ls -l readme.txt
-rw-r--r-- 1 john devteam 0 Sep 15 12:01 readme.txt
#            ^^^^         ^^^^^^^
#         所有者是 john   组是 devteam（继承自目录！）

$ mkdir subdir
$ ls -ld subdir
drwxr-sr-x 2 john devteam 4096 Sep 15 12:02 subdir
# 子目录也自动继承 SGID！
```

```bash
# 设置 SGID
$ chmod g+s /shared/project
$ chmod 2775 /shared/project

# 移除 SGID
$ chmod g-s /shared/project
```

### 5.3 Sticky Bit（黏着位）—— 数值 1

**效果**：在设置了 sticky bit 的目录中，只有**文件所有者**和 **root** 才能删除或重命名该目录中的文件，即使其他人的写权限是打开的。

```bash
# 最经典的例子：/tmp
$ ls -ld /tmp
drwxrwxrwt 20 root root 4096 Sep 15 12:00 /tmp
#         ^
#   其他执行位显示为 t，不是 x

# 所有用户都可以在 /tmp 里创建文件
# 但我不能删除 alice 创建的文件
$ whoami
john
$ touch /tmp/myfile
$ ls -l /tmp/myfile
-rw-r--r-- 1 john john 0 Sep 15 12:01 /tmp/myfile

$ su - alice
$ rm /tmp/myfile
rm: remove write-protected regular empty file '/tmp/myfile'?
rm: cannot remove '/tmp/myfile': Operation not permitted
```

```bash
# 设置 sticky bit
$ mkdir /shared/uploads
$ chmod 1777 /shared/uploads

$ ls -ld /shared/uploads
drwxrwxrwt 2 john john 4096 Sep 15 12:00 /shared/uploads

# 如果目录本身没有 x 权限，t 显示为大写 T
$ chmod 1776 /shared/uploads
$ ls -ld /shared/uploads
drwxrwxrwT 2 john john 4096 Sep 15 12:00 /shared/uploads
```

### 5.4 特殊权限总结表

| 特殊权限 | 数字 | 文件效果 | 目录效果 | 示例 |
|----------|:----:|----------|----------|------|
| SUID | 4 | 以文件所有者的身份执行 | 无意义 | `passwd`、`ping` |
| SGID | 2 | 以文件所属组的身份执行 | 新建文件继承目录的组 | 共享项目目录 |
| Sticky | 1 | 无意义（旧版 Unix 残留） | 只有文件所有者可以删除 | `/tmp` |

**八进制权限模板**：

```
 4  7  5  5
 │  └─┘──┘───┘
 │   常规权限 rwx（三组）
 └─ 特殊权限（SUID=4, SGID=2, Sticky=1, 可叠加）
```

```bash
# 常用组合
$ chmod 4755 myapp        # SUID + rwxr-xr-x
$ chmod 2775 shared/      # SGID + rwxrwxr-x
$ chmod 1777 /tmp         # Sticky + rwxrwxrwx
$ chmod 6755 myapp        # SUID + SGID + rwxr-xr-x
```

## 6. ACL 访问控制列表（可选进阶）

传统的 `ugo` 三层权限模型只能针对 owner/group/other 三类角色。当需要为**多个**特定用户或组赋予不同权限时，就需要 ACL。

### 6.1 查看 ACL：`getfacl`

```bash
# 基础查看
$ getfacl file.txt
# file: file.txt
# owner: john
# group: developers
user::rw-
group::r--
other::r--
```

如果 ACL 输出多了个 `+`，说明有额外的 ACL 条目：

```bash
$ ls -l report.txt
-rw-rwxr--+ 1 john developers 2048 Sep 15 12:30 report.txt
#          ^ 这个 + 号表示有扩展 ACL

$ getfacl report.txt
# file: report.txt
# owner: john
# group: developers
user::rw-
user:alice:rwx          # <-- alice 有额外 rwx 权限
group::r--
group:managers:r--      # <-- managers 组有读权限
mask::rwx
other::r--
```

### 6.2 设置 ACL：`setfacl`

```bash
# 为特定用户添加读、写权限
$ setfacl -m u:alice:rw- report.txt

# 为特定组添加读权限
$ setfacl -m g:managers:r-- report.txt

# 查看结果
$ getfacl report.txt
# file: report.txt
# owner: john
# group: developers
user::rw-
user:alice:rw-
group::r--
group:managers:r--
mask::rw-
other::r--

# 设置默认 ACL（对目录有效，决定了该目录下新建文件的 ACL）
$ mkdir shared_projects
$ setfacl -m d:u:alice:rwx shared_projects/
$ setfacl -m d:g:developers:rwx shared_projects/

$ getfacl shared_projects/
# file: shared_projects/
# owner: john
# group: john
user::rwx
group::r-x
other::r-x
default:user::rwx
default:user:alice:rwx
default:group::r-x
default:group:developers:rwx
default:mask::rwx
default:other::r-x

# 在该目录下创建的文件会自动继承默认 ACL
$ cd shared_projects
$ touch newfile
$ getfacl newfile
# file: newfile
# owner: john
# group: john
user::rw-
user:alice:rwx          # effective: rw-   （有效权限 = ACL权限 & mask）
group::r-x              # effective: r--
group:developers:rwx    # effective: rw-
mask::rw-
other::r--

# 删除某个 ACL 条目
$ setfacl -x u:alice report.txt

# 清除所有 ACL 条目（回到纯 ugo 权限）
$ setfacl -b report.txt

# 递归设置目录树的 ACL
$ setfacl -R -m u:alice:rwx project_dir/
```

### 6.3 ACL 的 mask

在 ACL 中有一个特殊的 **mask** 条目，它限制了所有命名用户（除 owner 外）、命名组、组的**最大权限**。

```bash
$ getfacl file.txt
...
mask::rwx       # mask 为 rwx，所有额外条目的权限不受限
...

$ setfacl -m mask::r-- file.txt

$ getfacl file.txt
...
user:alice:rw-          # effective: r--    <- 尽管给了 rw-，实际只有 r--
group:managers:r--      # effective: r--
mask::r--
...
```

## 7. 综合实战场景

### 场景一：Web 服务器部署

```bash
# 假设你的 Web 应用在 /var/www/myapp
# Nginx/Apache 以 www-data 用户运行
# 你需要安全地管理文件权限

# 1. 创建部署用户，加入 www-data 组

# 2. 设置目录所有权
$ sudo chown -R deploy:www-data /var/www/myapp/

$ sudo find /var/www/myapp -type d -exec chmod 2750 {} \;

total 8
```

### 场景三：安全检查脚本

```bash
#!/bin/bash
# 安全审计脚本：检查常见权限问题

echo "=== 安全检查报告 ==="
echo ""

# 检查 /etc/passwd 和 /etc/shadow 权限
echo "1. /etc/passwd 权限应为 644："
ls -l /etc/passwd

echo ""
echo "2. /etc/shadow 权限应为 640 或 400："
ls -l /etc/shadow

echo ""
echo "3. 查找全局可写的目录（rwx for other）："
find / -type d -perm -o+w -not -path "/proc/*" -not -path "/sys/*" 2>/dev/null | head -10

echo ""
echo "4. 查找全局可写且 root 拥有的文件："
find / -type f -user root -perm -o+w -not -path "/proc/*" -not -path "/sys/*" 2>/dev/null | head -10

echo ""
echo "5. 查找无主文件（没有对应 UID 的用户的文件）："
find / -nouser -ls 2>/dev/null | head -10

echo ""
echo "6. 查找设置了 SUID 的文件（潜在安全风险）："
find / -type f -perm -4000 -ls 2>/dev/null | head -10

echo ""
echo "7. 检查 /tmp 是否有 sticky bit："
ls -ld /tmp

echo ""
echo "8. 检查 root 可以免密码 SSH 登录："
grep -r "PermitRootLogin" /etc/ssh/sshd_config

echo ""
echo "9. 检查没有密码的用户："
sudo awk -F: '($2 == "" || $2 == "!") && $7 !~ /(nologin|false)/ {print $1}' /etc/shadow
```

### 场景四：批量创建学生用户

```bash
# 需求：创建 50 个学生用户，统一设置 shell、组和初始密码
# 学生名单：stu01, stu02, ..., stu50
# 使用脚本批量处理

$ sudo groupadd students

# 批量创建脚本
$ cat create_students.sh
#!/bin/bash
GROUP="students"
SHELL="/bin/bash"
BASE_HOME="/home"
INITIAL_PASSWORD="Welcome123!"

for i in $(seq -w 1 50); do
    USERNAME="stu${i}"
    HOMEDIR="${BASE_HOME}/${USERNAME}"

    # 检查用户是否已存在
    if id "$USERNAME" &>/dev/null; then
        echo "User $USERNAME already exists, skipping."
        continue
    fi

    # 创建用户
    useradd -m -s "$SHELL" -g "$GROUP" -d "$HOMEDIR" -c "Student ${i}" "$USERNAME"

    # 设置密码（注意：echo 方式不安全，仅用于批量脚本演示）
    echo "${USERNAME}:${INITIAL_PASSWORD}" | chpasswd

    # 强制首次登录修改密码
    passwd -e "$USERNAME"

    echo "Created user: $USERNAME"
done

echo "Done! Created $(grep -c '^stu[0-9]' /etc/passwd) student users."

# 验证
$ sudo bash create_students.sh
Created user: stu01
Created user: stu02
...
Created user: stu50
Done! Created 50 student users.

# 抽查用户信息
$ id stu15
uid=1015(stu15) gid=1003(students) groups=1003(students)

# 验证密码过期标记已设置
$ sudo passwd -S stu15
stu15 P 09/15/2024 0 99999 7 -1   # 首次登录需要改密码
```

### 场景五：权限问题诊断

```bash
# 用户报告：ls 目录报 Permission denied

# 1. 先检查目录的基本权限
$ ls -ld /data/projects/reports
drw-rw---- 2 alice reports 4096 Sep 15 14:00 /data/projects/reports
# 注意：所有者 alice 没有 x（执行/进入）权限！

# 2. 诊断中间每一步的目录权限
$ namei -l /data/projects/reports/report.pdf
f: /data/projects/reports/report.pdf
drwxr-xr-x root     root     /
drwxr-xr-x root     root     data
drwxrwx--- root     projects projects
drw-rw---- alice    reports  reports   # <-- 问题在这里
-rw-r--r-- alice    reports  report.pdf

# namei 递归检查路径中每一级目录的权限
# 发现 alice 的 home directory reports 没有 x（执行）权限

# 3. 修复
$ chmod u+x /data/projects/reports
$ ls -ld /data/projects/reports
drwxrw---- 2 alice reports 4096 Sep 15 14:00 /data/projects/reports

# 4. 验证
$ cat /data/projects/reports/report.pdf
# 成功读取
```

### 场景六：理解 umask 在共享环境中的影响

```bash
# 场景：两个用户 alice 和 bob 同属 developers 组
# 但 bob 设置了自己的 umask，导致 alice 无法读取他的文件

# alice 查看自己的环境
$ umask
0022

$ touch alice_file.txt
$ ls -l alice_file.txt
-rw-r--r-- 1 alice alice 0 Sep 15 14:00 alice_file.txt   # 644 = others 可读

# bob 使用更严格的 umask
$ su - bob
$ umask
0077

$ touch bob_file.txt
$ ls -l bob_file.txt
-rw------- 1 bob bob 0 Sep 15 14:01 bob_file.txt          # 600 = 只有自己可访问

# alice 尝试读取 bob 的文件
$ su - alice
$ cat /home/bob/bob_file.txt
cat: /home/bob/bob_file.txt: Permission denied

# 解决方案1：统一设置 umask
# 在 /etc/profile 中设置全局 umask 为 002
$ sudo bash -c 'echo "umask 002" >> /etc/profile'
$ source /etc/profile

# 解决方案2：使用共享目录 + SGID（推荐）
$ sudo mkdir /shared/work
$ sudo chgrp developers /shared/work
$ sudo chmod 2770 /shared/work
# SGID 确保新文件都属 developers 组，即使 umask 不一致也能互相访问
```

## 总结

| 层面 | 命令 | 核心功能 |
|------|------|----------|
| **查询身份** | `whoami`, `id`, `groups`, `who`, `w`, `last` | 确认我是谁，我在哪 |
| **用户管理** | `useradd`, `passwd`, `usermod`, `userdel`, `chsh` | 增删改查用户 |
| **组管理** | `groupadd`, `groupmod`, `groupdel`, `gpasswd`, `newgrp` | 增删改查组 |
| **切换身份** | `su`, `sudo`, `su -`, `sudo -i`, `sudo !!` | 借用其他身份的权限 |
| **文件权限** | `chmod`, `chown`, `chgrp`, `umask` | 精确控制文件的读、写、执行 |
| **特殊权限** | SUID(4), SGID(2), Sticky(1) | 满足常规权限模型无法覆盖的特殊场景 |
| **ACL** | `getfacl`, `setfacl` | 为任意数量的用户/组设置差异化权限 |

**核心法则**：

1. **最小权限原则**：只给完成任务所必需的权限，不多给
2. **`x` 对目录是进入权**：没有 x 就无法访问目录中的任何文件
3. **sudo 优于 su**：记录详细，可分粒度的配置
4. **`chmod 600` 保护敏感文件（私钥），`700` 保护专属目录，`755` 给可执行程序，`644` 给普通文件**
5. **SGID + 共享目录 = 团队协作神器**
