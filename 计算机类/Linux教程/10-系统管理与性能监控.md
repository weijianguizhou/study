## 磁盘管理

### `df` — 查看磁盘分区使用情况

```bash
# 基本用法
$ df
Filesystem     1K-blocks      Used Available Use% Mounted on
/dev/sda1       30831564  12876524  16360412  45% /
/dev/sdb1       51593212   8923436  40030332  19% /data
tmpfs             991832         0    991832   0% /dev/shm

# 人类可读格式（GB/MB）
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
udev            933M     0  933M   0% /dev
tmpfs           194M  1.5M  193M   1% /run
/dev/sda1        30G   13G   16G  45% /
tmpfs           969M   16K  969M   1% /dev/shm
tmpfs           5.0M  4.0K  5.0M   1% /run/lock
/dev/sdb1        50G  8.6G   39G  19% /data
tmpfs           194M  4.0K  194M   1% /run/user/1000

# 显示文件系统类型
$ df -Th
Filesystem     Type      Size  Used Avail Use% Mounted on
udev           devtmpfs  933M     0  933M   0% /dev
tmpfs          tmpfs     194M  1.5M  193M   1% /run
/dev/sda1      ext4       30G   13G   16G  45% /
/dev/sdb1      xfs        50G  8.6G   39G  19% /data

# 查看 inode 使用情况（文件数量限制）
$ df -i
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda1      1966080 245678 1720402   13% /
/dev/sdb1      3276800  15634 3261166    1% /data
# 当 IUse% 达到 100% 时，即使磁盘还有空间也无法创建新文件！

# 过滤文件系统类型
$ df -h -t ext4          # 只显示 ext4
$ df -h -x tmpfs         # 排除 tmpfs

# 查看特定目录所属的分区
$ df -h /var/log
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        30G   13G   16G  45% /

# 只显示本地文件系统
$ df -hl
```

**字段解读**：

| 字段 | 含义 | 注意 |
|------|------|------|
| `Filesystem` | 分区/设备名 | `/dev/sda1` 表示第一块硬盘第一分区 |
| `Size` | 总大小 | |
| `Used` | 已使用 | |
| `Avail` | 可用 | **关注这个** |
| `Use%` | 使用率 | 超过 90% 需要清理 |
| `Mounted on` | 挂载点 | |

### `mount` / `umount` — 挂载与卸载

```bash
# 查看当前所有挂载
$ mount
sysfs on /sys type sysfs (rw,nosuid,nodev,noexec,relatime)
proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
/dev/sda1 on / type ext4 (rw,relatime,errors=remount-ro)
/dev/sdb1 on /data type xfs (rw,relatime,attr2,inode64,logbufs=8)

# 查看特定类型的挂载
$ mount -t ext4          # 只看 ext4 类型
$ mount -t nfs           # 只看 NFS 网络挂载

# 挂载设备
$ sudo mount /dev/sdb1 /mnt/data

# 挂载并指定文件系统类型
$ sudo mount -t ext4 /dev/sdc1 /mnt/backup

# 挂载 ISO 镜像
$ sudo mount -o loop ubuntu.iso /mnt/iso

# 只读挂载
$ sudo mount -o ro /dev/sdc1 /mnt/readonly

# 挂载 NFS 网络文件系统
$ sudo mount -t nfs 192.168.1.50:/exports/data /mnt/nfs_data

# 卸载
$ sudo umount /mnt/data
# 如果提示 target is busy（有进程在使用）：
$ sudo lsof /mnt/data          # 找出占用进程
$ sudo fuser -km /mnt/data     # 强制结束所有占用进程
$ sudo umount -l /mnt/data     # 懒卸载（断开连接，等空闲时真正卸载）
```

### `/etc/fstab` — 开机自动挂载

`/etc/fstab`（File System Table）定义了系统启动时自动挂载哪些文件系统。

```bash
$ cat /etc/fstab
# <file system>  <mount point>  <type>  <options>       <dump>  <pass>
UUID=12345678-abcd-1234-abcd-123456789abc  /      ext4  defaults        0       1
UUID=ABCD-1234                             /boot/efi  vfat  umask=0077   0       1
UUID=11111111-2222-3333-4444-555555555555  /data      xfs   defaults     0       2
/swapfile                                  none       swap  sw           0       0
```

**字段说明**：

| 字段 | 含义 | 示例 |
|------|------|------|
| `file system` | 设备路径或 UUID | `UUID=xxx` 或 `/dev/sdb1` |
| `mount point` | 挂载点 | `/data` |
| `type` | 文件系统类型 | `ext4`, `xfs`, `ntfs`, `vfat` |
| `options` | 挂载选项 | `defaults`, `noatime`, `ro` |
| `dump` | 备份标记（0=不备份） | `0` |
| `pass` | fsck 检查顺序（0=不检查, 1=根, 2=其他） | `1` |

**常用挂载选项**：

| 选项 | 含义 |
|------|------|
| `defaults` | 默认选项集合（rw, suid, dev, exec, auto, nouser, async） |
| `noatime` | 不更新文件访问时间（提升 SSD 寿命和性能） |
| `nodiratime` | 不更新目录访问时间 |
| `noexec` | 不允许执行该文件系统上的程序 |
| `nosuid` | 忽略 suid/sgid 位 |
| `ro` | 只读挂载 |
| `rw` | 读写挂载 |
| `user` | 允许普通用户挂载 |

```bash
# 添加新硬盘到 fstab 示例
# 1. 获取 UUID
$ sudo blkid /dev/sdc1
/dev/sdc1: UUID="99990000-aaaa-bbbb-cccc-ddddeeeeffff" TYPE="ext4"

# 2. 创建挂载点
$ sudo mkdir -p /mnt/storage

# 3. 编辑 /etc/fstab 添加一行
# UUID=99990000-aaaa-bbbb-cccc-ddddeeeeffff  /mnt/storage  ext4  defaults,noatime  0  2

# 4. 测试挂载（不重启验证 fstab 是否正确）
$ sudo mount -a
# 无输出表示成功

# 5. 验证
$ df -h /mnt/storage
```

### 磁盘配额简介

限制用户或组可以使用的磁盘空间和文件数量。


## 内存管理

### `free` — 查看内存使用情况

```bash
# 人类可读格式
$ free -h
              total        used        free      shared  buff/cache   available
Mem:           1.9Gi       453Mi       342Mi       1.5Mi       1.2Gi       1.4Gi
Swap:          2.0Gi        89Mi       1.9Gi

# 更详细的数字（MB）
$ free -m
              total        used        free      shared  buff/cache   available
Mem:           1962         453         342           1        1166        1445
Swap:          2047          89        1958

# 持续监控（每秒刷新）
$ free -h -s 1
              total        used        free      shared  buff/cache   available
Mem:           1.9Gi       453Mi       341Mi       1.5Mi       1.2Gi       1.4Gi
Swap:          2.0Gi        89Mi       1.9Gi

              total        used        free      shared  buff/cache   available
Mem:           1.9Gi       455Mi       339Mi       1.5Mi       1.2Gi       1.4Gi
...
# 按 Ctrl+C 停止

# 只显示总计
$ free -h --total
```

**字段详解**：

| 字段 | 含义 |
|------|------|
| `total` | 总物理内存 |
| `used` | 已使用（`total - free - buff/cache`） |
| `free` | 完全未使用的内存 |
| `shared` | 共享内存（tmpfs 等） |
| `buff/cache` | 缓冲区 + 缓存（可被释放，不是浪费） |
| `available` | **真正可用的内存**（包含可回收的 buff/cache） |

> **关键理解**：Linux 会将空闲内存用作缓存（buff/cache），提高 I/O 性能。
> 不要看到 `free` 很少就以为内存不够——应该看 `available`！
> `available` = `free` + 可回收的 `buff/cache`。

**Buffer vs Cache**：
- **Buffer**：存储即将写入磁盘的数据（写缓冲）
- **Cache**：存储从磁盘读取过的数据（读缓存），下次读直接命中

```bash
# 释放缓存（仅在测试/调试时使用，正常不应手动释放）
$ sudo sh -c 'echo 1 > /proc/sys/vm/drop_caches'   # 释放 pagecache
$ sudo sh -c 'echo 2 > /proc/sys/vm/drop_caches'   # 释放 dentry 和 inode
$ sudo sh -c 'echo 3 > /proc/sys/vm/drop_caches'   # 释放全部
# 执行后 free -h 查看效果
```

**Swap 交换空间**：
- 当物理内存不足时，将不常用的内存页移到磁盘上的 swap 区
- 少量 swap 使用是正常的；大量 swap 使用说明内存严重不足

```bash
# 查看 swap 使用最多的进程
$ for file in /proc/*/status; do
    awk '/VmSwap|Name/{printf $2 " " $3}END{ print ""}' "$file" 2>/dev/null
  done | sort -k2 -hr | head -5
chrome 245678 kB
mysqld 102400 kB
java   89216 kB
node   45678 kB
```

### `vmstat` — 虚拟内存统计

```bash
# 每 2 秒采样一次，共 5 次
$ vmstat 2 5
procs -----------memory---------- ---swap-- -----io---- -system-- ----cpu----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  0  91172 350120  85312 1124092    0    1    15    20   52   79  3  2 94  1  0
 0  0  91172 350096  85312 1124092    0    0     0     8  150  280  1  1 98  0  0
 0  0  91172 350096  85312 1124092    0    0     0     0  145  275  1  1 98  0  0
 0  0  91172 350096  85320 1124088    0    0     0    14  155  290  1  0 99  0  0
 0  0  91172 350096  85320 1124088    0    0     0     0  148  278  1  1 98  0  0
```

**字段解读**：

| 类别 | 字段 | 含义 |
|------|------|------|
| procs | `r` | 运行队列中的进程数 |
| procs | `b` | 不可中断睡眠（等待 I/O）的进程数 |
| memory | `swpd` | 已使用的 swap 大小（KB） |
| memory | `free` | 空闲内存（KB） |
| memory | `buff` | 缓冲区 |
| memory | `cache` | 缓存 |
| swap | `si` | 每秒从 swap 读入内存（swap in） |
| swap | `so` | 每秒从内存写入 swap（swap out） |
| io | `bi` | 每秒从块设备读入的块数 |
| io | `bo` | 每秒写入块设备的块数 |
| system | `in` | 每秒中断数 |
| system | `cs` | 每秒上下文切换数 |
| cpu | `us` | 用户态 CPU 时间百分比 |
| cpu | `sy` | 内核态 CPU 时间百分比 |
| cpu | `id` | 空闲 CPU 时间百分比 |
| cpu | `wa` | 等待 I/O 的 CPU 时间百分比 |
| cpu | `st` | 被虚拟机偷走的 CPU 时间 |

> **健康指标**：
> - `r` > CPU 核数 → CPU 成为瓶颈
> - `si/so` 持续 > 0 → 内存不足，正在频繁 swap
> - `wa` 持续 > 10% → 磁盘 I/O 瓶颈
> - `id` 接近 0 + `us` 很高 → CPU 满负荷

### `uptime` — 系统运行时间 + 负载

```bash
$ uptime
10:30:00 up 45 days, 3:15, 3 users, load average: 0.25, 0.18, 0.15

# 解读：
# 10:30:00           — 当前时间
# up 45 days, 3:15   — 已运行 45 天 3 小时 15 分钟
# 3 users            — 当前登录用户数
# load average: 0.25, 0.18, 0.15 — 1分钟/5分钟/15分钟平均负载
```

**平均负载（load average）解读**：

| 负载值 | 含义（4核 CPU 为例） |
|--------|---------------------|
| `0.25` | 空闲，25% 的资源在使用 |
| `1.00` | 恰好用满一个核心 |
| `4.00` | 用满所有 4 个核心（正常） |
| `8.00` | 过载，有进程在排队等待 |
| `> 核数 × 2` | 严重过载，需紧急排查 |

> 经验法则：load average 持续 > CPU 核数，说明系统在过载运作。

### `logrotate` — 日志轮转

防止日志文件无限增长填满磁盘。

```bash
# 主配置文件
$ cat /etc/logrotate.conf
weekly                  # 每周轮转一次
rotate 4                # 保留 4 个历史文件
create                  # 轮转后创建新的空日志文件
dateext                 # 使用日期作为后缀（而非序号）
compress                # 压缩旧日志
include /etc/logrotate.d

# 查看应用级配置
$ ls /etc/logrotate.d/
nginx  rsyslog  apt  ufw  mysql-server

# 示例：Nginx 日志轮转配置
$ cat /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                   # 每天轮转
    missingok               # 日志不存在不报错
    rotate 14               # 保留 14 天
    compress                # 压缩
    delaycompress           # 延迟压缩（当前+前一个不压缩）
    notifempty              # 空文件不轮转
    create 0640 www-data adm
    sharedscripts
    postrotate
        [ -s /run/nginx.pid ] && kill -USR1 `cat /run/nginx.pid`
    endscript
}

# 手动触发轮转（测试配置）
$ sudo logrotate -f /etc/logrotate.d/nginx

# 测试配置（不实际执行）
$ sudo logrotate -d /etc/logrotate.d/nginx
```

## 总结

本章涵盖了 Linux 系统管理的核心领域：

| 类别 | 关键命令 | 核心用途 |
|------|---------|---------|
| 磁盘管理 | `df`, `du`, `lsblk`, `fdisk`, `mount` | 磁盘空间监控和分区管理 |
| 自动挂载 | `/etc/fstab` | 开机自动挂载文件系统 |
| 内存管理 | `free`, `vmstat`, `/proc/meminfo` | 内存使用分析和性能诊断 |
| CPU 监控 | `lscpu`, `uptime`, `nproc` | CPU 信息和系统负载 |
| 日志管理 | `journalctl`, `dmesg`, `logrotate` | 日志查看、排查和轮转 |
| 性能监控 | `htop`, `iotop`, `nethogs`, `glances` | 全维度系统性能监控 |
| 系统信息 | `uname`, `lsb_release`, `hostnamectl` | 系统版本和配置信息 |
| 时区管理 | `timedatectl` | 时间和时区配置 |
| 关机重启 | `shutdown`, `reboot`, `poweroff` | 系统电源管理 |
| 日常维护 | unattended-upgrades, cron | 自动化系统维护 |

**运维心智模型**：
- **磁盘**：把 `df -h` 作为日常口头禅，磁盘满是最常见的生产事故
- **内存**：关注 `available` 而不是 `free`，Linux 用缓存不是浪费
- **日志**：学会用 `journalctl -xe` 和 `tail -f /var/log/syslog` 快速定位问题
- **监控**：`htop` 是日常窗口，`glances` 是全局仪表盘，`sar` 是事后排查

## 习题与实践

### 磁盘管理

1. 使用 `df -h` 查看所有分区的使用情况，找出使用率超过 80% 的分区。
2. 使用 `du -sh * | sort -hr | head -10` 找出你的家目录下最大的 10 个文件/目录。
3. 使用 `find ~ -type f -size +100M` 找出家目录下大于 100MB 的文件。
4. 使用 `lsblk -f` 查看系统中的所有块设备及其 UUID。
5. （可选）在虚拟机中添加一块新硬盘，使用 `fdisk` 分区，`mkfs.ext4` 格式化，编辑 `/etc/fstab` 实现开机自动挂载。

### 内存与 CPU

6. 使用 `free -h` 查看内存，解释 `free`、`buff/cache` 和 `available` 的区别。
7. 运行 `vmstat 2 5` 并解释各列含义，特别关注 `si`、`so` 和 `wa` 三个指标。
8. 使用 `lscpu` 查看 CPU 信息，确认：物理 CPU 数、每个 CPU 的核心数、是否开启超线程、总逻辑 CPU 数。
9. 运行 `uptime`，观察过去 1/5/15 分钟的平均负载。尝试运行一个 CPU 密集型任务（如 `dd if=/dev/zero of=/dev/null bs=1M count=100000`），再次查看负载变化。

### 日志管理

10. 使用 `journalctl -xe -n 20` 查看最近的系统日志，尝试解读其中 3 条日志。
11. 使用 `sudo grep "Failed" /var/log/auth.log` 查看是否有失败的登录尝试（如在虚拟机中尝试用错误密码 SSH 登录几次）。
12. 查看 `dmesg` 中与磁盘（`sd`）、CPU（`CPU`）、网络（`eth`）相关的硬件检测信息。
13. 使用 `journalctl --disk-usage` 查看日志占用多少磁盘空间。

### 性能监控

14. 安装并运行 `glances`，观察 CPU、内存、磁盘 I/O、网络等仪表盘。
15. 使用 `sudo iotop -o` 查看当前正在进行磁盘读写的进程。
16. 使用 `sudo nethogs eth0` 查看各进程的网络流量使用情况。

### 系统管理

17. 使用 `hostnamectl` 查看系统主机名、操作系统、内核版本和硬件信息。
18. 使用 `timedatectl` 查看当前时区，练习切换时区再切回来。
19. 使用 `uname -a` 和 `lsb_release -a` 查看完整的系统和内核信息。
20. 检查 `/etc/fstab` 文件，画出系统的挂载关系图。

### 综合实战

21. **磁盘空间告警脚本**：
    - 编写一个脚本，当任何分区使用率超过 90% 时发送邮件/通知
    - 使用 cron 定时执行

22. **系统健康日报**：
    - 编写脚本收集：磁盘使用、内存使用、系统负载、最近错误日志
    - 输出为格式化的文本报告
    - 使用 cron 每天凌晨生成

23. **日志清理策略**：
    - 配置 `logrotate` 为你的应用日志设置轮转策略
    - 设置 `journalctl --vacuum-size=500M` 的 cron 定期清理任务
    - 统计清理前后磁盘空间变化

24. **性能瓶颈定位**：
    - 在测试环境模拟高负载场景（如用 `stress` 工具）
    - 依次使用 `top`/`htop` → `iotop` → `nethogs` → `sar` 定位瓶颈
    - 记录完整的排查过程和结论
