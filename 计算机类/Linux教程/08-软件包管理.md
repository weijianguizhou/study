# 软件包管理

> **MOC**：[[00-Linux教程MOC|Linux 教程目录]] | **前置**：[[07-Shell脚本基础|Shell 脚本]] | **后续**：[[09-网络与远程操作|网络与远程操作]]

> 软件包管理是 Linux 系统管理的基石。不同的 Linux 发行版使用不同的包管理工具，但它们的目标一致：让你轻松地安装、升级、卸载软件，解决依赖关系。

## 一、软件包管理概念

### 1.1 什么是软件包

**软件包** = 编译好的二进制文件 + 配置文件 + 依赖信息 + 元数据

一个软件包通常包含：
- **可执行文件**：编译好的二进制程序
- **库文件**：程序运行所需的共享库（`.so` 文件）
- **配置文件**：默认配置，通常放在 `/etc/` 下
- **文档**：man 手册页、README 等
- **元数据**：名称、版本、描述、依赖关系、维护者信息

```bash
# 以 dpkg 为例，查看一个包的详细信息
$ dpkg -L nginx        # 列出包安装的所有文件
/.
/etc
/etc/nginx
/etc/nginx/nginx.conf
/etc/nginx/sites-available
/etc/nginx/sites-available/default
/usr/sbin/nginx
/usr/share/nginx
/usr/share/doc/nginx
...

$ dpkg -s nginx        # 查看包的元数据
Package: nginx
Status: install ok installed
Priority: optional
Section: httpd
Maintainer: Ubuntu Developers <ubuntu-devel-discuss@lists.ubuntu.com>
Architecture: amd64
Version: 1.18.0-6ubuntu14.4
Depends: nginx-core, nginx-common, ...
Description: small, powerful, scalable web/proxy server
```

### 1.2 为什么要包管理

在没有包管理的年代（Windows 时代的"下一步 → 下一步 → 完成"），Linux 领域更惨——你可能要自己编译源码：

```bash
# 源码编译安装的"痛苦"流程
$ wget https://example.com/software-3.2.1.tar.gz
$ tar -xzf software-3.2.1.tar.gz
$ cd software-3.2.1
$ ./configure          # 检查依赖，生成 Makefile
configure: error: libfoo >= 2.0 not found   # 缺少依赖！
$ wget .../libfoo-2.1.tar.gz                # 下载依赖
$ tar -xzf libfoo-2.1.tar.gz                # 解压
$ cd libfoo-2.1
$ ./configure && make && sudo make install   # 编译安装依赖
$ cd ../software-3.2.1
$ ./configure         # 再次尝试...可能还有更多依赖
# ... 循环往复，这就是"依赖地狱"
```

**包管理的优势**：

| 问题 | 没有包管理 | 有包管理 |
|------|-----------|---------|
| 安装 | 手动下载、编译 | `apt install nginx` |
| 依赖 | 手动逐一解决（依赖地狱） | 自动解析安装 |
| 升级 | 重复整个流程 | `apt upgrade` |
| 卸载 | 不知道文件散落在哪里 | `apt remove nginx` 彻底清理 |
| 查询 | 无从查起 | `apt list --installed` |
| 安全 | 无法获知漏洞 | `apt update` 获取安全更新 |

### 1.3 软件仓库（Repository）

**仓库**是软件包的远程存储服务器，包含：
- 打包好的软件（`.deb`、`.rpm` 等）
- 索引信息（包名、版本、依赖关系）
- 数字签名（防止篡改）

```
你的电脑                         远程服务器
┌──────────┐                   ┌──────────────┐
│ apt/dnf  │ ─── 请求列表 ──→  │  软件仓库     │
│          │ ←── 返回索引 ──   │  (Repository) │
│          │                   │              │
│          │ ─── 下载包 ────→  │  main/        │
│          │ ←── 返回 .deb ──  │  universe/    │
│  /var/   │                   │  multiverse/  │
│  cache/  │                   │  ...          │
└──────────┘                   └──────────────┘
```

### 1.4 各种安装方式对比

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **包管理 (apt/dnf/pacman)** | 自动化、安全、统一管理 | 版本可能较旧 | 绝大多数场景 |
| **源码编译** | 最新版本、可定制优化 | 耗时、需手动解决依赖 | 需要特定功能/性能优化 |
| **二进制下载** | 直接运行、简单 | 无自动更新、需手动管理 PATH | 闭源软件、Go 程序 |
| **Snap** | 沙盒隔离、自动更新 | 体积大、启动慢 | Ubuntu 生态 |
| **Flatpak** | 跨发行版、沙盒隔离 | 体积大 | 桌面应用 |
| **AppImage** | 单文件运行、无安装 | 无自动更新 | 临时使用 |

## 二、Debian/Ubuntu 系（APT + dpkg）

> APT (Advanced Package Tool) 是 Debian/Ubuntu 的高级包管理工具，底层依赖 dpkg。

### 2.1 软件源（sources.list）

```bash
# 查看当前软件源
$ cat /etc/apt/sources.list
deb http://archive.ubuntu.com/ubuntu/ jammy main restricted
deb http://archive.ubuntu.com/ubuntu/ jammy-updates main restricted
deb http://archive.ubuntu.com/ubuntu/ jammy universe
deb http://archive.ubuntu.com/ubuntu/ jammy multiverse
deb http://security.ubuntu.com/ubuntu/ jammy-security main restricted
# deb-src ...  # 源码仓库（通常被注释掉）

# 源格式说明：
# deb/deb-src  仓库URL   发行版代号   组件1 组件2 ...
# deb：二进制包仓库
# deb-src：源码包仓库
```

**Ubuntu 仓库组件分类**：

| 组件 | 含义 | 支持级别 |
|------|------|---------|
| `main` | 官方支持的自由软件 | Canonical 官方支持 |
| `universe` | 社区维护的自由软件 | 社区支持 |
| `restricted` | 官方支持的专有驱动 | Canonical 支持（非自由） |
| `multiverse` | 非自由软件 | 无官方支持 |

### 2.4 卸载软件包

```bash
# apt remove：卸载包但保留配置文件
$ sudo apt remove nginx
# 遗留的配置文件位于 /etc/nginx/

# apt purge：彻底卸载（包括配置文件）
$ sudo apt purge nginx
# /etc/nginx/ 目录也被删除

# 清理不再需要的依赖
$ sudo apt autoremove
正在读取软件包列表... 完成
正在分析软件包的依赖关系树... 完成
将会同时卸载下列软件：
  nginx-common nginx-core libnginx-mod-http-geoip
  libnginx-mod-http-image-filter ...
升级了 0 个软件包，新安装了 0 个软件包，要卸载 7 个软件包，有 0 个软件包未被升级。
解压缩后将会空出 2,168 kB 的空间。
是否继续？ [Y/n] y

# 三种卸载方式对比
$ sudo apt remove package     # 卸载软件，保留配置
$ sudo apt purge package      # 卸载软件 + 删除配置
$ sudo apt autoremove         # 自动移除孤儿依赖
```

### 2.5 升级软件包

```bash
# 升级所有已安装的包（不会删除或安装新包）
$ sudo apt upgrade
正在读取软件包列表... 完成
正在分析软件包的依赖关系树... 完成
下列软件包将被升级：
  libssl3 openssl python3 python3-minimal
升级了 4 个软件包，新安装了 0 个软件包，要卸载 0 个软件包，有 0 个软件包未被升级。
需要下载 3,245 kB 的归档。
解压缩后会消耗 128 kB 的额外空间。
是否继续？ [Y/n] y

# 完整升级（会处理依赖变化，可安装/删除包）
$ sudo apt full-upgrade

# 列出可升级的包
$ apt list --upgradable

# 查看某个包的详细升级信息
$ apt show nginx | grep -E "^(Package|Version|Description)"
```

**dpkg 状态标志解读**：

| 标志 | 含义 |
|------|------|
| `ii` | 期望安装，已安装 |
| `rc` | 期望删除，仅残留配置文件 |
| `un` | 未知，未安装 |
| `iU` | 已安装，但未完全解包 |
| `iF` | 已安装，但配置失败 |

### 2.9 锁定软件包版本

```bash
# 锁定包，防止被升级
$ sudo apt-mark hold nginx
nginx 已设置为保留。

# 查看被锁定的包
$ apt-mark showhold
nginx

# 尝试升级（被锁定的包不会被升级）
$ sudo apt upgrade
下列软件包被保留而不升级：
  nginx

# 取消锁定
$ sudo apt-mark unhold nginx
已取消对 nginx 的保留。

# 自动/手动安装标记
$ apt-mark auto nginx-common     # 标记为自动安装（依赖用）
$ apt-mark manual nginx          # 标记为手动安装（用户主动装的）
```

### 2.10 清理缓存

```bash
# 查看缓存大小
$ du -sh /var/cache/apt/archives/
385M  /var/cache/apt/archives/

# apt clean：删除所有下载的 .deb 包（最彻底）
$ sudo apt clean
$ du -sh /var/cache/apt/archives/
4.0K  /var/cache/apt/archives/

# apt autoclean：只删除过时版本（保留最新版本）
$ sudo apt autoclean

# 一起清理
$ sudo apt autoremove && sudo apt autoclean && sudo apt clean
```

### 2.12 换国内镜像源

```bash
# 备份原始源
$ sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

Description:    Ubuntu 22.04.3 LTS

# 使用 sed 替换为阿里云镜像

$ sudo sed -i 's|http://security.ubuntu.com|http://mirrors.aliyun.com|g' /etc/apt/sources.list

# 使用 sed 替换为清华镜像
$ sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list

# 使用 sed 替换为中科大镜像
$ sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.ustc.edu.cn|g' /etc/apt/sources.list

# 更新源列表
$ sudo apt update && sudo apt upgrade
```


### 4.3 AUR（Arch User Repository）

AUR 是 Arch 社区用户维护的软件仓库，包含官方仓库没有的软件。

```bash
# AUR 助手：yay（最常用）或 paru

# 手动安装 AUR 包（不使用助手）

$ cd package-name
$ makepkg -si                  # -s 自动安装依赖，-i 安装
```

## 五、三大发行版命令对比表

| 操作 | Debian/Ubuntu (apt) | RHEL/Fedora (dnf) | Arch (pacman) |
|------|--------------------|--------------------|---------------|
| **更新索引** | `apt update` | `dnf check-update` | `pacman -Sy` |
| **升级所有包** | `apt upgrade` | `dnf upgrade` | `pacman -Su` |
| **更新+升级** | `apt update && apt upgrade` | `dnf update` | `pacman -Syu` |
| **安装包** | `apt install pkg` | `dnf install pkg` | `pacman -S pkg` |
| **卸载包** | `apt remove pkg` | `dnf remove pkg` | `pacman -R pkg` |
| **彻底卸载** | `apt purge pkg` | — | `pacman -Rns pkg` |
| **搜索包** | `apt search kw` | `dnf search kw` | `pacman -Ss kw` |
| **搜索已安装** | `apt list --installed` | `dnf list installed` | `pacman -Qs kw` |
| **查看包信息** | `apt show pkg` | `dnf info pkg` | `pacman -Si pkg` |
| **本地包信息** | `dpkg -s pkg` | `rpm -qi pkg` | `pacman -Qi pkg` |
| **列出包文件** | `dpkg -L pkg` | `rpm -ql pkg` | `pacman -Ql pkg` |
| **文件属于谁** | `dpkg -S /path` | `rpm -qf /path` | `pacman -Qo /path` |
| **清理依赖** | `apt autoremove` | `dnf autoremove` | `pacman -Qdt` |
| **清理缓存** | `apt clean` | `dnf clean all` | `pacman -Sc` |
| **安装本地包** | `dpkg -i pkg.deb` | `rpm -ivh pkg.rpm` | `pacman -U pkg.pkg.tar.zst` |
| **查找拥有者** | `apt-file search /bin/cmd` | `dnf provides /bin/cmd` | `pacman -F /bin/cmd` |

### 6.4 从源码编译

这是最传统、最灵活的安装方式：

```bash
# 完整流程：以安装 nginx 为例

# 1. 安装编译工具和依赖
$ sudo apt install build-essential libpcre3-dev zlib1g-dev libssl-dev

# 2. 下载源码
$ wget https://nginx.org/download/nginx-1.26.1.tar.gz
$ tar -xzf nginx-1.26.1.tar.gz
$ cd nginx-1.26.1

# 3. 配置（检测环境，生成 Makefile）
$ ./configure --prefix=/opt/nginx \
              --with-http_ssl_module \
              --with-http_v2_module \
              --with-http_gzip_static_module
checking for OS
 + Linux 5.15.0-91-generic x86_64
checking for C compiler ... found
 + using GNU C compiler
checking for PCRE library ... found
checking for OpenSSL library ... found
checking for zlib library ... found
...
Configuration summary
  + using system PCRE library
  + using system OpenSSL library
  + using system zlib library
  nginx path prefix: "/opt/nginx"
  nginx binary file: "/opt/nginx/sbin/nginx"
  nginx configuration file: "/opt/nginx/conf/nginx.conf"

# 4. 编译
$ make -j$(nproc)
# -j$(nproc) 使用所有 CPU 核心并行编译，加速

# 5. 安装
$ sudo make install

# 6. 验证
$ /opt/nginx/sbin/nginx -v

# 7. 添加到 PATH
$ echo 'export PATH="/opt/nginx/sbin:$PATH"' >> ~/.bashrc
$ source ~/.bashrc
```

**常见 `./configure` 选项**：

| 选项 | 含义 |
|------|------|
| `--prefix=/path` | 安装目录（默认 /usr/local） |
| `--bindir=/path` | 可执行文件目录 |
| `--sysconfdir=/path` | 配置文件目录 |
| `--enable-xxx` | 启用可选功能 |
| `--disable-xxx` | 禁用默认功能 |
| `--with-xxx` | 包含某个外部库 |
| `--without-xxx` | 排除某个外部库 |

**卸载源码编译的程序**：

```bash
# 方法1：如果有 make uninstall 目标
$ cd nginx-1.26.1
$ sudo make uninstall

# 方法2：手动删除（如果没有 uninstall 目标）
$ sudo rm -rf /opt/nginx

# 方法3：使用 checkinstall 生成 .deb 包管理
$ sudo apt install checkinstall
$ cd nginx-1.26.1
$ ./configure --prefix=/opt/nginx
$ make
$ sudo checkinstall    # 生成 .deb 包，可用 dpkg 管理卸载
```

## 七、总结

本章全面介绍了 Linux 软件包管理的各种方式：

| 知识点 | 关键内容 |
|--------|---------|
| 包管理概念 | 软件包 = 二进制+配置+依赖；解决依赖地狱 |
| APT/dpkg | Debian/Ubuntu 系，最常用的包管理器 |
| DNF/RPM | RHEL/Fedora 系，功能强大，支持历史回滚 |
| pacman | Arch 系，简洁快速，AUR 扩展 |
| 三大发行版对比 | 熟悉不同发行版的命令映射 |
| Snap | Ubuntu 推广的沙盒包格式 |
| Flatpak | 跨发行版的桌面应用分发方式 |
| AppImage | 单文件运行，无需安装 |
| 源码编译 | `./configure && make && make install` |
| 脚本安装 | `curl \| bash` 模式（注意安全） |
| 二进制下载 | 解压到 `/usr/local`，添加 PATH |

**选择建议**：

- **日常使用** → 优先使用发行版自带包管理器（apt/dnf/pacman）
- **需要最新版本** → 尝试 PPA（Ubuntu）、EPEL（RHEL）、AUR（Arch）
- **桌面应用** → Flatpak（跨发行版）或 Snap（Ubuntu）
- **临时试用** → AppImage
- **定制需求** → 源码编译
- **闭源软件/CLI 工具** → 二进制下载

7. 研究你的系统中的软件包依赖关系：
   ```bash
   # 选择一个你常用的软件，绘制其依赖树
   $ apt depends <package>    # Debian/Ubuntu
   $ dnf deplist <package>    # RHEL/Fedora
   $ pactree <package>        # Arch (需要 pacman-contrib)
   ```

> **提示**：不同发行版的包管理器虽语法不同但理念相通。建议在实际操作中熟悉你所用发行版的包管理命令，同时了解其他发行版的等价命令。遇到依赖问题时，使用 `apt depends`、`dnf deplist` 或 `pactree` 分析依赖树。
