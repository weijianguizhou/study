### 1.1 试分析时间复杂度
```c
sum=1;
for(i=0; sum<n; i++)
    sum+=i;
```

**解答**：时间复杂度为 $O(\sqrt{n})$。

> **推导**：初始 `sum = 1`，第 1 次循环后 `sum = 1 + 0 = 1`，第 2 次后 `sum = 1 + 1 = 2`，第 3 次后 `sum = 1 + 1 + 2 = 4`……第 $k$ 次循环后（$i = k-1$）：
> $$\text{sum} = 1 + \sum_{j=0}^{k-1} j = 1 + \frac{k(k-1)}{2}$$
> 循环条件为 $\text{sum} < n$，即 $1 + \frac{k(k-1)}{2} < n \implies \frac{k(k-1)}{2} < n-1 \approx \frac{k^2}{2} < n \implies k < \sqrt{2n}$。因此循环执行次数 $k$ 与 $\sqrt{n}$ 同阶。

### 1.2 试给出一个时间复杂度为 $O(\log_2 n)$ 的程序段。

**解答**：

**方法一（二分查找）**：
```c
int binarySearch(int arr[], int n, int target) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

**方法二（指数增长循环）**：
```c
int i = 1;
while (i < n)
    i *= 2;  // 每次翻倍，执行约 log₂ n 次
```

### 2.2.1 指出以下算法中的错误和低效之处，并将它改写成一个既正确又高效的算法。

**原算法错误/低效分析**：

| 问题 | 说明 |
|------|------|
| **低效** | 外层循环 $k$ 次，每次内层都移动全部后续元素。删除 $k$ 个连续元素只需移动一次后续元素，时间复杂度应从 $O(k \cdot n)$ 降为 $O(n)$ |
| **错误 1** | `j = a.length; j >= i+1; j--` 中 `j` 的初值应为 `a.length - 1`（数组下标从 0 开始） |
| **错误 2** | `a.elem[j-1] = a.elem[j]` 方向错误。删除操作应向前覆盖：`a.elem[j-1] = a.elem[j]` 当 $j$ 从 $i$ 递增到末尾，或反向。但这里是反向，应该是 `a.elem[j] = a.elem[j-1]`？不对——重新分析： |
| **错误 3** | 反向遍历时下标的逻辑——若从 $j = a.length-1$ 递减至 $i$，应执行 `a.elem[j-1] = a.elem[j]`（将后面元素前移）。但原代码 `j >= i+1`，`a.elem[j-1] = a.elem[j]` 实际是正确的前移，但初值 `a.length` 越界 |
| **错误 4** | 条件 `i+k > a.length` 应为 `i+k-1 >= a.length`（下标从 1 开始计数），即 `i + k - 1 > a.length` |

**改正后的高效算法**：

```cpp
Status DeleteK(SqList &a, int i, int k) {
    // 本过程从顺序存储结构的线性表a中删除第i个元素起的k个元素
    // i 从 1 开始计数（第 i 个位置）
    if (i < 1 || k < 0 || i + k - 1 > a.length)
        return INFEASIBLE;
    // 一次性前移：将第 i+k 个元素起的元素前移 k 位
    for (int j = i + k; j <= a.length; j++)
        a.elem[j - k - 1] = a.elem[j - 1];  // 下标从 0 开始存储
    a.length -= k;
    return OK;
}
```

> **效率分析**：原算法外层 $k$ 次循环 × 内层约 $(n-i)$ 次移动 = $O(kn)$。新算法仅一趟循环移动 $n-(i+k)+1$ 个元素 = $O(n)$。

### 6.3 一棵度为2的有序树与一棵二叉树有何区别？

**解答**：

| 度为 2 的有序树 | 二叉树 |
|---|---|
| 每个结点最多 2 棵子树，且子树**有次序** | 每个结点最多 2 棵子树，且有**明确的左/右之分** |
| 若结点只有 1 棵子树，无左右之分 | 若结点只有 1 棵子树，必须区分是**左子树**还是**右子树** |
| 空树无定义 | 空树是合法的二叉树 |
| 3 个结点的有序树（度≤2）只有 2 种形态 | 3 个结点的二叉树有 5 种形态 |

**核心区别**：二叉树中左右子树是严格区分的——即使另一侧为空，空的位置仍有意义（左空右非空 ≠ 左非空右空）。而度为 2 的有序树中，仅有一个子结点时不分左右。

### 6.5 高度为 $h$ 的完全二叉树至少有多少个结点？至多有多少个结点？

**解答**：

- **最少**：前 $h-1$ 层满，第 $h$ 层仅 1 个结点。结点数 $= 1 + 2 + 4 + \cdots + 2^{h-2} + 1 = (2^{h-1} - 1) + 1 = 2^{h-1}$

- **最多**：$h$ 层全满（满二叉树）。结点数 $= 1 + 2 + 4 + \cdots + 2^{h-1} = 2^h - 1$

$$
\boxed{2^{h-1} \leq n \leq 2^h - 1}
$$

### 6.6 下述编码哪一组不是前缀码？$\{00,01,10,11\}, \{0,1,00,11\}, \{0,10,110,111\}$

**解答**：

**$\{00,01,10,11\}$**：所有编码长度均为 2，互相不为前缀 → **是前缀码**。

**$\{0,1,00,11\}$**：$0$ 是 $00$ 的前缀 → **不是前缀码**。

**$\{0,10,110,111\}$**：
- $0$ 不是 $10$ 的前缀（$10$ 以 $1$ 开头）
- $0$ 不是 $110$ 的前缀
- $0$ 不是 $111$ 的前缀
- $10$ 不是 $110$ 的前缀（$110$ 的前两位是 $11 \neq 10$）
- $10$ 不是 $111$ 的前缀
- $110$ 不是 $111$ 的前缀（第三位 $0 \neq 1$）
→ **是前缀码**。

> 所以第二组 $\{0,1,00,11\}$ 不是前缀码。

### 6.7 哈夫曼编码设计

字符集 $\{a,b,c,d,e,f,g,h\}$，概率 $\{0.07, 0.19, 0.02, 0.06, 0.32, 0.03, 0.21, 0.10\}$。

**哈夫曼树构建过程**（每次合并最小的两个概率）：

| 步骤 | 合并 | 新结点概率 |
|------|------|-----------|
| 1 | c(0.02) + f(0.03) | 0.05 |
| 2 | 0.05 + d(0.06) | 0.11 |
| 3 | a(0.07) + h(0.10) | 0.17 |
| 4 | 0.11 + 0.17 | 0.28 |
| 5 | b(0.19) + g(0.21) | 0.40 |
| 6 | e(0.32) + 0.28 | 0.60 |
| 7 | 0.40 + 0.60 | 1.00 |

**哈夫曼编码结果**（左侧为 0，右侧为 1，或等效分配）：

| 字母 | 概率 | 编码 |
|------|------|------|
| e | 0.32 | `00` |
| c | 0.02 | `01000` |
| f | 0.03 | `01001` |
| d | 0.06 | `0101` |
| a | 0.07 | `0110` |
| h | 0.10 | `0111` |
| b | 0.19 | `10` |
| g | 0.21 | `11` |

**WPL**（带权路径长度）：
$$\begin{aligned}
\text{WPL} &= 0.32 \times 2 + 0.19 \times 2 + 0.21 \times 2 + 0.07 \times 4 + 0.10 \times 4 + 0.06 \times 4 + 0.02 \times 5 + 0.03 \times 5 \\
&= 0.64 + 0.38 + 0.42 + 0.28 + 0.40 + 0.24 + 0.10 + 0.15 \\
&= 2.61
\end{aligned}$$
