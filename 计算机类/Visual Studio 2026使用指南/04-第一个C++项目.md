# 04-第一个C++项目

前面三章都是准备工作。这一章真正开始写代码：建一个控制台项目，看懂 VS 在磁盘上生成了什么，弄明白 `F5` 和 `Ctrl+F5` 的区别，最后学会脱离 IDE 用命令行构建——这一步在接入 CI 时会用到。

---

## 1. 创建控制台应用

### 1.1 走一遍流程

1. 打开 VS 2026 → 起始窗口点 **创建新项目**（或按 `Ctrl+Shift+N`）。
2. 在模板列表里搜索 `控制台`，选择 **控制台应用**（语言筛选 **C++**，平台 **Windows**）。
3. 点 **下一步**，填写：

| 字段 | 建议值 | 说明 |
|------|--------|------|
| **项目名称** | `HelloVS` | 会同时作为默认命名空间名与 `.exe` 名 |
| **位置** | `D:\cpp\` | **不要放在中文路径或含空格的路径下**（见本章第 8 节） |
| **解决方案名称** | `HelloVS` | 可以留空，默认与项目同名 |
| **将解决方案和项目放在同一目录中** | 建议勾选 | 目录结构更扁平，便于理解 |

4. 点 **创建**。

### 1.2 模板选哪个

| 模板 | 生成什么 | 适合 |
|------|----------|------|
| **控制台应用** | 一个 `.cpp`，含 `main` 与 `#include <iostream>` | ✅ 学习、算法练习、命令行工具 |
| **空项目** | 什么都没有，需要自己添加文件 | 想完全从零开始 |
| **Windows 桌面应用程序** | Win32 窗口程序骨架 | 图形界面入门 |
| **静态库 / 动态库** | 库项目骨架 | 写库给别人用（见 [[05-项目与解决方案管理|第 5 章]]） |

> **提示**：VS 2026 的**新建** C++ 控制台项目默认使用 **C++20** 标准（项目模板会写入 `/std:c++20`）。这和"编译器在没指定 `/std` 时默认 C++14"并不矛盾——见 [[01-VS2026概览与版本选择#4.1 一个必须澄清的坑：默认标准有两个|第 1 章 4.1 节]]。

## 2. 项目文件结构解析

### 2.1 生成后磁盘上有什么

假设项目名 `HelloVS`，位置 `D:\cpp\`，勾选了"同一目录"，生成后的目录大致是：

```text
D:\cpp\HelloVS\
├── HelloVS.sln              ← 解决方案文件（文本格式，记录包含哪些项目）
├── HelloVS.vcxproj          ← MSBuild 项目文件（真正的构建定义，XML）
├── HelloVS.vcxproj.filters  ← 筛选器：只影响 IDE 里的显示分组
├── HelloVS.vcxproj.user     ← 你本机的个人设置（不提交到 Git）
├── HelloVS.cpp              ← 源文件
└── .vs\                     ← IDE 的隐藏缓存目录（不提交到 Git）
    └── ...
```

编译一次之后，还会多出：

```text
D:\cpp\HelloVS\
├── x64\
│   └── Debug\
│       ├── HelloVS.exe          ← 生成的可执行文件
│       ├── HelloVS.pdb          ← 调试符号
│       └── HelloVS.obj          ← 编译产生的目标文件
```

> **注意**：`.vs\` 是**隐藏目录**，在文件资源管理器里默认看不到。它保存了 IDE 的临时状态；遇到"IntelliSense 发疯""项目加载异常"时，**关掉 VS、删掉 `.vs\`、重新打开**是最常用的急救手段（详见 [[13-常见问题与效率技巧|第 13 章]]）。

### 2.2 每个文件干什么

| 文件 | 是否提交到 Git | 作用 |
|------|:---:|------|
| `HelloVS.sln` | ✅ | 解决方案：记录包含哪些项目、启动项目等 |
| `HelloVS.vcxproj` | ✅ | **核心**：编译器开关、包含目录、链接库、文件清单都在这 |
| `HelloVS.vcxproj.filters` | ✅ | IDE 里的筛选器分组（不影响编译） |
| `HelloVS.vcxproj.user` | ❌ | 本机调试设置（如命令行参数、工作目录） |
| `.vs\` | ❌ | IDE 缓存 |
| `x64\`、`Debug\`、`Release\` | ❌ | 中间产物与输出 |
| `HelloVS.cpp` | ✅ | 你的代码 |

对应的 `.gitignore` 片段：

```ini
# Visual Studio
.vs/
x64/
Debug/
Release/
*.user
*.aps
*.ipch
*.opendb
*.db
```

> **实战场景**：`.vcxproj.user` 里存着"调试时用什么命令行参数、工作目录是哪里"。这些是**本机**设置，同事的机器上路径可能完全不同，所以不该提交。项目级的公共调试参数应该写进 `.vcxproj` 的调试属性页。

### 2.3 在 IDE 里看结构

**解决方案资源管理器**显示的是"逻辑结构"：

```text
解决方案 'HelloVS' (1 个项目)
└── HelloVS
    ├── 头文件              ← 筛选器（可能是空的）
    ├── 源文件
    │   └── HelloVS.cpp
    ├── 资源文件            ← 筛选器（可能是空的）
    └── 引用                ← 引用的其他项目/库
```

注意 **"头文件""源文件""资源文件"是筛选器**，不是磁盘目录。哪怕它们显示为空，磁盘上也没有对应的空文件夹。

## 3. 读懂生成的代码

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello World!\n";
    return 0;
}
```

逐行看：

| 代码 | 含义 |
|------|------|
| `#include <iostream>` | 引入标准输入输出库，`std::cout` 需要它 |
| `int main()` | 程序入口。Windows 控制台程序的入口就是 `main`（或宽字符版 `wmain`） |
| `std::cout << ...` | 向标准输出写字符串；`std::` 是命名空间前缀 |
| `"\n"` | 换行符。比 `std::endl` 更轻量（不强制刷新缓冲区） |
| `return 0;` | 返回 0 表示正常结束。`main` 里其实可以省略，但写上更清晰 |

> **提示**：这里的 `std::` 前缀别嫌烦。虽然可以写 `using namespace std;`，但在头文件里绝对不要这么干，否则会把命名空间污染传给所有包含者。

## 4. 生成与运行

### 4.1 `Ctrl+F5` 与 `F5` 的区别

这是新手第一个必须搞清的差别：

| 快捷键 | 行为 | 什么时候用 |
|--------|------|-----------|
| **`Ctrl+F5`** | **开始执行（不调试）**：编译并运行，程序结束后**停在"按任意键继续"** | 只想看运行结果 |
| **`F5`** | **开始调试**：编译并附加调试器运行，程序结束窗口**直接关闭** | 要打断点排查问题 |
| **`Ctrl+Shift+B`** | 只生成，不运行 | 检查能否编译通过 |

> **注意**：用 `F5` 跑一个"打印完就退出"的程序，黑窗口会一闪而过——因为调试器接管了生命周期，不会自动暂停。想看输出就用 `Ctrl+F5`，或者在 `main` 的 `return` 前打断点。

### 4.2 生成输出：`Ctrl+Alt+O`

**输出窗口**（`Ctrl+Alt+O`）里选"**生成**"，能看到完整的编译过程：

```text
1>------ 已启动生成: 项目: HelloVS, 配置: Debug x64 ------
1>HelloVS.cpp
1>HelloVS.vcxproj -> D:\cpp\HelloVS\x64\Debug\HelloVS.exe
========== 生成: 成功 1 个，失败 0 个，最新 0 个，跳过 0 个 ==========
```

关键信息在最后一行。`->` 后面就是**可执行文件的完整路径**。

### 4.3 错误去哪看：`Ctrl+\, Ctrl+E`

编译失败时看**错误列表**（`Ctrl+\, Ctrl+E`）：

| 列 | 含义 |
|----|------|
| 代码 | 如 `C2143`、`LNK2019`（错误码速查见 [[13-常见问题与效率技巧|第 13 章]]） |
| 说明 | 错误描述 |
| 项目 / 文件 / 行 | **双击直接跳到出错位置** |

> **提示**：错误列表支持筛选（只看错误 / 只看警告），也支持按"生成 + IntelliSense"分类。**以"生成"分类为准**——IntelliSense 的红色波浪线有时是误报。

### 4.4 输出窗口 vs 程序输出

两者完全不同，别搞混：

```text
输出窗口（Ctrl+Alt+O）  →  编译器/链接器/调试器说的话
程序的黑窗口            →  你的 std::cout 输出
```

调试时想让信息出现在**输出窗口**，可以用：

```cpp
#include <windows.h>

OutputDebugStringA("这条信息会出现在 VS 的输出窗口\n");
```

这在写没有控制台的 Windows 程序时特别有用。

## 5. 命令行构建

脱离 IDE 构建是接入 CI 的第一步。有两种方式。

### 5.1 用 MSBuild（推荐）

先在开始菜单打开 **Developer Command Prompt for VS 2026**（这个快捷方式会帮你配好环境变量），然后：

```bat
:: 在解决方案目录下
msbuild HelloVS.sln /p:Configuration=Debug /p:Platform=x64

:: 生成 Release 版本
msbuild HelloVS.sln /p:Configuration=Release /p:Platform=x64

:: 重新生成（先清理再编译）
msbuild HelloVS.sln /t:Rebuild /p:Configuration=Release /p:Platform=x64

:: 清理
msbuild HelloVS.sln /t:Clean
```

常用参数：

| 参数 | 作用 |
|------|------|
| `/p:Configuration=Debug\|Release` | 指定配置 |
| `/p:Platform=x64\|Win32\|ARM64` | 指定平台（注意 32 位在 MSBuild 里叫 **`Win32`**，不是 `x86`） |
| `/t:Build\|Rebuild\|Clean` | 指定目标 |
| `/m` | 多进程并行构建 |
| `/v:minimal\|normal\|detailed` | 输出详细程度 |
| `/p:VCToolsVersion=14.50.35717` | 锁定工具集版本 |
| `/bl` | 生成 `msbuild.binlog`，可用结构化日志查看器分析 |

> **注意**：**必须用"开发者命令提示符"**，不能用普通的 `cmd`。因为 `msbuild` 依赖一堆环境变量（`PATH`、`INCLUDE`、`LIB` 等），普通命令行里没配，会报"找不到 windows.h"之类的错。想自己配的话，先执行 `vcvars64.bat`。

### 5.2 用 devenv（IDE 的命令行外壳）

```bat
devenv HelloVS.sln /Build "Release|x64"
devenv HelloVS.sln /Rebuild "Debug|x64"
devenv HelloVS.sln /Clean
```

`devenv` 会启动 IDE 的构建引擎。适合需要与 IDE 行为完全一致的场景，但**比 MSBuild 慢**，CI 里一般用 MSBuild。

### 5.3 验证生成结果

```bat
:: 确认 exe 存在
dir x64\Release\HelloVS.exe

:: 直接运行
x64\Release\HelloVS.exe
```

## 6. 配置与平台：Debug/x64 是什么意思

工具栏上那两个下拉框（如 `Debug` + `x64`）合起来叫一个**配置**：

```text
配置 = 配置(Configuration) × 平台(Platform)
       ├── Debug   ：不优化、带完整调试信息 → 开发时用
       ├── Release ：开优化、面向发布     → 发布时用
       └── 平台
           ├── x64   ：64 位（现在的默认选择）
           ├── Win32 ：32 位（对应 x86，MSBuild 里就叫 Win32）
           └── ARM64 ：ARM 64 位
```

| 组合 | 输出目录 |
|------|----------|
| Debug + x64 | `x64\Debug\` |
| Release + x64 | `x64\Release\` |
| Debug + Win32 | `Debug\`（32 位时通常不带平台前缀） |

**Debug 与 Release 的关键差异**：

| 维度 | Debug | Release |
|------|-------|---------|
| 优化 | `/Od` 关闭 | `/O2` 最大化速度 |
| 调试信息 | `/Zi` 完整 | 通常仍有 `/Zi`（但优化会让单步错位） |
| 运行库 | `/MDd`（调试版 CRT） | `/MD`（发行版 CRT） |
| `assert` | 生效 | 被 `NDEBUG` 屏蔽 |
| 速度 | 慢得多 | 快 |

> **注意**：**性能测试必须在 Release 下做**。在 Debug 下测出来的耗时可能比 Release 慢十倍以上，据此优化会得出完全错误的结论。详见 [[09-性能分析与诊断|第 9 章]]。

> **实战场景**：Debug 下能跑、Release 下崩溃，是最经典的一类 bug。常见原因是**未初始化变量**（Debug 下 CRT 会帮忙填 0xCC，Release 下是真正的垃圾值）或**优化暴露的越界访问**。这时该上 AddressSanitizer——见 [[09-性能分析与诊断|第 9 章]]。

## 7. 动手改：加一个头文件和一个源文件

试着把代码拆开，体会多文件项目的工作方式。

**`mathutils.h`**（右键项目 > **添加 > 新建项 > 头文件**）：

```cpp
#pragma once

namespace mathutils {
    int add(int a, int b);
    int factorial(int n);
}
```

**`mathutils.cpp`**（右键项目 > **添加 > 新建项 > C++ 文件**）：

```cpp
#include "mathutils.h"

namespace mathutils {

int add(int a, int b) {
    return a + b;
}

int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

}  // namespace mathutils
```

**`HelloVS.cpp`**：

```cpp
#include <iostream>
#include "mathutils.h"

int main()
{
    std::cout << "3 + 4 = " << mathutils::add(3, 4) << '\n';
    std::cout << "5! = " << mathutils::factorial(5) << '\n';
    return 0;
}
```

按 `Ctrl+F5`，输出：

```text
3 + 4 = 7
5! = 120
```

> **提示**：新建的文件会**自动加入项目**（`.vcxproj` 里多了一条 `<ClCompile>`）。如果手动往目录里拷文件，IDE 不会自动感知——需要右键项目 > **添加 > 现有项**。

## 8. 首次运行常见问题

| 现象 | 原因 | 处置 |
|------|------|------|
| `Ctrl+F5` 后黑窗口一闪而过 | 用的是 `F5`，或程序崩溃退出 | 改用 `Ctrl+F5`；或在 `return` 前打断点 |
| 中文输出乱码 | 源码编码与控制台代码页不一致 | 用 `/utf-8` 编译选项，或设置控制台代码页。详见 [[13-常见问题与效率技巧#2. 中文乱码专题\|第 13 章]] |
| 报错"无法打开源文件 iostream" | 没装 C++ 工作负荷，或包含路径被改坏 | 安装器里补装"使用 C++ 的桌面开发" |
| 报错 `LNK2019 无法解析的外部符号` | 函数声明了但没实现，或没把 `.cpp` 加入项目 | 检查 `.cpp` 是否在项目里；见 [[13-常见问题与效率技巧\|第 13 章]] |
| 路径含中文/空格导致怪问题 | 工具链对非 ASCII 路径支持不佳 | 把项目移到纯英文、无空格的路径 |
| 提示找不到 `msbuild` | 用了普通 `cmd` | 改用"开发者命令提示符" |

## 小结

- 创建项目：`Ctrl+Shift+N` → **控制台应用**（C++）→ **不要放中文/空格路径**。
- 核心文件是 **`.vcxproj`**；`.filters` 只管 IDE 显示，`.user` 与 `.vs\` 不该提交。
- **`Ctrl+F5` 不调试运行（窗口会停住）**，**`F5` 调试运行（窗口直接关）**。
- 看编译过程用**输出窗口**，看错误用**错误列表**，两者不同。
- 命令行构建用 **MSBuild**，且必须在**开发者命令提示符**里；32 位平台名是 **`Win32`**。
- **Debug 与 Release 差异巨大**，性能测试必须在 Release 下做。
- 新建文件会自动加入项目；手工拷进来的文件需要"添加 > 现有项"。

## 练习题

1. 创建一个名为 `HelloVS` 的控制台应用，用 `Ctrl+F5` 和 `F5` 各运行一次，说明黑窗口行为为什么不同。
2. 在磁盘上找到生成的 `.exe`，记录它在 Debug x64 与 Release x64 两种配置下的完整路径。
3. 用开发者命令提示符分别构建 Debug 与 Release，并用 `/v:minimal` 观察输出差异。
4. 用 `msbuild /p:VCToolsVersion=...` 锁定工具集版本构建一次，在输出里确认编译器版本。
5. 按第 7 节拆出 `mathutils.h` / `mathutils.cpp`，再故意把 `mathutils.cpp` 从项目里排除，观察报什么错，并说明原因。
6. 在 Release 下写一个未初始化变量的程序，观察它是否"偶发崩溃"，再用 AddressSanitizer 复查一次。
