# 07-代码编辑与IntelliSense

写 C++ 的时间里，真正在"想算法"的部分可能不到一半，剩下的都花在找符号、对名字、改调用点这些琐事上。Visual Studio 的编辑器就是冲着这些琐事来的：IntelliSense 负责读懂你的代码，导航与重构负责带你在几万个符号之间穿梭，格式化、代码片段与 AI 补全负责让你少敲几百次键盘。这一章把这些能力一次讲清楚，并把 VS 2026 在编辑体验上的新改进点出来。

---

## 1. IntelliSense 是什么，不是什么

### 1.1 它是另一套引擎，不是编译器

本章最重要的一句话：**IntelliSense 与 MSVC 编译器是两套完全独立的代码理解引擎**。补全、波浪线、快速信息、导航全部来自 IntelliSense（内部使用 **EDG 前端**解析），与你按下"生成"时跑的 `cl.exe` 不是一回事。

```text
               你的 .cpp / .h 源码
                       │
      ┌────────────────┴────────────────┐
      ▼                                 ▼
┌────────────────────┐        ┌────────────────────┐
│ IntelliSense       │        │ MSVC 编译器 cl.exe  │
│ （EDG 前端·容错）   │        │ （严格·一次到底）    │
│ 补全·波浪线·导航    │        │ 真报错·真代码生成    │
└────────────────────┘        └────────────────────┘
      └────────────────┬────────────────┘
                       ▼
    "波浪线报错，但能编译通过" / "编译通过，波浪线还在"
```

### 1.2 三个必须接受的现象

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 红波浪线报错，但生成成功 | EDG 在模板、宏、`constexpr` 上比 MSVC 保守 | 编译通过就先用着；反复误报见第 13 章 |
| 编译报错，编辑器却一片干净 | IntelliSense 还没跟上编辑，或解析路径与编译器不同 | 先看**错误列表**，必要时重新扫描解决方案 |
| 刚打开大项目时提示"发虚" | 全代码库语义索引还在建立，符号表不完整 | 等索引跑完，或手动重新扫描（见 9.5） |

> **注意**：**以编译器为准**。IntelliSense 的报错**不会**阻断"生成"，编译器的报错会。所以"能跑起来"不能反推"代码没问题"，反过来也一样——别把红波浪线当成编译失败的证据。

## 2. 补全与提示

### 2.1 五条常用命令

| 命令 | 快捷键 | 菜单路径 | 作用 |
|------|--------|----------|------|
| 列出成员 | `Ctrl+J` | 编辑 > IntelliSense > 列出成员 | 弹出当前作用域可见的成员与变量 |
| 完成单词 | `Ctrl+Space` | 编辑 > IntelliSense > 完成单词 | 补全正在输入的标识符 |
| 参数信息 | `Ctrl+Shift+Space` | 编辑 > IntelliSense > 参数信息 | 显示重载列表并高亮当前参数 |
| 快速信息 | `Ctrl+K, Ctrl+I` | 编辑 > IntelliSense > 快速信息 | 鼠标悬停提示的键盘版本 |
| 快速操作 | `Ctrl+.` | 编辑 > 快速操作和重构 | 打开灯泡/螺丝刀建议列表 |

> **提示**：`Ctrl+K, Ctrl+I` 这类**组合键**分两段按：先按 `Ctrl+K`，全部松开，再按 `Ctrl+I`。`Ctrl+Space` 是"把正在敲的词补完"，`Ctrl+J` 是"把能用的东西都列出来看看"，记不住名字时用后者。

### 2.2 内联提示（Inlay Hints）与悬停信息

内联提示把**本来不写在代码里、读代码时却需要知道的信息**直接渲染在标识符旁边，默认开启。按 **Alt+F1** 随时切换显示与隐藏；设置位于 **工具 > 选项 > 文本编辑器 > C/C++ > IntelliSense**（想换按键就到 **工具 > 选项 > 环境 > 键盘** 里搜"内联提示"）。它主要显示**参数名提示**与**类型提示**（`auto`、结构化绑定推导出的真实类型）；这些提示只是"画上去的"，不会写进文件，也不影响编译。

```cpp
auto count = items.size();            // 内联类型提示：size_t
for (auto& [key, value] : table) { }  // 内联类型提示：const std::string / int
draw(1920, 1080, true);               // 内联参数名提示：width / height / antialias
```

## 3. 导航

### 3.1 跳转命令总表

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 转到定义 | `F12` | 跳到符号的定义处 |
| 转到声明 | `Ctrl+F12` | 跳到头文件里的声明处 |
| 速览定义 | `Alt+F12` | 就地弹出浮层查看定义，不离开当前文件 |
| 查找所有引用 | `Shift+F12` | 列出全解决方案的引用，可筛选读/写 |
| 转到所有 | `Ctrl+T` 或 `Ctrl+,` | 统一的搜索框式跳转入口 |
| 导航后退 / 前进 | `Ctrl+-` / `Ctrl+Shift+-` | 跳转后回原位，成对使用 |
| 类视图 / 书签窗口 | `Ctrl+Shift+C` / `Ctrl+K, Ctrl+W` | 按类组织代码（见 9.3）；打开书签列表（见 8.2） |

`Ctrl+T` / `Ctrl+,` 的价值在于"我大概记得有这么个东西"——输入时实时过滤出**文件、类型、成员、符号**；只想要某一类结果时，**编辑 > 转到** 菜单下有专门的**转到文件 / 转到类型 / 转到成员 / 转到符号**命令。

**速览定义与 CodeLens**：`Alt+F12` 打开的**速览定义**是一个**可以编辑的真编辑器**（只是嵌在浮层里），不是只读预览——读实现细节时就地看、顺手改，按 `Esc` 关掉，人还在原处，浮层里继续按 `F12` 还能再钻一层。改函数签名前的必做动作是 `Shift+F12`（**查找所有引用**），结果按项目/文件分组。**CodeLens** 则在每个函数、类上方显示**引用计数**与作者信息，点计数就地展开引用列表；VS 2026 的 C++ CodeLens 引用依赖全代码库语义索引（见 9.5），索引跑完计数才准，想关掉它去 **工具 > 选项 > 文本编辑器 > 所有语言 > CodeLens**。编辑器顶部由三个下拉框组成的**导航栏**（左选类型/命名空间，中选成员，右切重载）适合在长文件里定位成员，开关在 **工具 > 选项 > 文本编辑器 > 所有语言 > 常规 > 导航栏**。

> **实战场景**：读陌生函数时用 `Alt+F12` 一层层往下"扒"，比反复开文件、跳来跳去再按十几次后退快得多，而且不污染导航历史。

## 4. 重构

### 4.1 重命名：`Ctrl+R, Ctrl+R`

`Ctrl+R, Ctrl+R`（或 `Ctrl+.` 里选重命名）打开重命名面板，输入新名字后回车：

- **改之前会预览**，可以展开确认每一处改动；
- **可以带上注释与字符串**里的同名内容一起改；
- **重命名类型时可以同步改文件名**，把 `Foo` 改成 `Bar` 时顺手把 `Foo.h` / `Foo.cpp` 一起改名。

### 4.2 创建声明/定义、移动定义位置与其它重构

在头文件里写了声明还没写实现时，把光标放在函数名上按 `Ctrl+.` 会出现**创建定义**；反过来在 `.cpp` 里对着实现按 `Ctrl+.` 可以**创建声明**；已有实现想挪进头文件，用**移动定义位置**。

> **提示**：执行"创建声明/定义"后编辑器要不要跳过去是可以配置的——选项里提供**速览**、**打开文档**、**不导航**三种行为（配置入口在 **工具 > 选项 > 文本编辑器 > C/C++** 下）。写代码快的人通常选"速览"，批量补实现时选"不导航"。

| 操作 | 入口 | 说明 |
|------|------|------|
| 提取函数 | `Ctrl+.` > 提取函数 | 选中一段代码抽成新函数，自动处理参数与返回值 |
| 转为原始字符串字面量 | `Ctrl+.` > 转为原始字符串 | 把满是 `\\` 的路径变成 `R"(C:\data\out)"` |
| 添加 / 移除 `#include` | `Ctrl+.` | 补上缺失的直接包含，或清理未使用的包含，见 5.3 |

按 `Ctrl+.` 弹出的图标有两种含义：**灯泡**是"快速操作"，会改变代码结构或行为（创建定义、提取函数、添加 `#include`）；**螺丝刀**是"建议"，只影响代码**风格/质量**、不改变语义（成员函数加 `const`、全局函数加 `static`）。第 5 节讲的就是 C++ 特有的螺丝刀建议。

## 5. C++ 专属的智能建议

### 5.1 建议把不修改状态的成员函数标记为 `const`

```cpp
class Counter {
public:
    int Value() { return value_; }   // 螺丝刀：没改状态，可以加 const
    void Add(int n) { value_ += n; }
private:
    int value_ = 0;
};
```

改成 `int Value() const` 之后它就能被 `const Counter&` 调用了。这不是洁癖：**漏写 `const` 是"能编译但用不了"的典型原因**——某个函数接 `const` 引用，你却在里面调了非 `const` 成员函数，报错信息还很难看。

### 5.2 建议把只在本文件使用的全局函数标记为 `static`

在 `.cpp` 里定义、又只被本文件调用的全局函数（例如 `static int clamp01(int v) { ... }`），编辑器会建议加 `static` 改为内部链接。好处有两个：**避免符号名冲突**（两个 `.cpp` 里各写一个同名函数也不会撞车）与给编译器更多优化空间。同样的建议也适用于只在本翻译单元使用的全局常量与变量，更彻底的做法是放进匿名命名空间。

### 5.3 未使用的 `#include` 会变灰

一个 `#include` 如果在**当前翻译单元里没被用到**，它的文字就会变**灰色**——这是排查"编译时间为什么这么长"的第一现场。

```cpp
#include <vector>    // 用到了，正常颜色
#include <string>    // 没用到，显示为灰色
#include <map>       // 没用到，显示为灰色

void f(const std::vector<int>& v) { (void)v; }
```

把光标放到灰行上按 `Ctrl+.`，可以**移除这一个**，也可以**一次移除当前文件中所有未使用的 `#include`**。反方向的能力同样有：使用了只被间接包含进来的符号时（例如没直接包含 `<algorithm>` 就调用了 `std::sort`），编辑器会建议**添加对应的 `#include`**。

> **注意**：别盲目相信"灰掉就没用"。宏、模板特化、`static_assert` 里用到的符号可能不被 IntelliSense 统计到；头文件里删 `#include` 尤其要谨慎——它可能一直是某个 `.cpp` 赖以工作的**传递依赖**。**删完立刻生成一次**，让编译器兜底。

### 5.4 大小与对齐预览

把鼠标悬停在一个类/结构体/联合体/枚举上，快速信息里会给出**大小与对齐**：

```cpp
struct Packet {
    char   tag;      // 偏移 0
    int    seq;      // 偏移 4（tag 之后有 3 字节填充）
    double payload;  // 偏移 8
};                   // 大小 16 字节，对齐 8 字节
```

它在三种场合非常值钱：给结构体加字段前评估体积变化、按二进制格式收发数据时核对布局、多线程代码里判断两个对象会不会落在同一个缓存行上。要更严格地钉死布局，可配合 `#pragma pack` 或 `alignas`，再回来悬停复查。

## 6. 代码片段

### 6.1 展开与插入

| 方式 | 快捷键 / 操作 | 说明 |
|------|--------------|------|
| 输入片段名 + `Tab` | 例如输入 `for` 后按 `Tab` | 最常用，也可在补全列表里挑带"代码片段"图标的候选 |
| 插入代码片段 | `Ctrl+K, Ctrl+X` | 从列表里挑一个片段插入 |
| 外侧代码 | `Ctrl+K, Ctrl+S` | 用片段把选中代码包裹起来，如包进 `#if` |

C++ 内置片段常用的有 `#if`（条件编译骨架）、`for`、`while`、`switch`、`class`、`struct`、`enum`、`main`。展开后用 `Tab` 在可替换字段之间跳，`Enter` 或 `Esc` 结束编辑。

### 6.2 代码片段管理器与自定义片段

**工具 > 代码片段管理器**是片段的总入口：左侧选语言（选 **Visual C++**），能看到每个片段的位置路径，右下角有**导入**按钮。自定义片段有两条路：在管理器里用**导入**按钮选择 `.snippet` 文件，或直接把它拷进用户片段目录（管理器里会显示具体路径，通常是"文档"下的 `Visual Studio 2026\Code Snippets\Visual C++\My Code Snippets`）。下面这个片段叫 `cwout`，展开后打印"变量名 = 值"：

```xml
<?xml version="1.0" encoding="utf-8"?>
<CodeSnippets xmlns="http://schemas.microsoft.com/VisualStudio/2005/CodeSnippet">
  <CodeSnippet Format="1.0.0">
    <Header>
      <Title>cwout</Title>
      <Shortcut>cwout</Shortcut>
      <Description>把变量名与值一起输出到 std::cout</Description>
      <SnippetTypes><SnippetType>Expansion</SnippetType></SnippetTypes>
    </Header>
    <Snippet>
      <Declarations>
        <Literal><ID>var</ID><ToolTip>要打印的变量</ToolTip><Default>x</Default></Literal>
      </Declarations>
      <Code Language="cpp" Delimiter="$"><![CDATA[std::cout << "$var = " << $var << '\n';$end$]]></Code>
    </Snippet>
  </CodeSnippet>
</CodeSnippets>
```

几个必须注意的点：扩展名是 **`.snippet`**，用 **UTF-8** 保存（否则中文描述乱码）；`<Shortcut>` 是展开时输入的名字，`<Title>` 是列表里显示的名字；`$var$` 是可替换字段，`$end$` 是展开后光标停留的位置；`<Code Language="cpp">` 指明这是 C++ 片段，XML 结构少一层就不会被识别。

## 7. 格式化与代码风格

### 7.1 格式化快捷键

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 格式化文档 | `Ctrl+K, Ctrl+D` | 按当前风格设置重排整个文件 |
| 格式化选区 | `Ctrl+K, Ctrl+F` | 只排选中部分；输入 `;`、`}` 时编辑器也会自动调整缩进 |

### 7.2 `.editorconfig`：把风格写进仓库

`.editorconfig` 是与编辑器无关的纯文本约定文件，放在仓库里跟着 Git 走。Visual Studio 会读取它并让它**覆盖个人的 IDE 设置**，团队里每个人的缩进、换行、编码就都一致了，代码评审里也不会再出现"整篇都是改动"的假 diff。规则是**就近生效**：子目录里的配置覆盖上层，`root = true` 表示到此为止不再往上找。

| 键 | 取值 | 作用 |
|------|------|------|
| `indent_style` | `space` \| `tab` | 用空格还是制表符缩进 |
| `indent_size` | 整数 | 一级缩进的宽度 |
| `end_of_line` | `lf` \| `crlf` \| `cr` | 换行符类型，跨平台协作的关键 |
| `charset` | `utf-8` \| `utf-8-bom` \| `gbk` … | 文件编码，**解决乱码的第一道防线** |
| `trim_trailing_whitespace` | `true` \| `false` | 保存时删除行尾空白 |
| `insert_final_newline` | `true` \| `false` | 文件末尾补一个空行 |

一份实用的 C++ 仓库配置：

```ini
# 仓库根目录，不再向上级目录查找
root = true

[*]
charset = utf-8
end_of_line = crlf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 4

[*.{cpp,cc,cxx,h,hpp,inl,ipp}]
indent_size = 4
max_line_length = 100

# Markdown 里行尾两个空格是有意义的换行，别删
[*.md]
trim_trailing_whitespace = false
```

> **提示**：`charset = utf-8` 只约束**新建文件与格式化时的编码**，已经在磁盘上存成 GBK 的老文件不会自动转换，还得靠 9.2 的编码控件手工转一次。

### 7.3 clang-format 集成

团队里已有 `.clang-format` 时不必维护两套风格。在 **工具 > 选项 > 文本编辑器 > C/C++ > 格式设置** 里启用 ClangFormat 支持后，只要项目目录中存在 `.clang-format`，`Ctrl+K, Ctrl+D` 就会按它的规则排版，并不再使用 VS 自己的缩进/空格设置。

```ini
# .clang-format
BasedOnStyle: LLVM
Language: Cpp
Standard: c++20
IndentWidth: 4
ColumnLimit: 100
PointerAlignment: Left
SortIncludes: true
```

> **注意**：`BasedOnStyle` 决定基线（`LLVM` / `Google` / `Microsoft` 等），`ColumnLimit` 决定折行宽度，`PointerAlignment` 决定 `int* p` 还是 `int *p`；`SortIncludes` 会重排 `#include`，而**头文件之间的顺序有时是有语义的**，顺序敏感的文件可以用 `// clang-format off` / `// clang-format on` 圈起来。

> **提示**：格式化用 clang-format，**静态检查**用 clang-tidy，两者的配置是分开的：clang-tidy 的开关与检查项在 **项目属性 > 代码分析 > Clang-Tidy** 里配置。

## 8. 编辑器效率技巧

### 8.1 多光标与行操作

| 操作 | 快捷键 / 方式 | 说明 |
|------|--------------|------|
| 加一个光标 | `Ctrl+Alt+单击` | 在点击处再插一个插入点，可加多个，`Esc` 取消 |
| 框选（列选择） | `Alt+拖动` | 按矩形区域选择，改对齐的数据列极快 |
| 复制行 / 移动行 | `Ctrl+D` / `Alt+↑`、`Alt+↓` | 复制当前行到下方；上下挪动当前行或选中块 |
| 删除行 / 剪贴板环 | `Ctrl+Shift+L` / `Ctrl+Shift+V` | 删除当前行；在历史剪贴内容之间循环粘贴 |
| 注释 / 取消注释 / 大小写 | `Ctrl+K, Ctrl+C`、`Ctrl+K, Ctrl+U` / `Ctrl+Shift+U`、`Ctrl+U` | 对选中块整块加 `//` 或去掉；改宏名、常量名时顺手 |
| 跳到匹配括号 | `Ctrl+]` | 光标放在 `{`、`(` 上跳到配对的另一半，也能在 `#if` / `#endif` 间跳 |

典型用法：把一组 `int x1, x2, x3;` 里的 `int` 全改成 `long long`——用 `Alt+拖动` 框住那一列直接输入替换。

### 8.2 任务列表、书签、折叠与结构参考线

在注释里写下约定令牌，它就会出现在 **视图 > 任务列表** 里，默认令牌包括 `TODO`、`HACK`、`UNDONE`、`UnresolvedMergeConflict`：

```cpp
// TODO: 把这里换成 std::string_view，避免一次拷贝
// HACK: 依赖了未定义行为，等上游修复后删掉
```

在 **工具 > 选项 > 环境 > 任务列表** 里可以添加自己的令牌（比如 `FIXME`）并设置**优先级**；双击条目直接跳到代码位置。它按令牌解析，比满仓库搜 `TODO` 靠谱得多，不会误命中字符串里的普通文本。

**书签**适合"这几个地方等会儿都要回来改"：`Ctrl+K, Ctrl+K` 切换书签，`Ctrl+K, Ctrl+N` / `Ctrl+K, Ctrl+P` 前后跳，`Ctrl+K, Ctrl+W` 打开书签窗口（可改名、分组）。**折叠**适合收拾长文件：`Ctrl+M, Ctrl+O` 折叠到定义（只留函数签名，一屏看完文件结构），`Ctrl+M, Ctrl+M` 折叠/展开当前块，`Ctrl+M, Ctrl+L` 全部展开或折叠，`Ctrl+M, Ctrl+P` 停止大纲显示。**结构参考线**是编辑器左侧那些淡色竖线，用来指示代码块的嵌套层级，开关在 **工具 > 选项 > 文本编辑器 > 常规 > 显示结构参考线**。

## 9. VS 2026 的编辑体验改进

### 9.1 C++ 属性语法高亮与快捷键统一

`[[nodiscard]]`、`[[maybe_unused]]`、`[[likely]]`、`[[deprecated]]` 这类 C++ 属性在 VS 2026 里终于有了独立着色，不再和普通标识符糊在一起，属性密集的现代 C++ 代码可读性提升明显；颜色可在 **工具 > 选项 > 环境 > 字体和颜色** 里单独调整。这一代还统一了一批按键约定，让**快捷键向其他编辑器看齐**，从 VS Code 迁过来的人会更顺手（多光标、复制行、行移动这几类尤其明显）。如果反而改不回肌肉记忆，**工具 > 选项 > 环境 > 键盘** 里有**键盘方案**下拉框，可以直接切换到其他编辑器的键位方案。

### 9.2 右下角增强控件：查看与修改文件编码

编辑器**右下角**的编码指示器现在可以直接点击操作，这是解决中文乱码最顺手的一条路。把一份 GBK 老文件转成 UTF-8 的完整步骤：

1. 打开乱码文件，先看右下角显示的编码（例如 **GB2312**，或带 BOM 的 **UTF-8 with BOM**）；
2. **单击**这个编码名，在菜单里选**使用编码重新打开**，从列表里挑一个候选（中文 Windows 上通常是 GB2312 或 UTF-8），用**预览**确认注释已能正常显示；
3. 显示正确后再次单击编码名，选**通过编码保存**，把它真正存成 UTF-8；
4. 编译期再补一刀：在 **项目属性 > C/C++ > 命令行** 的"其他选项"里加上 **`/utf-8`**（等价于同时指定源码字符集与执行字符集），让 MSVC 明确按 UTF-8 解读源文件。

| 你看到的乱码 | 常见成因 |
|--------------|----------|
| `锟斤拷` | 文件本是 UTF-8 却被按 GBK 打开（或反之） |
| `????` 或方块 / `C2001: 常量中有换行符` | 前者是保存时目标编码无法表示这些字符（信息已丢失）；后者是源文件编码与编译器默认代码页不一致，字符串字面量被截断 |

> **实战场景**：从同事那里拷来一批 `.cpp`，注释全是 `锟斤拷`。不要逐个用记事本"另存为"——在 VS 里逐个走"重新打开 → 通过编码保存"两步即可，改完把 `.editorconfig` 的 `charset` 定为 `utf-8`，下次就不会再犯。

### 9.3 查找排除文件、类视图子串搜索

Quick Find（`Ctrl+F`）与 Find in Files（`Ctrl+Shift+F`）都支持**排除**条件：在查找窗口里把不想搜的路径或通配符填进排除项，例如 `third_party/`、`build/`、`out/`、`*.generated.h`。这解决的是大型仓库里很实在的痛点——搜一个 `CreateWindow`，结果前两百条全来自第三方库和生成代码。

**视图 > 类视图**（`Ctrl+Shift+C`）的搜索框现在支持**子串匹配**：输入 `render` 就能命中 `DeferredRenderer`、`RendererFactory`，不必从单词开头对齐；配合 VS 2026 对大型项目的性能优化，几万个类型的解决方案里过滤与展开也基本不卡。

### 9.4 右键一键生成预处理输出

在**解决方案资源管理器**里对着一个 `.cpp` 文件右键，选择**预处理**，IDE 会立刻生成预处理之后的完整输出（默认落在项目的中间目录下，如 `x64\Debug\`）。它对应编译开关 `/P`（保留 `#line` 标记，便于对照原始行号；`/EP` 则去掉行标记，只留纯代码）。三个最有价值的场景：**宏套娃看不懂**（展开后 `MAX(1+2, 3)` 变成什么一目了然）、**查某个头文件是谁包含进来的**（在输出里搜 `#line` 附近的文件名，一路倒推包含链）、**模板/宏相关的编译错误定位**（编译器报的位置在宏里，输出能还原成实际参与编译的那一行）。输出动辄几万到几十万行，用 `Ctrl+F` 查找，别滚动着看。

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int v = MAX(1 + 2, 3);   // 预处理后：((1 + 2) > (3) ? (1 + 2) : (3))
// 实参被原样替换两次 —— 若实参带副作用（如 i++），就会被执行两遍
```

### 9.5 全代码库语义索引

VS 2026 为 C++ 引入了**全代码库语义索引**：把整个解决方案的符号关系建成索引后，导航（`F12`、`Ctrl+T`、`Shift+F12`）与语法着色的性能相比以前**提升 2 倍以上**，C++ 的 CodeLens 引用计数也依赖它。配置位于 **工具 > 选项 > C/C++ > IntelliSense > 浏览和导航**。

- 首次打开大型解决方案需要一段建立索引的时间，**此期间补全与跳转质量会下降**——这正是 1.2 里"提示发虚"的常见原因；
- 索引结果缓存在解决方案的隐藏目录（`.vs`）里，**删掉 `.vs` 会触发全量重建**，非必要不要删；
- 换了工具集、改了包含路径结构之后，**生成 > 重新扫描解决方案** 比干等更快。

## 10. GitHub Copilot 在编辑器里的用法

### 10.1 行内补全与 Copilot Chat

**行内补全**：继续输入时 Copilot 用灰色"幽灵文本"给出整行或整段建议，`Tab` 接受，`Esc` 拒绝，继续打字则自动忽略；写一堆相似的 getter、逐字段的序列化代码、样板测试时最有用。VS 2026 中 C++ 的补全质量有提升——Copilot 会把相关文件作为上下文，减少凭空编造 API 的情况。

**Copilot Chat**（**视图 > GitHub Copilot Chat**）有两种模式：

| 模式 | 做什么 | 适合的问题 |
|------|--------|------------|
| **Ask** | 只回答，不动你的代码 | "这段代码为什么会有数据竞争？""这个模板报错是什么意思？" |
| **Agent** | 直接在解决方案里改代码、建文件、跑命令 | "给 `Packet` 加上序列化与反序列化，并补上单元测试" |

用 Agent 模式要记住两点：它会**同时改多个文件**，改完要逐个审阅 diff 再接受；对不熟悉的仓库，先让它"只解释、先别改"。

### 10.2 右键 Copilot Actions 与 Next Edit Suggestions

在编辑器里**选中一段代码 → 右键**，VS 2026 的右键菜单里新增了一组 **Copilot Actions**：**解释代码**（读陌生代码最实用）、**优化**（性能或可读性建议）、**生成注释**（注意审阅，注释错了比没有更糟）、**生成单元测试**（生成测试脚手架，断言还得自己补）。**Next Edit Suggestions** 则会预判你下一处要改的地方：刚改了某个 API 的调用方式，它提示"接下来这里也要改"，按 `Tab` 跳过去接受即可，做机械式批量修改（加一个参数并同步所有调用点）时效率很高。开关位于 **工具 > 选项 > GitHub > Copilot**。

### 10.3 隐私与关闭方法

- **关闭入口**：**工具 > 选项 > GitHub > Copilot**，在这里可以关掉行内建议、关闭 Copilot Chat。关掉之后 IDE 其它功能完全不受影响——IntelliSense、导航、重构都是本地能力，与 Copilot 无关。
- **临时暂停**：编辑器右下角有 Copilot 状态指示，可以就地暂停建议，不必进选项页。
- **BYOK / BYOM（自带密钥 / 自带模型）**：可在 Copilot Chat 的模型选择器里接入 Microsoft Foundry、OpenAI、Anthropic、Ollama 等提供程序；**接入本地 Ollama 是代码完全不出网的一种折中方案**，但能力与云端模型有差距。
- **内容排除**：仓库级/组织级的排除规则由 GitHub 侧配置，需与管理员确认，不要假设"默认不会上传"。

> **注意**：启用 Copilot 意味着**你正在编辑的代码片段会被发送到服务端**以生成补全请求。合规要求"代码不出内网"时，正确做法是整体关掉它，而不是只关 Chat、留着行内补全。

## 小结

- **IntelliSense 与 MSVC 是两套引擎**：波浪线报错不等于编译失败，反过来也一样——**以编译器为准**。
- 补全与提示的四个核心键：`Ctrl+J`（列出成员）、`Ctrl+Shift+Space`（参数信息）、`Alt+F1`（切换内联提示）、`Ctrl+K, Ctrl+I`（快速信息）。
- 导航体系：`F12` / `Ctrl+F12` / `Alt+F12` 三兄弟，加上 `Shift+F12` 找引用、`Ctrl+T` 找符号、`Ctrl+-` 回原位。
- C++ 专属的螺丝刀建议很值钱：**成员函数加 `const`、全局函数加 `static`、未使用的 `#include` 变灰可一键清理、悬停看大小与对齐**。
- 风格统一靠 **`.editorconfig`**（随仓库走、就近生效）与 **`.clang-format`**（在选项里启用后接管格式化）。
- VS 2026 的编辑新能力记住五个：**C++ 属性高亮**、**右下角改编码**、**查找排除文件**、**右键生成预处理输出**、**全代码库语义索引**（导航与着色快 2 倍以上）。
- Copilot 的开关在 **工具 > 选项 > GitHub > Copilot**；合规要求代码不出网时，**整体关掉**才是正确做法。

## 练习题

1. 写一个只读不写状态的成员函数，观察螺丝刀建议并接受它加上 `const`；再把这个对象以 `const` 引用传给另一个函数，验证加 `const` 前编译失败、加之后通过。
2. 在一个 `.cpp` 里故意包含三个用不到的头文件，用 `Ctrl+.` 的"移除所有未使用的 `#include`"清掉，然后生成一次，确认没有误删；如果有问题，记录是哪个符号导致的。
3. 写一个字段依次为 `char`、`int`、`double` 的 `struct`，悬停查看它的大小与对齐；再调整字段顺序把大小降到最小，并解释填充字节是怎么来的。
4. 定义一个带参数的宏，分别用不带副作用和带副作用的实参调用它，用**右键 > 预处理**生成预处理输出，找出副作用被执行多次的证据。
5. 在仓库根目录放一份 `.editorconfig`（至少包含 `indent_style`、`indent_size`、`end_of_line`、`charset`、`trim_trailing_whitespace`、`insert_final_newline`），新建 `.cpp` 验证生效；再在子目录放一份不同配置，验证"就近生效"。最后写一个自定义代码片段（例如打印变量名与值的 `cwout`），通过 **工具 > 代码片段管理器** 导入并展开一次；如果没生效，检查 XML 结构、`Language` 属性与文件编码。
