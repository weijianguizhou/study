# 11 · 编译工具链与调试

## 11.1 编译引擎对比

LaTeX 的编译引擎经过多年演变，形成了不同的技术路线。理解它们的区别有助于选择最适合自己文档的编译方式。

### 11.1.1 总览

| 引擎 | 命令 | 输出格式 | 编码支持 | 字体方式 | 速度 |
|------|------|---------|---------|---------|------|
| TeX | `tex` / `latex` | DVI | ASCII 仅英文 | 位图/TFM | — |
| pdfTeX | `pdflatex` | **PDF（直接）** | UTF-8（需 inputenc） | 仅 TFM/Type1 | ⚡最快 |
| XeTeX | `xelatex` | PDF | **原生 Unicode** | **系统字体 + OpenType** | 🚀 快 |
| LuaTeX | `lualatex` | PDF | 原生 Unicode | 系统字体 + OpenType + Lua | 🐢 较慢 |
| dvipdfmx | `latex` → `dvipdfmx` | PDF（中转） | UTF-8 支持 | 系统字体 | 🚀 快 |

### 11.1.2 各引擎详细介绍

#### ① pdfTeX (`pdflatex`) — 经典西文首选

pdfTeX 是 TeX 的第一个重大扩展，由 Hàn Thế Thành 开发。它将 TeX 的 DVI 输出路径替换为直接生成 PDF。

**优点**：
- 速度最快，编译大型文档时优势明显
- 与绝大多数宏包兼容性最好
- 成熟的微排版扩展（microtype 宏包的支持最佳）

**缺点**：
- 底层编码仍为 7/8-bit，Unicode 支持是"打补丁"式的
- 处理中文需借助 CJK 宏包（繁琐的字体映射）
- 无法直接调用系统字体，字体配置复杂

**适用场景**：纯西文科技论文、期刊模板（很多期刊仍默认 pdflatex）

#### ② XeTeX (`xelatex`) — 中文和多语言首选

XeTeX 由 Jonathan Kew 开发，设计目标就是解决多语言排版问题。它在 TeX 引擎中直接内置了 Unicode 支持和系统字体接口。

**优点**：
- **原生 Unicode 支持**，无需额外编码转换
- **可直接调用系统字体**，配合 `fontspec` 宏包像 Word 一样选择字体
- 配合 `ctex` 宏包可轻松处理中文排版（自动配置中文字体）
- 是撰写中文文档的事实标准

**缺点**：
- microtype 宏包的字符伸缩（character protrusion）功能受限
- 对某些 TikZ/PGF 复杂计算的极端情况不如 pdfTeX 稳定

**适用场景**：中文文档/学位论文、多语言混排文档、需要特殊字体的设计排版

#### ③ LuaTeX (`lualatex`) — 可编程的下一代引擎

LuaTeX 将 Lua 脚本语言嵌入 TeX 引擎，允许用户在排版层面编写代码控制输出。

**优点**：
- 内嵌 Lua 虚拟机，可编程控制排版细节
- 对 OpenType 字体的支持最完善（特别是阿拉伯语等复杂文字）
- 理论上将逐渐取代 pdfTeX 和 XeTeX

**缺点**：
- **编译速度较慢**，大型文档耗时明显
- 部分老宏包尚未完全兼容（兼容性持续改善中）
- 社区生态仍在过渡阶段

**适用场景**：需要高级字体特性的文档、对排版控制有特殊需求的项目

#### ④ dvipdfmx (`latex` → `dvipdfmx`) — 传统 DVI 路线

传统编译路径：`latex` 先生成 DVI 文件，再由 `dvipdfmx` 转换为 PDF。

**优点**：
- 对中日韩（CJK）文字支持很好（由日本开发者维护）
- 宏包兼容性极广

**缺点**：
- 需要两步操作，不如直接生成 PDF 方便
- 逐渐被 XeTeX 取代

**适用场景**：遗留的老旧项目、特定出版社的模板要求

### 11.1.3 推荐策略

| 文档类型 | 推荐引擎 | 理由 |
|---------|---------|------|
| **中文论文/书籍** | **`xelatex`** | Unicode + 系统字体 + ctex 宏包 |
| 英文科技论文 | `pdflatex` 或 `lualatex` | 期刊模板多数支持 |
| 多语言排版（中日韩、阿拉伯语等） | `xelatex` 或 `lualatex` | 原生 Unicode + OpenType |
| 需要高级微排版效果 | `pdflatex` | microtype 支持最佳 |
| 个人项目/无约束选型 | `xelatex` | 兼容性与便利性平衡最佳 |

> 参考：刘海洋《LaTeX 入门》附录A；Oetiker et al., *The Not So Short Introduction to LaTeX2ε*。

## 11.2 编译流程

**含交叉引用的文档**需执行多次编译。标准流程：

```
xelatex main.tex       # 第1次：生成 .aux 辅助文件
xelatex main.tex       # 第2次：读入 .aux 解决引用
```

**含 BibTeX 参考文献**的流程：

```
xelatex main.tex       # 第1次：写 .aux，标记引用
bibtex   main          # 生成 .bbl 参考文献列表
xelatex main.tex       # 第2次：嵌入参考文献
xelatex main.tex       # 第3次：更新交叉引用
```

**含索引**（MakeIndex）：

```
xelatex main.tex
makeindex main.idx     # 生成 .ind 索引文件
xelatex main.tex
```

**latexmk 自动化**（推荐日常使用）：

```bash
latexmk -xelatex main.tex          # 自动执行所需次数
latexmk -xelatex -pvc main.tex     # 持续监控文件变化，自动重编译
latexmk -c                         # 清理辅助文件
```

## 11.3 常见报错对照

| # | 错误信息 | 原因 | 解决方法 |
|---|---------|------|---------|
| 1 | `! Undefined control sequence.` | 使用了未定义的命令 | 检查拼写，是否忘记 `\usepackage` |
| 2 | `! LaTeX Error: File 'xxx.sty' not found.` | 宏包文件缺失 | 安装宏包（tlmgr install xxx）或检查文件名 |
| 3 | `! Missing $ inserted.` | 数学命令在文本模式使用 | 在公式内使用，或添加 `$...$` |
| 4 | `! Extra }, or forgotten $.` | 括号或数学模式不匹配 | 检查 `{` `}` `$` 配对 |
| 5 | `! LaTeX Error: Environment xxx undefined.` | 环境未定义 | 检查是否加载了对应宏包 |
| 6 | `! Package inputenc Error: Unicode char ...` | 字符编码问题 | 使用 xelatex 或添加 `\usepackage[utf8]{inputenc}` |
| 7 | `! Emergency stop.` | 严重错误强制终止 | 查看之前第一个 Error |
| 8 | `! Dimension too large.` | TeX 内部计算溢出 | 减小数值或使用 `\begin{scope}[fpu=true]` |

## 11.4 调试技巧

**逐一排查法**：先用 `%` 注释掉一半内容，若编译通过则说明错误在另一半中，不断二分缩小范围。

**日志分析**：编译后查看 `.log` 文件。错误行通常以 `!` 开头，TeX 会指出出错位置（行号）。

**辅助工具**：

```latex
% 在导言区加入输出调试信息
\typeout{当前页边距：\the\oddsidemargin}

% 列出所有加载的宏包版本
\listfiles
```

编译时带 `-interaction=nonstopmode` 选项让 TeX 尽量继续而非停等：

```bash
xelatex -interaction=nonstopmode main.tex
```

**MWE（Minimal Working Example）**：制作最小可工作示例是排错的最佳实践——从完整文档中删除无关部分，保留能复现问题的最少代码。
