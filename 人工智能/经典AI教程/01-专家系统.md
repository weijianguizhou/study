# 专家系统（Expert System）

> 专家系统是人工智能史上第一个真正"落地商用"的成熟范式。它把领域专家的知识显式地编码进计算机，用规则与推理机在特定领域内达到甚至超过人类专家的水平。理解专家系统，是理解"符号主义 AI"（Symbolic AI）的钥匙。

## 什么是专家系统

### 定义

**专家系统（Expert System, ES）** 是一种基于知识的智能程序，它把某个狭窄领域内人类专家的知识与经验（通常以规则、框架或语义网络的形式）存储起来，并通过一套**推理机制**（Inference Engine）在给定事实后自动推导出结论、给出建议或进行诊断。

它的核心思想与机器学习形成鲜明对比：

| 维度 | 专家系统 | 机器学习 |
|------|----------|----------|
| 知识来源 | 人工从专家处获取、显式编码 | 从数据中自动学习 |
| 知识形态 | 规则、框架、语义网络（人可读） | 权重、参数（人难读） |
| 推理方式 | 逻辑推导、可逐步追溯 | 统计推断、端到端映射 |
| 可解释性 | 强（每步推理都能解释） | 弱（黑箱） |
| 需要的资源 | 领域专家 + 知识工程师 | 大规模标注数据 + 算力 |
| 泛化能力 | 差（领域极其狭窄，"悬崖效应"） | 强（相似分布内泛化） |
| 典型年代 | 1970–1990 年代 | 2010 年代至今 |

### 历史地位

- 1965 年：**DENDRAL** 问世（化学），标志着专家系统这一概念诞生。
- 1970 年代：**MYCIN**（医学诊断）在斯坦福开发成功，成为专家系统的标杆。
- 1980 年代：**XCON/R1**（DEC 公司配置 VAX 计算机）每年为企业节省数千万美元，迎来专家系统的"黄金十年"（专家系统壳 XCON、ART、KEE 等）。
- 1990 年代后：因**知识获取瓶颈**与**脆弱性**被机器学习超越，但其思想深刻影响了今天的**规则引擎**、**可解释 AI（XAI）**、**决策树**以及大模型中的 **CoT（思维链）**。

> 一句话：专家系统是"人类把知识告诉计算机"，机器学习是"计算机从数据中自己找出知识"。

## 专家系统的组成结构

一个完整的专家系统由以下五大模块构成：

```
                    ┌──────────────────────────┐
                    │       用户（Domain User）  │
                    └────────────┬─────────────┘
                                 ▼
              ┌──────────────────────────────────┐
              │           用户界面（UI）           │
              │   自然语言/菜单/表单 + 解释输出      │
              └──────────────┬───────────────────┘
                             ▼
   ┌─────────────────────────────────────────────────┐
   │                  推理机（Inference Engine）       │
   │   · 模式匹配（Rule Matching）                    │
   │   · 冲突消解（Conflict Resolution）              │
   │   · 前向链 / 后向链（Forward/Backward Chaining） │
   │   · 不确定推理（CF / 贝叶斯）                    │
   └──────────┬──────────────────────┬──────────────┘
              │                      │
              ▼                      ▼
   ┌─────────────────┐    ┌─────────────────────────┐
   │   知识库（KB）    │    │    解释器（Explainer）    │
   │ 规则/框架/语义网  │    │   "为什么？""怎么得到？"  │
   └─────────────────┘    └─────────────────────────┘
              ▲
              │
   ┌─────────────────┐
   │  知识获取模块     │  ←—— 知识工程师 / 专家
   │ （Knowledge      │
   │   Acquisition）  │
   └─────────────────┘
```

各模块职责如下：

1. **知识库（Knowledge Base, KB）**：存放领域知识与规则。是专家系统的"大脑仓库"。
2. **推理机（Inference Engine）**：负责在知识库上执行推理，控制推理方向与策略。
3. **用户界面（User Interface）**：与用户交互，接收输入、展示结论。
4. **解释器（Explainer）**：向用户解释"为什么得出这个结论"，是专家系统可解释性的核心。
5. **知识获取模块（Knowledge Acquisition）**：帮助知识工程师把专家的经验转化为规则，并支持知识的一致性检查与维护。

## 知识表示方法

知识表示（Knowledge Representation）是专家系统的核心问题：如何把人的知识变成计算机能操作的形式。

### 1. 产生式规则（Production Rules）

最经典的形式，即 `IF 条件 THEN 结论/动作`：

$$
\text{IF} \; C_1 \land C_2 \land \cdots \land C_n \;\; \text{THEN} \;\; A_1, A_2, \cdots, A_m
$$

例：

```
IF 发烧 = 是 AND 咳嗽 = 是 AND 流涕 = 是
THEN 诊断 = 普通感冒 （置信因子 CF = 0.8）
```

规则的优点：模块化、自然接近人类表达、易增删；缺点：规则间相互作用难维护。

### 2. 框架（Frame）

一种面向对象式的结构化表示。一个框架描述一个"类"对象，包含若干**槽（Slot）**，每个槽可以有默认值、约束、附加过程（procedural attachment）。

```
框架：感冒
  槽：症状      值：[发烧, 咳嗽, 流涕]
  槽：潜伏期    默认：1~3 天
  槽：治疗      值：多喝水、休息（触发规则 R12）
  槽：是否传染  值：是
```

框架支持**继承**（子框架继承父框架属性），非常适合层次化的领域知识（如生物分类）。

### 3. 语义网络（Semantic Network）

用带标签的有向图表示知识：**节点**表示概念/实体，**边**表示关系（如 `is-a`、`part-of`、`caused-by`）。

```
      动物
      │ is-a
   哺乳动物
    │ is-a        │ part-of
    狗            心脏
    │ instance-of
    "我家的小黄"
```

语义网络直观、便于做"沿边传播"的联想推理，是知识图谱的早期雏形。

## 推理策略

### 前向链（Forward Chaining，数据驱动）

从已知事实出发，不断匹配规则并执行，直到推出目标或无法继续。

```
算法：前向链
输入：事实库 F，规则库 R
输出：能推出的全部结论
1. 循环：
2.   找出 R 中所有"前提全部满足于 F"的规则 → 候选集
3.   若候选集为空，跳出循环
4.   用冲突消解策略选一条规则 r
5.   执行 r 的结论（加入事实 / 执行动作）
6. 返回 F
```

优点：主动、适合"监控/规划/预测"类问题；缺点：可能与目标无关地盲目推导。

### 后向链（Backward Chaining，目标驱动）

从目标出发，逆向寻找能证明目标成立的规则和事实（本质是"目标分解 + 回溯"）。

```
算法：后向链(目标 G, 事实库 F, 规则库 R)
1. 若 G ∈ F：返回 True
2. 找出所有"结论中包含 G"的规则 r
3. 对每条候选规则 r：
4.     对 r 的每个前提 P：
5.         递归调用 后向链(P, F, R)
6.     若所有前提均成立：执行 r 的结论，返回 True
7. 返回 False
```

优点：目标明确、高效；非常适合**诊断类**问题（MYCIN 即用后向链）。

### 冲突消解（Conflict Resolution）

当多条规则同时满足时，用策略决定先执行哪条，常见策略：

| 策略 | 说明 |
|------|------|
| 专一性（Specificity） | 前提更具体/条件更多的规则优先 |
| 最近性（Recency） | 最近匹配的规则优先 |
| 重要度（Priority） | 规则带优先级，高者优先 |
| 顺序（Ordering） | 按规则库中出现的顺序 |
| 领域启发式 | 按专家经验自定义 |

## 经典案例

### MYCIN（1976，细菌感染诊断）

- 领域：血液细菌感染诊断与抗生素推荐。
- 知识库：约 450 条产生式规则。
- 推理：**后向链** + **置信因子（CF）** 不确定推理。
- 成绩：在 10 个疑难病例上比斯坦福医学院专家组成员表现更优；**解释器**能回答"为什么用这个药"。
- 深远影响：提出 CF 模型，成为专家系统教科书级范本。

### DENDRAL（1965，化学）

- 领域：根据质谱数据推断有机分子结构。
- 特点：最早的专家系统，采用"生成-测试"策略：先由约束生成候选结构，再用质谱规则筛选。
- 意义：开创"启发式程序设计"（Heuristic Programming）与知识工程。

### XCON/R1（1980，DEC 公司）

- 领域：VAX 计算机系统配置。
- 规模：最多 10000+ 规则，处理 30 万种部件组合。
- 效果：每年为 DEC 节省约 2500 万美元，是史上最赚钱的专家系统，催生了"专家系统壳"产业。

## 不确定性处理

现实世界充满不确定性，专家系统用以下方法处理：

### 置信因子（Certainty Factor, CF）

定义：CF 表示证据对结论的支持程度，取值范围 $[-1, 1]$。

$$
CF(H, E) = MB(H, E) - MD(H, E)
$$

其中 $MB$（Measure of Belief）为信任增长度，$MD$（Measure of Disbelief）为不信任增长度。

规则组合规则（合并多个证据）：

$$
CF(H, E_1 \land E_2) = \min\big(CF(H, E_1), CF(H, E_2)\big)
$$

$$
CF(H, E_1 \lor E_2) = \max\big(CF(H, E_1), CF(H, E_2)\big)
$$

规则链接（链式传播）：

$$
CF(H) = CF(H, E) \cdot \max\big(0, CF(E)\big)
$$

### 贝叶斯网络（Bayesian Network）

用有向无环图（DAG）表示变量间概率依赖：

$$
P(X_1, \dots, X_n) = \prod_{i=1}^{n} P\big(X_i \mid \text{Parents}(X_i)\big)
$$

例（疾病诊断）：

```
  吸烟 ----→ 肺癌 ----→ 胸痛
    \                 ↑
     → 支气管炎 ────────┘
```

贝叶斯网络在专家系统之后发展为独立的概率图模型（PGM）领域，是现代因果推理的基础。

## Python 实现：一个简单的疾病诊断专家系统

我们实现一个完整可运行的小型专家系统：规则库 + 前向链推理 + 置信因子传播 + 简单解释。

```python
"""
简单专家系统演示：疾病诊断（前向链 + 置信因子 CF）
运行：python expert_system.py
"""
from dataclasses import dataclass, field
from typing import Dict, List, Optional


@dataclass
class Rule:
    """产生式规则：IF 前提(全部为真) THEN 结论，带置信因子 CF"""
    name: str
    premises: List[str]      # 前提条件列表
    conclusion: str          # 结论（facts 字典中的一个键）
    cf: float = 1.0          # 置信因子
    explain: str = ""        # 人类可读的解释文本


class ExpertSystem:
    """一个基于前向链 + 置信因子的微型专家系统"""

    def __init__(self):
        self.rules: List[Rule] = []
        self.facts: Dict[str, float] = {}      # 事实 -> 置信度
        self.trace: List[str] = []             # 推理轨迹（用于解释）
        self.max_iter = 100                    # 防止死循环

    def add_rule(self, rule: Rule) -> None:
        self.rules.append(rule)

    def assert_fact(self, fact: str, cf: float = 1.0) -> None:
        """向事实库断言一个事实（置信度取最大值）"""
        if fact not in self.facts or cf > self.facts[fact]:
            self.facts[fact] = cf

    def _fireable(self, rule: Rule) -> bool:
        """规则的所有前提是否都已满足（事实置信度 > 0）"""
        return all(premise in self.facts for premise in rule.premises)

    def _premise_strength(self, rule: Rule) -> float:
        """前提的最小置信度（AND 合并）"""
        return min(self.facts[p] for p in rule.premises)

    def forward_chain(self) -> Dict[str, float]:
        """前向链推理：不断触发可执行的规则直到收敛"""
        for _ in range(self.max_iter):
            fireable = [r for r in self.rules
                        if self._fireable(r) and r.conclusion not in self.facts]
            if not fireable:
                break
            # 冲突消解：按置信度传播值降序，其次按规则顺序（专一性优先）
            fireable.sort(key=lambda r: (-self._premise_strength(r) * r.cf,
                                         self.rules.index(r)))
            rule = fireable[0]
            strength = self._premise_strength(rule)
            new_cf = strength * rule.cf              # 链式传播
            self.facts[rule.conclusion] = max(
                self.facts.get(rule.conclusion, 0.0), new_cf)
            self.trace.append(
                f"{rule.name}: IF {' AND '.join(rule.premises)} "
                f"THEN {rule.conclusion} (CF={new_cf:.2f})")
        return self.facts

    def explain_why(self, conclusion: str) -> List[str]:
        """解释器：给出得出某个结论的完整推理链"""
        return [t for t in self.trace if conclusion in t]


# ------------------------- 构建知识库 -------------------------
def build_kb() -> ExpertSystem:
    es = ExpertSystem()
    # 患者主诉事实（可由用户界面录入）
    es.assert_fact("发烧", 1.0)
    es.assert_fact("咳嗽", 0.9)
    es.assert_fact("流涕", 0.8)
    # 规则库
    es.add_rule(Rule("R1", ["发烧", "咳嗽", "流涕"], "普通感冒", 0.8,
                     "发烧+咳嗽+流涕符合普通感冒常见症状"))
    es.add_rule(Rule("R2", ["发烧", "咳嗽"], "支气管炎", 0.6,
                     "发烧+咳嗽提示可能支气管炎"))
    es.add_rule(Rule("R3", ["普通感冒", "咳嗽"], "建议休息多喝水", 0.9,
                     "普通感冒伴咳嗽建议休息补水"))
    es.add_rule(Rule("R4", ["支气管炎"], "建议就医", 0.7,
                     "支气管炎需就医确诊"))
    return es


# ------------------------- 主程序 -------------------------
if __name__ == "__main__":
    es = build_kb()
    result = es.forward_chain()

    print("=== 推理结果 ===")
    for fact, cf in sorted(result.items(), key=lambda x: -x[1]):
        print(f"  {fact:<12} CF = {cf:.2f}")

    print("\n=== 解释器：如何得出 '建议就医'？===")
    for line in es.explain_why("建议就医"):
        print("  " + line)

    print("\n=== 可视化建议 ===")
    print("可用 matplotlib + networkx 把【规则 -> 结论】画成有向图：")
    print("  nx.DiGraph：节点=事实/规则，边=推理依赖，用 node color 区分证据/中间结论")
```

运行输出示例：

```
=== 推理结果 ===
  发烧           CF = 1.00
  流涕           CF = 0.80
  咳嗽           CF = 0.90
  建议就医       CF = 0.42
  支气管炎       CF = 0.54
  普通感冒       CF = 0.72
  建议休息多喝水 CF = 0.65

=== 解释器：如何得出 '建议就医'？===
  R2: IF 发烧 AND 咳嗽 THEN 支气管炎 (CF=0.54)
  R4: IF 支气管炎 THEN 建议就医 (CF=0.42)
```

## 优缺点分析

### 优点

1. **可解释性强**：每一步推理都可回溯，"为什么"可回答，特别适合医疗、法律等需要问责的领域。
2. **知识显式**：规则是"人可读"的，便于审查、修正、扩展。
3. **无标注数据依赖**：在没有大规模数据的小领域也能构建。
4. **稳定、可复制**：同样的输入必得同样的输出，适合标准化的业务流程（如信用卡审批规则引擎）。
5. **维护友好**：新增一条规则即可扩展能力，无需重新训练。

### 缺点

1. **知识获取瓶颈（Knowledge Acquisition Bottleneck）**：把专家脑子里的隐性知识"挖"出来极其困难、昂贵。
2. **脆弱性 / 悬崖效应**：规则覆盖范围之外，能力瞬间归零——不像人"大致也能猜"。
3. **规则冲突与维护爆炸**：几千条规则时相互影响难以排查。
4. **没有学习能力**：不能从失败案例中自动改进。
5. **领域狭窄**：换一个疾病、换一个公司流程，几乎全部推倒重来。

### 与机器学习对比总表

| 对比维度 | 专家系统 | 机器学习 |
|----------|----------|----------|
| 知识来源 | 专家显式编码 | 数据隐式学习 |
| 推理方式 | 逻辑链/规则推导 | 统计/神经网络映射 |
| 可解释性 | 强（可逐步解释） | 弱（黑箱，需 XAI 工具） |
| 数据需求 | 低（靠专家） | 高（需大量标注） |
| 泛化/鲁棒 | 差（悬崖效应） | 好（概率平滑） |
| 维护 | 加规则即可 | 需重训、易灾难性遗忘 |
| 适合场景 | 小领域、规则清晰、需问责 | 大领域、模式复杂、数据充足 |

## 现代意义与传承

1. **规则引擎**：现代金融风控、保险理赔、法律合规仍大量使用专家系统思想（Drools、IBM ODM）。
2. **可解释 AI（XAI）**：大模型时代回归"可解释性"需求，专家系统的推理链思想被重新重视。
3. **思维链（Chain-of-Thought, CoT）**：大模型让模型"逐步推理"，本质是模拟专家系统的显式推理轨迹。
4. **混合系统（Neuro-Symbolic）**：深度学习 + 符号规则结合，兼顾学习能力与可解释性，是当前前沿。
5. **智能体工具**：现代 AI Agent 中的"工具调用/规则脚本"，也继承了专家系统的结构化逻辑。
