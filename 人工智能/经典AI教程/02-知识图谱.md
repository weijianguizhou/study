# 知识图谱（Knowledge Graph）

> 知识图谱是用**图（Graph）**来组织世界知识的方式：实体是节点，关系是边。2012 年 Google 提出并用于增强搜索引擎，让搜索从"关键词匹配"进化为"理解语义"。它是连接符号主义 AI 与现代大模型（RAG、GraphRAG）的桥梁。

## 什么是知识图谱

### 定义

**知识图谱（Knowledge Graph, KG）** 是一种以**图结构**存储的知识库，图中的**节点**表示实体（Entity）或概念，**边**表示实体之间的关系（Relation）。它遵循"语义网"（Semantic Web）的理念，用标准化的三元组表示知识，支持机器自动理解、推理与检索。

2012 年 5 月，Google 正式发布 **Google Knowledge Graph**，在搜索框旁展示实体卡片（名人、电影、地点等），标志着"知识图谱"这一术语进入主流。

### 与普通数据库的区别

| 维度 | 关系型数据库（RDBMS） | 知识图谱 |
|------|----------------------|----------|
| 数据模型 | 表 / 外键 | 图 / 三元组 |
| 查询方式 | SQL（多表 JOIN） | SPARQL / Cypher / 图遍历 |
| 关系表达 | 外键间接表达 | 边直接表达，天然支持多跳 |
| 模式约束 | 强（Schema 固定） | 灵活（本体可演进） |
| 推理支持 | 弱 | 强（规则 / 图算法 / 表示学习） |
| 典型场景 | 事务处理（OLTP） | 关联查询、推荐、问答 |

## 核心概念

### 三元组（Triple）

知识图谱的最小单元是**三元组**：

$$
(h,\ r,\ t)
$$

其中 $h$ 为头实体（head），$r$ 为关系（relation），$t$ 为尾实体（tail）。

例：

```
(姚明, 出生于, 上海)
(姚明, 效力于, 休斯顿火箭)
(休斯顿火箭, 属于联盟, NBA)
```

一条三元组也可以把关系反写，形成反向边：`(上海, 是姚明的出生地, 姚明)`。

### 实体（Entity）、关系（Relation）、属性（Attribute）

- **实体**：真实世界中的具体对象或抽象概念，如"姚明"、"上海"、"Python"。
- **关系**：实体之间的语义联系，如"出生于"、"效力于"、"包含"。
- **属性**：实体的特征值，如"姚明"的"身高 = 226cm"、"出生日期 = 1980-09-12"。属性常建模为实体到字面量的边。

### 本体（Ontology）

**本体**是知识图谱的"模式层"（Schema），定义了概念类别（Classes）、属性、关系类型及其层级与约束。

```
本体片段（RDFS 风格）：
  人 ⊂ 生物
  运动员 ⊂ 人
  出生于 : Person → Place
  效力于 : Athlete → Team
```

本体让知识图谱可推理：若"运动员 ⊂ 人"且"姚明 : 运动员"，可推出"姚明 : 人"。

## 知识图谱构建流程

完整构建流水线（Knowledge Graph Construction Pipeline）：

```
  数据源（网页/文档/数据库/多模态）
       │
       ▼
  ① 知识抽取（Knowledge Extraction）
       │  NER / 关系抽取 / 属性抽取
       ▼
  ② 知识融合（Knowledge Fusion）
       │  实体对齐 / 实体消歧 / 冲突消解
       ▼
  ③ 知识存储（Knowledge Storage）
       │  图数据库 Neo4j / RDF 三元组库 / 向量库
       ▼
  ④ 应用与更新（应用 + 增量维护）
```

### ① 知识抽取

从非结构化文本中提取结构化知识：

- **命名实体识别（NER）**：识别"人名 / 地名 / 机构名 / 时间"等实体。
- **关系抽取（Relation Extraction）**：识别句子中实体间的关系，如"姚明生于上海" → `(姚明, 出生于, 上海)`。
- **属性抽取（Attribute Extraction）**：抽取实体属性值。

典型工具：SpaCy、Stanford CoreNLP、哈工大 LTP、以及基于大模型的抽取 Pipeline。

### ② 知识融合

多个来源的知识需要合并去重：

- **实体对齐（Entity Alignment）**：判断两个实体指向同一对象（"NBA" == "National Basketball Association"）。
- **实体消歧（Entity Disambiguation）**：区分同名实体（"苹果"指水果还是公司）。
- **冲突消解**：处理矛盾事实（"北京人口 2189 万" vs "2170 万"）。

### ③ 知识存储

两类主流方案：

| 方案 | 代表 | 特点 |
|------|------|------|
| 图数据库 | Neo4j、Amazon Neptune | Cypher 查询、图遍历快、适合多跳分析 |
| RDF 三元组库 | Jena TDB、Virtuoso | 标准语义栈（RDF/OWL/SPARQL），适合开放数据与推理 |
| 向量/键值存储 | FAISS、Milvus + Embedding | 面向语义检索，与 LLM/RAG 结合（GraphRAG） |

Neo4j Cypher 示例：

```cypher
CREATE (yaoming:Person {name: '姚明', height: 226})
CREATE (shanghai:City {name: '上海'})
CREATE (rockets:Team {name: '休斯顿火箭'})
CREATE (yaoming)-[:BORN_IN]->(shanghai)
CREATE (yaoming)-[:PLAYS_FOR]->(rockets);

// 查询：姚明效力于哪个联盟？
MATCH (y:Person {name: '姚明'})-[:PLAYS_FOR]->(:Team)-[:IN_LEAGUE]->(league)
RETURN league.name;
```

## 知识图谱表示学习（Knowledge Graph Embedding）

目标：把实体与关系映射到低维连续向量空间，使"语义相近"的向量"距离相近"，从而支撑链接预测、实体对齐与推理。

### TransE（2013）

核心假设：头实体向量 + 关系向量 ≈ 尾实体向量：

$$
h + r \approx t
$$

得分函数（越小越好）：

$$
f(h, r, t) = \|\, h + r - t \,\|
$$

损失函数（margin-based）：

$$
\mathcal{L} = \sum_{(h,r,t)\in S} \sum_{(h',r',t')\in S'} \max\big(0,\; \gamma + f(h,r,t) - f(h',r',t')\big)
$$

其中 $\gamma$ 为 margin，$S'$ 为通过替换头/尾生成的负样本。

### TransH / TransR

- **TransH**：把实体投影到关系超平面再做平移，解决一对多/多对一关系：
  $$
  h_{\perp} = h - w_r^{\top} h\, w_r, \qquad t_{\perp} = t - w_r^{\top} t\, w_r
  $$
  $$
  f(h, r, t) = \| h_{\perp} + r - t_{\perp} \|
  $$
- **TransR**：用关系矩阵 $\mathbf{M}_r$ 把实体映射到关系专属空间：
  $$
  f(h, r, t) = \|\, \mathbf{M}_r h + r - \mathbf{M}_r t \,\|
  $$

| 模型 | 空间 | 表达能力 | 参数量 | 适用关系 |
|------|------|----------|--------|----------|
| TransE | 单一向量空间 | 弱（不能建模一对多） | 少 | 一对一 |
| TransH | 关系超平面 | 中 | 中 | 一对多/多对一 |
| TransR | 关系专属空间 | 强 | 多 | 复杂/多种关系 |
| DistMult | 对角双线性 | 中 | 少 | 对称关系 |
| RotatE | 复数旋转 | 强 | 中 | 关系建模精细 |

## Python 实现一：用 networkx 构建知识图谱并查询

```python
"""
知识图谱基础演示：networkx 建图 + 关系查询 + 路径搜索
运行：python kg_basic.py
"""
import networkx as nx
import matplotlib.pyplot as plt


def build_kg() -> nx.MultiDiGraph:
    """构建一个小型人物/作品知识图谱（MultiDiGraph 支持多重关系）"""
    G = nx.MultiDiGraph()
    # 三元组列表: (h, r, t)
    triples = [
        ("姚明", "出生于", "上海"),
        ("姚明", "效力于", "休斯顿火箭"),
        ("姚明", "国籍", "中国"),
        ("休斯顿火箭", "属于联盟", "NBA"),
        ("中国", "位于", "亚洲"),
        ("上海", "位于", "中国"),
        ("科比", "效力于", "洛杉矶湖人"),
        ("洛杉矶湖人", "属于联盟", "NBA"),
        ("科比", "国籍", "美国"),
        ("NBA", "赛事性质", "篮球职业联赛"),
    ]
    for h, r, t in triples:
        G.add_edge(h, t, relation=r)
    return G


def query_relations(G: nx.MultiDiGraph, entity: str):
    """查询某实体的所有直接关系"""
    print(f"=== 实体「{entity}」的直接关系 ===")
    for _, t, data in G.out_edges(entity, data=True):
        print(f"  {entity} --{data['relation']}--> {t}")


def query_multi_hop(G: nx.MultiDiGraph, start: str, end: str):
    """多跳路径查询（简单推理）"""
    print(f"\n=== 从「{start}」到「{end}」的路径 ===")
    for path in nx.all_simple_paths(G, start, end, cutoff=3):
        print("  → ".join(path))


if __name__ == "__main__":
    G = build_kg()
    query_relations(G, "姚明")
    query_multi_hop(G, "姚明", "NBA")
    query_multi_hop(G, "姚明", "篮球职业联赛")

    # 可视化建议
    print("\n=== 可视化建议 ===")
    print("1) 将 networkx 图用 spring_layout 布局，plt.show() 直接出图")
    print("2) 用 pyvis 输出交互式 HTML 图，节点可拖拽、按关系着色")
    print("3) 用 neo4j 库连接真实图数据库，跑 Cypher 多跳查询")
    pos = nx.spring_layout(G, seed=42, k=1.2)
    nx.draw_networkx(G, pos, with_labels=True,
                     node_color="lightblue", font_size=10)
    nx.draw_networkx_edge_labels(
        G, pos, edge_labels={(u, v): d["relation"] for u, v, d in G.edges(data=True)},
        font_size=7)
    # plt.show()  # 取消注释以显示
```

## Python 实现二：从零实现 TransE

```python
"""
TransE 知识图谱嵌入（从零实现，纯 numpy）
目标：学出实体/关系向量，使 h + r ≈ t
运行：python transe.py
"""
import numpy as np


class TransE:
    def __init__(self, entities, relations, dim=50, margin=1.0, lr=0.01):
        self.dim = dim
        self.margin = margin
        self.lr = lr
        self.entity2id = {e: i for i, e in enumerate(entities)}
        self.rel2id = {r: i for i, r in enumerate(relations)}
        self.n_ent = len(entities)
        self.n_rel = len(relations)
        # 向量初始化（单位长度，保证 |h + r - t| 有界）
        rng = np.random.default_rng(42)
        self.E = rng.uniform(-1, 1, (self.n_ent, dim))
        self.R = rng.uniform(-1, 1, (self.n_rel, dim))
        self._normalize_embeddings()

    def _normalize_embeddings(self):
        self.E /= np.linalg.norm(self.E, axis=1, keepdims=True) + 1e-9

    def _score(self, h, r, t):
        return np.linalg.norm(h + r - t, axis=1)

    def corrupt(self, triple):
        """负采样：随机替换头或尾实体"""
        h, r, t = triple
        if np.random.rand() < 0.5:
            h = np.random.randint(0, self.n_ent)
        else:
            t = np.random.randint(0, self.n_ent)
        return h, r, t

    def train(self, triples, epochs=100, batch_size=64):
        triples = np.array([[self.entity2id[h], self.rel2id[r],
                             self.entity2id[t]] for h, r, t in triples])
        for epoch in range(epochs):
            rng = np.random.default_rng(epoch)
            idx = rng.permutation(len(triples))
            losses = []
            for i in range(0, len(idx), batch_size):
                batch = triples[idx[i:i + batch_size]]
                h, r, t = batch[:, 0], batch[:, 1], batch[:, 2]
                # 负样本
                h_neg, t_neg = h.copy(), t.copy()
                neg = np.random.rand(h.shape[0]) < 0.5
                h_neg[neg] = rng.integers(0, self.n_ent, size=neg.sum())
                t_neg[~neg] = rng.integers(0, self.n_ent, size=(~neg).sum())
                # 前向
                pos_s = self._score(self.E[h], self.R[r], self.E[t])
                neg_s = self._score(self.E[h_neg], self.R[r], self.E[t_neg])
                loss = np.maximum(0, self.margin + pos_s - neg_s)
                losses.append(loss.mean())
                # 梯度（近似：对向量直接更新）
                for k in range(h.shape[0]):
                    if pos_s[k] - neg_s[k] < -self.margin:
                        continue
                    e_h, e_t, e_h2, e_t2 = self.E[h[k]], self.E[t[k]], \
                                           self.E[h_neg[k]], self.E[t_neg[k]]
                    e_r = self.R[r[k]]
                    g1 = (e_h + e_r - e_t) / (np.linalg.norm(e_h + e_r - e_t) + 1e-9)
                    g2 = (e_h2 + e_r - e_t2) / (np.linalg.norm(e_h2 + e_r - e_t2) + 1e-9)
                    self.E[h[k]] -= self.lr * (g1 - g2)
                    self.E[t[k]] -= self.lr * (-g1)
                    self.E[h_neg[k]] -= self.lr * (-g2)
                    self.E[t_neg[k]] -= self.lr * (g2)
                    self.R[r[k]] -= self.lr * (g1 - g2)
                self._normalize_embeddings()
            if epoch % 20 == 0:
                print(f"epoch {epoch:3d}  loss = {np.mean(losses):.4f}")
        print("训练完成。")


if __name__ == "__main__":
    # 小型知识库
    entities = ["姚明", "上海", "中国", "亚洲", "科比", "洛杉矶",
                "休斯顿火箭", "NBA", "美国"]
    relations = ["出生于", "国籍", "效力于", "位于", "属于联盟", "赛事性质"]
    triples = [
        ("姚明", "出生于", "上海"), ("上海", "位于", "中国"),
        ("中国", "位于", "亚洲"), ("姚明", "国籍", "中国"),
        ("姚明", "效力于", "休斯顿火箭"), ("休斯顿火箭", "属于联盟", "NBA"),
        ("科比", "出生于", "洛杉矶"), ("美国", "位于", "北美洲"),
        ("科比", "国籍", "美国"), ("洛杉矶湖人", "属于联盟", "NBA"),
    ]
    model = TransE(entities, relations, dim=30, margin=1.0, lr=0.01)
    model.train(triples, epochs=60)

    # 链接预测示例：谁出生于上海？
    print("\n=== 链接预测：(?, 出生于, 上海) 排序 ===")
    scores = []
    for e in entities:
        h = model.entity2id[e]; r = model.rel2id["出生于"]; t = model.entity2id["上海"]
        scores.append((e, model._score(model.E[h:h+1], model.R[r:r+1],
                                       model.E[t:t+1])[0]))
    for e, s in sorted(scores, key=lambda x: x[1])[:4]:
        print(f"  {e:<6} 距离 = {s:.4f}")

    print("\n=== 可视化建议 ===")
    print("1) 用 sklearn.decomposition.PCA / TSNE 把 30 维向量降到 2D 散点图")
    print("2) 用 matplotlib 标注实体名，观察聚类与关系向量方向")
```

## 典型应用

### 搜索引擎（Google Knowledge Graph）

搜索"姚明"右侧出现"身高 / 效力球队 / 妻子 / 简介"结构化卡片。查询语义从关键词扩展到"实体 + 关系 + 属性"。

### 推荐系统

以"用户—商品—标签"构建图谱，用**协同过滤 + 知识图谱**做多跳推荐解释（如"因为你喜欢《流浪地球》，而它和《三体》同属刘慈欣作品"）。

### 问答系统（KBQA）

把自然语言问题转换为对知识图谱的查询（实体链接 → 意图解析 → 图查询/推理）：

> "姚明效力过的球队属于哪个联盟？" → `MATCH (y:Person{name:'姚明'})-[:PLAYS_FOR]->(t)-[:IN_LEAGUE]->(l) RETURN l`

### 医疗 / 金融知识图谱

- 医疗：药品—疾病—症状—靶点关系，辅助诊断与用药禁忌核查。
- 金融：公司—股权—高管—风险事件关联，反欺诈、关联风控。

### 与向量数据库 / RAG 的关系

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 向量数据库（RAG） | 文本切块 → Embedding → 相似度检索 | 简单、可回答开放式问题 | 缺乏结构关联、难以多跳 |
| 知识图谱 | 显式实体关系图 | 精确、可多跳推理、可解释 | 构建维护成本高、覆盖有限 |
| GraphRAG（微软） | KG + LLM 结合 | 全局性、多跳、可解释 | 管线复杂、成本高 |

在大模型时代，**知识图谱 + RAG** 正在融合：用图谱提供结构化事实与推理路径，用 LLM 提供语言理解与生成，两者互补。

## 优缺点

| 优点 | 缺点 |
|------|------|
| 表达力强：实体关系直观、可多跳 | 构建与维护成本高（知识抽取、融合难） |
| 可解释、可审计 | 覆盖不全（长尾知识缺失） |
| 支持符号推理与规则推理 | 与自然语言有语义鸿沟 |
| 与图算法/表示学习结合多样 | 冷启动与实时更新困难 |
| 是"可信知识"的锚点 | 开放世界仍有不确定与噪声 |

## 现代意义

- **本体与模式**：OWL/RDFS 语义栈仍是语义网的标准，工业界在用它做数据治理。
- **GraphRAG**：把知识图谱注入 LLM 检索管线，成为 RAG 升级方向。
- **神经符号融合**：TransE 等嵌入与符号推理结合，是"能学又能推"的研究前沿。
- **数字孪生/监管科技**：金融、医疗、政务用知识图谱做关联分析与合规审计。
