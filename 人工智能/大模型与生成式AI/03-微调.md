# 微调

> 提示工程是在"冻结"的模型上做文章；**微调（Fine-Tuning）**则直接修改模型参数，把模型"练成"某个领域/风格/任务的专家。全参微调成本高，因此实践中以 **LoRA / QLoRA** 等参数高效微调（PEFT）为主。本篇给出完整原理与可运行代码。

## 1. 为什么需要微调

### 1.1 Prompt 不够用的场景

| 场景 | Prompt 的困境 | 微调的价值 |
|------|--------------|-----------|
| 垂直领域（医疗、法律、金融） | 通用模型缺乏领域黑话与范式 | 注入领域知识、术语、格式 |
| 产品风格统一 | 每次都要写一大段风格约束 | 把风格"焊死"进模型 |
| 指令遵循 | 模型老是不按格式输出 | 用指令数据强化格式遵循 |
| 私有数据 | 数据不能出域（合规） | 本地训练本地用 |
| 长上下文任务 | 每次注入太多示例成本高 | 一次学会，推理省上下文 |
| 推理成本 | 大模型贵、慢 | 用小模型微调逼近大模型效果（蒸馏思路） |

### 1.2 微调 vs 提示工程 vs RAG

```
                     知识/能力从哪来？
   ┌─────────────────────────────────────────────┐
   │  修改参数（记忆最"深"，训练成本高）             │
   │    └── 微调（SFT/RLHF/DPO）                  │
   │  上下文注入（即时、灵活、不持久）               │
   │    ├── 提示工程（示例、CoT）                  │
   │    └── RAG（外部知识检索）                    │
   │  两者常组合：RAG 提供事实，微调提供格式/风格    │
   └─────────────────────────────────────────────┘
```

**决策建议**：
- 需要**固定行为/格式** → 微调；
- 需要**实时知识** → RAG；
- 先 Prompt，再 RAG，最后才微调（成本从低到高）。

## 2. 全参微调（Full Fine-Tuning）

### 2.1 定义与流程

对预训练模型的所有参数 $\theta$，在任务数据 $D$ 上继续优化：

$$
\theta^* = \arg\min_\theta \mathbb{E}_{(x,y) \sim D}\left[ -\sum_t \log P_\theta(y_t \mid x, y_{<t}) \right]
$$

流程：加载预训练权重 → 在任务数据上训练若干 epoch → 保存权重 → 评估 → 部署。

### 2.2 与预训练的区别

| 维度 | 预训练 | 全参微调 |
|------|--------|----------|
| 数据 | 万亿级通用文本 | 万~百万级任务数据 |
| 学习率 | 低（稳定） | 稍高但有上限 |
| 目的 | 获取世界知识 | 适配具体任务 |
| 成本 | 万卡·月 | 单卡~数卡·小时 |
| 风险 | — | 过拟合、灾难性遗忘 |

### 2.3 代价与风险

- **显存**：7B 模型 fp16 全参微调约需 60–140 GB 显存（含优化器状态）；
- **灾难性遗忘**：新任务学太好会"忘掉"通用能力；
- **过拟合**：数据少时迅速在训练集上饱和；
- **难复用**：每个任务一个完整模型副本。

缓解：低学习率、少量 epoch、混入通用语料、经验回放、参数高效微调。

## 3. LoRA（低秩适配）

### 3.1 核心思想

LoRA（Hu et al., 2021）认为：微调时权重更新的 $\Delta W$ 具有**低秩性**。因此不直接学 $\Delta W$，而是把它分解成两个小矩阵的乘积：

$$
W' = W + \Delta W = W + BA, \quad B \in \mathbb{R}^{d_{\text{in}} \times r}, \; A \in \mathbb{R}^{r \times d_{\text{out}}}
$$

前向计算：

$$
h = W'x = Wx + BAx
$$

**训练时**：冻结 $W$，只训练 $A, B$（参数量从 $d_{\text{in}} \times d_{\text{out}}$ 降到 $r \times (d_{\text{in}} + d_{\text{out}})$，$r \ll \min(d_{\text{in}}, d_{\text{out}})$）。
**推理时**：可将 $W' = W + BA$ 合并为单一矩阵，**不增加任何推理开销**。

### 3.2 初始化与缩放

- $A$ 用高斯分布初始化，$B$ 初始化为 0，保证训练开始时 $BA = 0$，模型输出不变；
- 前向时对 $BAx$ 乘缩放因子 $\alpha / r$，防止更新过大：

$$
h = Wx + \frac{\alpha}{r} BAx
$$

### 3.3 参数量计算示例

对隐藏层 $d_{\text{model}} = 4096$，线性层权重 $W \in \mathbb{R}^{4096 \times 4096}$：

| rank $r$ | 全参 | LoRA 参数量 $r(d_{in}+d_{out})$ | 减少比例 |
|----------|------|-------------------------------|----------|
| 8 | 16.7M | 65K | ~257× |
| 16 | 16.7M | 131K | ~128× |
| 64 | 16.7M | 524K | ~32× |

一个 7B 模型，只在 Q/K/V/O 上做 $r=8$ 的 LoRA，可训练参数仅约 **0.1%–1%**。

### 3.4 为什么 LoRA 有效

1. **本质梯度低秩**：实验发现微调中梯度的主方向集中在少数奇异方向，低秩子空间足以捕获任务信号；
2. **正则效应**：大幅减少可训练参数，天然抗过拟合；
3. **可插拔**：多个 LoRA 可以共享基座模型，按需切换（多任务只存一份基座 + 多个小适配器）；
4. **可合并**：推理时 $W + BA$ 合并，延迟零增加。

### 3.5 LoRA 关键超参

| 超参 | 作用 | 常用值 |
|------|------|--------|
| `r` | 秩，越大表达力越强 | 8 / 16 / 32 |
| `alpha` | 缩放因子，影响学习强度 | 8–64，通常 2×r |
| `target_modules` | 适配哪些层 | q/k/v/o、gate/up/down |
| `dropout` | LoRA dropout | 0.05–0.1 |
| `lr` | 学习率 | 1e-4 ~ 3e-4（比全参高） |

## 4. QLoRA：4bit 量化 + LoRA

QLoRA（Dettmers et al., 2023）解决"小显存微调大模型"：把基座模型量化到 4bit，再叠加 LoRA。

- **NF4（Normal Float 4）**：基于正态分布的分位数量化，比均匀 4bit 更精确；
- **双重量化**：对量化常数再做 8bit 量化，进一步省显存；
- **Paged Optimizer**：优化器状态溢出时自动换页到 CPU，避免 OOM。

效果：**7B 模型微调只需约 6–8 GB 显存**，与跑一个 Llama 2 7B 的推理显存相当。

### 4.1 量化带来的精度损失

| 方法 | 精度损失 | 显存（7B 微调） | 适用 |
|------|----------|-----------------|------|
| fp16 全参 | 基准 | 60–140 GB | 有钱有卡 |
| fp16 + LoRA | 很小（<1%） | 14–18 GB | 主流方案 |
| QLoRA (4bit) | 可忽略（1–3%） | 6–8 GB | 单卡玩家 |
| 8bit + LoRA | 很小 | 8–10 GB | 折中 |

## 5. 其他 PEFT 方法

### 5.1 方法对比

| 方法 | 修改位置 | 增加参数量 | 原理 |
|------|----------|-----------|------|
| LoRA | 权重低秩增量 | 极小 | $W + BA$ |
| Adapter | 每层插入小网络 | 小 | $x \to \text{Dropout} \to \text{Down} \to \text{ReLU} \to \text{Up} \to x + h$ |
| Prefix-Tuning | 前缀 token 向量 | 小 | 在 K/V 前拼接可学习向量 |
| P-Tuning | embedding 层软提示 | 极小 | 可学习的 prompt 向量 |
| IA3 | 激活向量缩放 | 极小 | 学习缩放向量 $l_W$ 乘在激活上 |

**Adapter** 前向（LayerNorm 后插入）：

$$
h \leftarrow h + W_{\text{up}}\left( \text{ReLU}\left( W_{\text{down}}\left( \text{LN}(h) \right) \right) \right)
$$

**Prefix-Tuning**：为每个注意力头拼接前缀键值 $P_K, P_V$（长度为 $l$）：

$$
\text{Attn}(x; [P_K; K], [P_V; V])
$$

注意：Prefix/P-Tuning 在推理时**不能合并**，会引入额外计算；LoRA 可合并，因此实践中占主导。

### 5.2 选择建议

- 默认选 **LoRA / QLoRA**（效果、速度、可合并均衡）；
- 数据极少、任务极轻 → P-Tuning（参数量最小）；
- 需要最强效果、不差钱 → 全参微调或全参 + LoRA 混合；
- 快速切换多任务 → 多 LoRA 挂载同一基座。

## 6. 微调数据构建

### 6.1 数据量级参考

| 数据规模 | 效果 | 说明 |
|----------|------|------|
| 100–1K 条 | 可学到风格/格式 | 常配 few-shot 提示 |
| 1K–10K 条 | 稳定学会一种任务 | 最常用区间 |
| 10K–100K 条 | 领域能力明显增强 | 需清洗与去重 |
| >100K 条 | 接近领域专家模型 | 训练成本上升 |

### 6.2 指令数据格式

SFT 常用 chat 模板（与 `apply_chat_template` 一致）：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个法律咨询助手。"},
    {"role": "user", "content": "试用期内被辞退有补偿吗？"},
    {"role": "assistant", "content": "根据《劳动合同法》第三十九条..."}
  ]
}
```

**数据质量 > 数量**：去重、去噪声、对齐角色、保证答案正确性，比堆数量更重要。

### 6.3 SFT 训练细节

- 损失只算 `assistant` 部分（mask 掉 user/system）；
- 学习率：LoRA 1e-4~3e-4，全参 1e-5~2e-5；
- epoch：小数据 2–4 个，大数据 1–2 个；
- 最大序列长度：按数据分布设定，过长浪费显存；
- 混合少量通用数据缓解遗忘。

## 7. SFT → RLHF/DPO 的衔接

微调不是终点：

```
预训练 Base Model
   │  SFT：学"怎么说"（格式、风格、遵循指令）
   ▼
SFT 模型
   │  RLHF / DPO：学"什么该说"（人类偏好、安全、有用性）
   ▼
对齐模型
```

- **SFT** 优化的是"像标注者"的分布；
- **RLHF** 优化的是"被人类偏好"（Bradley–Terry 模型 + PPO，见 [[01-大语言模型原理|LLM 原理]] 6.3）；
- **DPO** 用偏好对直接构造损失，无需显式奖励模型：

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\log \sigma\left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right)
$$

工程上：SFT 数据（指令对）与偏好数据（好/坏回答）分开构建；先 SFT 后 DPO 是开源对齐的主流组合。

## 8. 过拟合与灾难性遗忘

| 问题 | 表现 | 对策 |
|------|------|------|
| 过拟合 | 训练集 loss 低、验证集高 | 更多数据、early stopping、LoRA、dropout、数据增强 |
| 灾难性遗忘 | 通用能力、旧任务退化 | 混入通用语料、低 lr、少 epoch、知识蒸馏 |
| 格式过拟合 | 只会一种格式 | 数据多样性、模板随机化 |

**评估手段**（详见 [[../机器学习教程/01-模型评估与交叉验证|模型评估]]）：切分训练/验证集，用 held-out 测试集对比微调前后的通用 benchmark（如 MMLU、GSM8K、本领域测试集）。

## 9. Python 实战：用 PEFT 微调开源小模型

以 Qwen2.5-0.5B 为例做 LoRA 微调，单张 16GB 卡即可完成（甚至 CPU 可跑小规模）。

```bash
pip install transformers peft datasets accelerate bitsandbytes
```

```python
import torch
from transformers import (
    AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer,
    DataCollatorForLanguageModeling,
)
from peft import LoraConfig, get_peft_model, TaskType

# 1. 加载模型（可加 load_in_4bit 做 QLoRA）
model_id = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.float16,
    device_map="auto",
    # quantization_config=BitsAndBytesConfig(load_in_4bit=True),  # QLoRA
)

# 2. 配置 LoRA
lora_cfg = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,                 # 秩
    lora_alpha=16,       # 缩放
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    bias="none",
)
model = get_peft_model(model, lora_cfg)
print("可训练参数:", model.print_trainable_parameters())  # 约占总量 0.3%

# 3. 构造指令数据（示例：两条）
samples = [
    ("把下面句子翻译成英文：你好，世界。", "Hello, world."),
    ("把下面句子翻译成英文：今天天气很好。", "The weather is nice today."),
]

def build_prompt(inst, out=None):
    p = f"<|im_start|>user\n{inst}<|im_end|>\n<|im_start|>assistant\n"
    return p + (out if out else "")

texts = [build_prompt(i, o) for i, o in samples]
tokenizer.pad_token = tokenizer.eos_token

def tokenize(t):
    enc = tokenizer(t, truncation=True, max_length=256, padding=True)
    enc["labels"] = enc["input_ids"].copy()
    return enc

from datasets import Dataset
ds = Dataset.from_dict({"text": texts}).map(lambda x: tokenize(x["text"]))

# 4. 训练
trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir="./lora_qwen",
        per_device_train_batch_size=2,
        num_train_epochs=3,
        learning_rate=2e-4,
        logging_steps=10,
        save_strategy="epoch",
        report_to=[],
        fp16=torch.cuda.is_available(),
    ),
    train_dataset=ds,
    data_collator=DataCollatorForLanguageModeling(tokenizer, mlm=False),
)
trainer.train()

# 5. 保存与合并（合并后推理零额外开销）
model.save_pretrained("./lora_qwen_final")
merged = model.merge_and_unload()
merged.save_pretrained("./qwen_merged_full")
```

```python
# 推理验证
merged.eval()
prompt = build_prompt("把下面句子翻译成英文：这是一个测试。")
inputs = tokenizer(prompt, return_tensors="pt")
out = merged.generate(**inputs, max_new_tokens=64, do_sample=False)
print(tokenizer.decode(out[0], skip_special_tokens=True))
# 期望: <|im_start|>assistant
# This is a test.
```

**关键点回顾**：
- `target_modules` 要匹配模型实际层名（不同模型不同，Qwen 是 `q_proj/k_proj/...`）；
- QLoRA 只需加 `load_in_4bit=True` + `BitsAndBytesConfig`；
- 小数据、小模型演示流程，真实任务请放大数据并切分验证集。
