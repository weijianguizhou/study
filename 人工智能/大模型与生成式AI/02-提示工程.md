# 提示工程

> 提示工程（Prompt Engineering）是**不修改模型参数**、仅通过设计输入文本（Prompt）来引导 [[01-大语言模型原理|LLM]] 输出的技术。它依托于 LLM 的上下文学习（ICL）能力：模型会在输入中"现学现用"。成本最低、见效最快，是所有 LLM 应用的入口技能。

## 1. 什么是 Prompt，为什么重要

### 1.1 Prompt 的定义

Prompt 是给模型的完整输入文本，通常包含：**系统指令 + 用户指令 + 示例 + 上下文 + 输出格式要求**。

```
┌─────────────────────────────────────────┐
│ [System]  你是一个资深 Python 工程师…      │  ← 角色设定
│ [User]    请把下面代码重构为使用 dataclass  │  ← 任务
│ [Example] 输入:… 输出:…                    │  ← few-shot 示例
│ [Context] 相关代码片段…                    │  ← 参考信息（RAG）
│ [Format]  仅输出 JSON: {"code": ...}      │  ← 格式约束
└─────────────────────────────────────────┘
```

### 1.2 为什么"怎么写"比"模型"还重要

- **ICL 效应**：模型的能力在推理时被 prompt 中的示例"即时激活"，同样的模型、不同 prompt，效果可以天差地别（[[01-大语言模型原理|LLM 原理]] 3.3 节）；
- **零成本迭代**：改 prompt 比重新训练快几个数量级；
- **接口即产品**：API 调用本质是工程化 prompt 模板；
- **可观测可调试**：prompt 是文本，可记录、可回放、可测试。

### 1.3 Prompt 的"成败维度"

| 维度 | 含义 | 常见问题 |
|------|------|----------|
| 准确性 | 是否答对 | 指令含糊、歧义 |
| 格式 | 是否按约定输出 | 输出 JSON 不合法 |
| 长度 | 是否啰嗦/截断 | 无长度约束、max_tokens 过小 |
| 一致性 | 同题是否稳定 | 采样随机性、prompt 不鲁棒 |
| 安全性 | 是否泄露/越狱 | prompt 注入、敏感数据 |

## 2. 基本技巧

### 2.1 清晰指令（Be Specific）

- 用**动词开头**的祈使句："总结""翻译""列出""比较"；
- 给出**约束条件**：长度、风格、受众、禁止事项；
- 避免**模棱两可**的词："简略地""合适的"。

### 2.2 分隔符（Delimiters）

用分隔符把"指令"和"数据"分开，降低歧义与注入风险：

```
请把【】中的内容翻译成英文：
【变压器是一种基于自注意力机制的深度神经网络模型。】
```

常见分隔符：`"""`、`<>`、`【】`、`###`、XML 标签 `<user_input>...</user_input>`。

### 2.3 Few-shot 示例（In-Context Learning）

给 2–5 个"输入→输出"示例，让模型模仿格式与推理模式：

```
判断商品评论情感（只输出 积极/消极）：

输入：质量很好，发货快。            → 积极
输入：用了一天就坏了，客服还推诿。  → 消极
输入：价格公道，物流慢了点。        → 积极
输入：包装破损，商品有划痕。        → 
```

**Few-shot 设计要点**：
- 示例要覆盖**边界情况**（转折句、反讽）；
- 示例顺序会影响性能（把"难例"放最后）；
- 示例要与测试分布接近（选相似样本）；
- 过多数量的示例收益递减，且占上下文。

### 2.4 结构化输出（JSON / Markdown）

要求模型输出合法 JSON，便于程序解析。常用技巧：

1. **给出 schema 示例**；
2. **限定字段名**；
3. **要求"只输出 JSON，不要多余文字"**；
4. 配合 `response_format={"type": "json_object"}` 或 Function Calling 更稳（见 06 篇）。

## 3. 进阶技巧

### 3.1 Chain-of-Thought（思维链，CoT）

Wei et al. (2022)：让模型**显式输出中间推理步骤**，大幅提升多步推理准确率。机制直觉：

- 模型每一步推理受限于"即时涌现"，把推理过程写下来相当于**扩展了注意力可及的有效工作记忆**；
- 推理链把大任务分解为小步骤，每步的错误概率 $p$ 相乘，但**每步正确率显著提升**，总体 $P_{\text{correct}} \approx \prod p_i$ 反而更高；
- 与人类"草稿纸"同理：写出来 > 心算。

**Zero-shot CoT**：只需在指令后加一句：

```
请一步一步推理，最后给出答案。
```

**Few-shot CoT**：示例中包含推理过程：

```
Q: 小明有 3 个苹果，又买了 5 个，吃掉了 2 个，还剩几个？
A: 先算总数 3+5=8，再减去吃掉的 2，8-2=6。答案：6。

Q: 一间教室 6 排座位，每排 8 个，坐了 42 人，还有多少空位？
A:
```

**提示风格差异**：直接问"哪个大？"往往答错；加"让我们一步步想"后正确率显著提升（GSM8K 等算术任务上可从 18% 提到 60%+）。

### 3.2 Self-Consistency（自我一致性）

CoT 的采样扩展：让模型**多次采样**推理链，然后对最终答案**投票**：

$$
\hat{y} = \arg\max_{y} \sum_{i=1}^{k} \mathbb{1}[\text{answer}_i = y]
$$

其中 $k$ 是采样次数（常取 5–20）。原理：正确的推理路径在"推理空间"中是多数派，投票可过滤单条路径的错误。用 temperature $>0$ 采样多次。

### 3.3 ReAct：推理 + 行动交替

ReAct 把"思考（Reasoning）"与"行动（Acting）"交替进行，是 Agent 的基础（详细见 [[06-AI智能体|AI 智能体]]）：

```
Thought: 我需要查询北京今天的天气。
Action: search("北京天气")
Observation: 晴，27°C，微风
Thought: 天气不错，回答用户问题。
Answer: 北京今天晴，27°C，微风，适宜出行。
```

### 3.4 角色扮演（Role Prompting）

给模型设定角色可激活特定知识领域与文风：

```
你是一位拥有 20 年经验的算法工程师，擅长从工程视角分析问题。
请以文档形式给出方案。
```

**为什么有效**：角色词在预训练语料中与大量对应风格的文本共现，相当于做了一次"分布内检索"。

### 3.5 思维树（Tree of Thoughts, ToT）

CoT 是单条路径；ToT 让模型**在每一步生成多个候选，并用评估器打分、回溯搜索**：

```
步骤 1: 生成 3 个候选推理分支
步骤 2: 对每个分支打分，选前 2 个
步骤 3: 继续扩展，直至找到可行解
```

适合游戏谜题、组合优化等探索型任务；代价是调用次数多、成本高。

## 4. 上下文学习：机制再深入

ICL 在 [[01-大语言模型原理|LLM 原理]] 3.3 已有讨论，提示工程层面记住三条实操结论：

1. **示例 > 描述**：给 2 个具体例子，通常比 50 字抽象说明更有效；
2. **格式传递**：模型学的是"输入→输出"的映射模式，示例中怎么排、怎么标，输出就会怎么来；
3. **顺序敏感**：示例与指令的摆放顺序影响性能，测试时 A/B 一下。

## 5. 常见问题与对策

| 问题 | 现象 | 对策 |
|------|------|------|
| 幻觉 | 编造事实/引用 | 要求"不确定就说不确定"；接 [[04-RAG检索增强生成|RAG]] |
| 输出过长 | 废话多 | 限字数/限条数、`max_tokens`、"只给结论" |
| 输出过短 | 答案太简 | 要求"分条、带解释、给出理由" |
| 格式不稳 | JSON 解析失败 | 给 schema、`response_format`、正则兜底 |
| 忽略指令 | 不遵守约束 | 约束放前面、重复强调、few-shot 示范 |
| Prompt 注入 | 用户输入劫持指令 | 分隔符隔离、输入过滤、系统指令后置 |
| 回答不一致 | 同题不同答 | 降 temperature、Self-Consistency、缓存 |

### 5.1 Prompt 注入防护

攻击：用户输入包含"忽略之前所有指令……"。防御：

- 用分隔符把用户输入与指令隔离；
- 对输入做黑名单/白名单过滤；
- 关键操作（删除、转账）需人工确认；
- 用独立模型判断"输入是否可疑"。

## 6. 提示工程工作流：评估与迭代

提示工程不是"写一次就完"，而是一个**围绕评估集的迭代循环**：

```
建立评估集(20-50条 golden) → 跑基线 → 分析失败 → 改进 prompt
        ↑                                           │
        └─────────────── 回归测试 ←────────────────┘
```

### 6.1 建立评估集

- 每条含：输入、期望输出（或判分标准）、难度标签；
- 覆盖：常规、边界、反例、注入攻击；
- 来源：真实日志采样 + 人工构造。

### 6.2 自动评估方式

| 方式 | 原理 | 适用 |
|------|------|------|
| 规则判分 | 正则/包含/相似度 | 结构化输出 |
| 参考匹配 | 与 golden 的语义相似度（embedding） | 摘要/改写 |
| LLM-as-Judge | 用强模型对输出打分 | 开放生成 |
| 人工评审 | 抽样人工打分 | 上线前终审 |

### 6.3 迭代策略（按性价比排序）

1. **改措辞**：明确动词、加约束、删冗余；
2. **加示例**：针对失败模式补 few-shot；
3. **加结构**：分步骤指令、XML/JSON 模板；
4. **换策略**：CoT → Self-Consistency → ToT；
5. **换模型**：以上都试过才考虑升档模型。

> 一句话：**先让评估集说话，再动手改 prompt**；没有评估集的一切"优化"都是玄学。

## 7. Python 实战

### 7.1 OpenAI 风格 API 对话（本地或云端）

```python
# pip install openai
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",  # 本地 vLLM/Ollama 也兼容
    api_key="sk-xxx",                     # 本地可随便填
)

resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[
        {"role": "system", "content": "你是一个简洁的中文助手，回答不超过 50 字。"},
        {"role": "user", "content": "请用一句话解释什么是提示工程。"},
    ],
    temperature=0.3,
)
print(resp.choices[0].message.content)
```

### 7.2 Few-shot 示例（代码生成 + 补全）

```python
few_shot = [
    {"role": "user", "content": "用 Python 写一个求和函数，返回列表元素之和。"},
    {"role": "assistant", "content": 'def mysum(lst):\n    return sum(lst)'},
    {"role": "user", "content": "用 Python 写一个反转字符串的函数。"},
]

resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=few_shot + [{"role": "user", "content": "用 Python 写一个判断回文数的函数。"}],
    temperature=0.2,
)
print(resp.choices[0].message.content)
```

### 7.3 JSON 结构化输出

```python
resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    response_format={"type": "json_object"},
    messages=[
        {"role": "system", "content": '输出严格为 JSON，仅包含字段 "title", "tags", "summary"。'},
        {"role": "user", "content": "请总结下面这段文章：\n\n" + article_text},
    ],
)

import json
data = json.loads(resp.choices[0].message.content)  # 解析失败时兜底重试
print(data["title"], data["tags"])
```

### 7.4 本地 transformers 生成（无需 API）

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")

messages = [
    {"role": "system", "content": "你是中文助手。"},
    {"role": "user", "content": "用一句话介绍深度学习的自注意力机制。"},
]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tokenizer(text, return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=100, temperature=0.5, top_p=0.9)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

## 8. 提示模板库与最佳实践

### 8.1 常用模板骨架

```
[System]
你是{角色}。你遵循以下规则：
1. {规则1}
2. 不确定时明确说"不确定"，不要编造。
3. 输出格式：{格式}

[User]
任务：{任务描述}
输入：
{数据}

要求：
- {约束1}
- {约束2}
```

### 8.2 各场景模板速查

| 场景 | 关键要素 | 一句话模板 |
|------|----------|-----------|
| 摘要 | 长度、语言、重点 | "用 3 句话、中文，概括要点，保留数据" |
| 翻译 | 目标语言、风格 | "翻译成英文，保持技术术语准确" |
| 抽取 | 字段、格式 | "从文本中抽取 JSON: {name, price, tags}" |
| 改写 | 风格、语气 | "改写为更正式/更口语/更简洁的版本" |
| 分类 | 类别清单 | "判断属于哪一类，只输出类别名" |
| 代码 | 语言、约束 | "用 Python 实现，附注释，处理边界情况" |
| 反思 | 修正逻辑 | "指出错误并给出修正后的答案" |

### 8.3 最佳实践清单

1. **从精确开始，逐条加约束**（先测基线再增强）；
2. **指令数据分离**（分隔符 + 变量注入）；
3. **示例与任务同分布**；
4. **固定 temperature**（评估时用 0，部署时按需调）；
5. **建立评估集**（20–50 条 golden 样本，回归测试每次改 prompt）；
6. **版本管理 prompt**（模板即代码，纳入 git）；
7. **兜底与重试**（JSON 解析失败重试、限流退避）。
