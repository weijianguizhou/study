# 大语言模型原理

> 大语言模型（Large Language Model, LLM）是基于 [[../深度学习教程/12-Transformer与大模型|Transformer]] 的自回归语言模型：给定上文，预测下一个 token。看似简单的目标，配上足够大的模型与数据，却涌现出推理、规划、上下文学习等能力。本篇回答三个问题：**它怎么训练？能力从哪来？有什么天花板？**

## 1. 什么是 LLM

### 1.1 形式化定义

LLM 是一个参数化概率模型，对 token 序列 $\mathbf{x} = (x_1, x_2, \dots, x_n)$ 建模联合概率，并通过**链式法则**分解为逐 token 的条件概率乘积：

$$
P(x_1, x_2, \dots, x_n) = \prod_{t=1}^{n} P(x_t \mid x_1, x_2, \dots, x_{t-1})
$$

由于是逐 token 生成，被称为**自回归（autoregressive）**。训练目标就是最大化整个语料的这个概率，等价于最小化**交叉熵损失**：

$$
\mathcal{L} = -\frac{1}{N} \sum_{i=1}^{N} \sum_{t=1}^{n_i} \log P_\theta(x^{(i)}_t \mid x^{(i)}_{<t})
$$

其中 $P_\theta$ 是参数为 $\theta$ 的 Transformer，$N$ 是序列数。

### 1.2 为什么说"语言模型"

- **唯一目标**：预测下一个词。这与 BERT 的双向掩码建模不同——LLM 只能看到左边（因果）。
- **通用框架**：任何任务（翻译、问答、写代码）都可以被改写成"输入上文 → 续写下文"，因此**任务即文本**。
- **概率性质**：输出是一整个 token 分布，解码策略（贪心、采样、top-k/top-p）决定最终文本。

### 1.3 与 Transformer 章的关系

Transformer 架构在 [[../深度学习教程/12-Transformer与大模型|Transformer 与大模型]] 中已完整推导，本篇**只补充 LLM 特有的部分**：

1. **因果掩码**（causal mask）：训练时禁止位置 $t$ 看到 $>t$ 的 token。
2. **位置编码 RoPE**（旋转位置编码）：相对位置信息编码。
3. **KV Cache**：推理时缓存已算的 Key/Value。
4. **MoE**：混合专家，稀疏激活。

## 2. 预训练目标：下一个词预测

### 2.1 为什么"预测下一个词"如此强大

预测下一个词迫使模型完成隐式的多任务学习：

- 预测动词时，要理解**语法**（主谓一致、时态）；
- 预测实体时，要理解**世界知识**（"中国的首都是____"）；
- 预测代码时，要理解**逻辑与库接口**；
- 预测对话回复时，要理解**意图与情感**。

**Chinchilla（2022）经验法则**：最优训练预算下，参数量 $N$ 与数据量 $D$ 应按约 20 token / 参数分配，即 $D \approx 20N$。

### 2.2 交叉熵损失的展开

对单个位置 $t$，模型输出 logits $\mathbf{z} \in \mathbb{R}^{|V|}$，经 softmax 得概率分布：

$$
P_\theta(x_t \mid x_{<t}) = \frac{\exp(z_{x_t})}{\sum_{v \in V} \exp(z_v)}
$$

损失对 logits 的梯度为 $z_j - P(x_j)$（logits 减概率），恰好是"误差信号"，反向传播非常干净：

$$
\frac{\partial \mathcal{L}}{\partial z_j} = P(x_j) - \mathbb{1}[j = x_t]
$$

### 2.3 解码策略（生成时用）

训练用交叉熵，生成时选 token 的策略直接影响质量：

| 策略 | 做法 | 特点 |
|------|------|------|
| 贪心解码 | 每步取概率最大的 token | 快，但重复、缺乏多样性 |
| 随机采样 | 按分布采样 | 多样但可能不连贯 |
| Top-k | 只在 top-k 中采样 | 控制长尾噪声 |
| Top-p（核采样） | 在累计概率 p 的最小集合中采样 | 最常用，兼顾质量与多样 |
| Temperature | logits 除以 $T$ 后 softmax | $T\to 0$ 趋近贪心，$T$ 大更随机 |

Temperature 的数学：$P(x) \propto \exp(z_x / T)$，$T>1$ 使分布更平缓（更随机），$T<1$ 更尖锐（更确定）。

## 3. 核心能力来源

### 3.1 缩放定律（Scaling Laws）

Kaplan et al. (2020) 提出 loss 与参数量 $N$、数据量 $D$、计算量 $C$ 呈**幂律关系**：

$$
L(N) = a \cdot N^{-\alpha} + L_0
$$

$$
L(D) = b \cdot D^{-\beta} + L_0
$$

$$
L(C) = c \cdot C^{-\gamma} + L_0
$$

其中 $\alpha, \beta, \gamma$ 是常数（约 $\alpha \approx 0.076$，$\beta \approx 0.095$），$L_0$ 是语料本身的不可约熵。含义：

- **幂律**：想降低 loss，参数量/数据量/算力需指数级增长，收益递减；
- **loss 与任务性能强相关**：更低的 loss 往往意味着更强的下游能力；
- **预测性**：可以用小模型拟合缩放曲线，外推大模型的性能，指导算力预算。

### 3.2 涌现能力（Emergent Abilities）

跨过某个规模阈值后，某些能力**突然出现**且不可用平滑曲线外推：多步算术、遵循复杂指令、上下文学习、思维链。三种主流解释：

1. **相变观**：参数规模跨越临界点后表征能力质变；
2. **度量观**（Wei et al. 2022 的"阶梯指标"）：像准确率这样的非连续指标放大了连续能力的突变；
3. **组合观**：能力来自若干子能力（分解、检索、对齐格式）的组合，子能力各自平滑增长，组合结果看似涌现。

> 工程启示：小模型与大模型的差距并非"懂与不懂"，而是"能力涌现的规模阈值"。选择模型时看任务是否落在该模型已涌现的能力范围内。

### 3.3 上下文学习（In-Context Learning, ICL）

GPT-3 的发现：**不更新参数**，只在 prompt 里给几个示例，模型就能学会做新任务。机制解释：

1. **模式匹配**：示例激活了预训练中见过的相似任务模式；
2. **隐式贝叶斯**：示例相当于先验，模型在隐空间中做后验推理；
3. **任务向量**（最近研究）：ICL 等价于在表征空间中叠加一个"任务方向"。

数学直觉（隐空间中的"学习"）：模型在隐藏层里维护一个隐变量 $\theta_{\text{task}}$，示例更新它对输出的影响可写作对 $h$ 的线性偏移：

$$
h_{\text{new}} = h + \alpha \cdot \underbrace{(g(\text{example}_1) - g(\text{example}_0))}_{\approx \text{任务方向}}
$$

## 4. 架构细节（LLM 特有）

### 4.1 因果掩码（Causal Mask）

自注意力的完整形式（已在 Transformer 章推导）。LLM 只保留下三角：

$$
\text{MaskedAttention}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_k}} + \mathbf{M}\right)\mathbf{V}
$$

其中掩码矩阵 $M_{ij} = -\infty$（当 $i < j$）否则 $0$，使 softmax 后 $i<j$ 处的权重为 0，保证位置 $i$ 只看到 $j \le i$。

### 4.2 旋转位置编码（RoPE）

绝对位置编码无法表达相对位置。RoPE（Su et al., 2021）将位置信息以**旋转矩阵**方式注入 Q/K 向量：对第 $m$ 个位置、第 $i$ 个维度对，旋转角度 $\theta_i = 10000^{-2i/d}$：

$$
R_m = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix}, \quad
\mathbf{q}'_m = R_m \mathbf{q}_m
$$

关键性质——点积只依赖**相对位置差**：

$$
(R_m \mathbf{q})^T (R_n \mathbf{k}) = \mathbf{q}^T R_{n-m} \mathbf{k}
$$

RoPE 的优势：相对位置感知、外推性好（长上下文）、可被 $\theta$ 的缩放插值到更长序列。

### 4.3 KV Cache

推理时生成第 $t$ 个 token，只需与历史 $t-1$ 个 token 做注意力。把历史上所有 $\mathbf{K}, \mathbf{V}$ 缓存起来，避免重复计算：

```
输入: q_new ──► Q                              ┌──► 注意力输出
              K_new ──► 追加到 KV Cache ───────┤
              V_new ──► 追加到 KV Cache ───────┘
```

KV Cache 大小随序列长度线性增长：每层每头需要 $2 \times \text{seq\_len} \times d_k$ 个浮点数。对 7B 模型、4096 上下文，KV Cache 约占用 0.5–1 GB，是推理显存的主要开销之一（详见 07 篇）。

### 4.4 混合专家（MoE, Mixture-of-Experts）

MoE 把前馈网络替换为 $N$ 个专家（Feed-Forward 子网络），每 token 由路由网络激活 Top-$k$ 个专家：

$$
y = \sum_{i \in \text{Top-}k(\text{softmax}(W_r x))} g_i \cdot \text{FFN}_i(x)
$$

门控得分 $g_i$ 来自 router（一个线性层 + softmax）：

$$
g = \text{softmax}(W_r x) \in \mathbb{R}^{N}, \quad k \ll N
$$

**效果**：总参数量大（容量大、记住更多知识），但每 token 只算 $k/N$ 的 FFN 参数（算力省）。DeepSeek-V3（671B 总参 / 37B 激活）就是典型例子。

**代价**：多专家模型显存要求高、分布式训练复杂度大、路由可能失衡（需要辅助负载均衡损失）。

## 5. Tokenization：BPE 分词算法

### 5.1 为什么需要分词

模型不能直接吃字符或单词。字符序列过长（信息密度低），单词表过大（OOV 问题）。**子词（subword）分词**折中：常见词整词，生僻词拆成子词。

### 5.2 BPE（Byte-Pair Encoding）算法

迭代式合并最频繁的字节/字符对：

```
1. 从字符（或字节）级别的序列开始
2. 统计所有相邻符号对的频次
3. 合并频次最高的对，加入词表
4. 重复直到词表达到目标大小（如 32k/100k/150k）
```

示例：语料中 `low` 与 `lowest` 高频，"lo"、"low" 会成为词表条目；`lowermost` 则被切成 `low` + `ermost`。

### 5.3 常用 Tokenizer 对比

| 算法 | 代表模型 | 特点 |
|------|----------|------|
| BPE | GPT 系列、Llama | 简单高效，字节级解决 OOV |
| WordPiece | BERT | 基于似然增量而非频次选合并对 |
| SentencePiece | Llama、Qwen | 直接对原始文本/字节建模，无需预分词，支持多语言 |
| 字节级 BPE | GPT-2 起 | 词表固定 256 字节起步，兼容所有 Unicode |

> 注意：LLM 的"知识量"与其 tokenizer 词表（vocabulary size）和上下文长度强相关。中文在 BPE 下通常一个字约 0.5–2 个 token，这影响 API 计费。

## 6. 训练三阶段

### 6.1 阶段一：预训练（Pre-training）

在万亿级原始文本上做 next-token 预测（第 2 节）。产出 **Base Model**：知识丰富但"不会好好说话"——它接话，不回答问题。

### 6.2 阶段二：SFT（Supervised Fine-Tuning）

用人工标注的 `<指令, 期望回复>` 对继续训练。损失变为在**回复部分**的交叉熵：

$$
\mathcal{L}_{\text{SFT}} = -\sum_{t \in \text{reply}} \log P_\theta(x_t \mid x_{<t})
$$

把"续写分布"校准成"对话分布"。产出 **Instruct Model**（如 ChatGPT 的第一版训练）。

### 6.3 阶段三：RLHF

#### Reward Model 训练

收集人类对同一问题的多个回答的**偏好排序**，训练奖励模型 $R_\phi$，用 Bradley–Terry 模型建模成对偏好概率：

$$
P(\text{answer}_A \succ \text{answer}_B) = \sigma\left(R_\phi(s, a_A) - R_\phi(s, a_B)\right)
$$

奖励模型损失（最大化偏好似然）：

$$
\mathcal{L}_{RM} = -\mathbb{E}_{(s, a_w, a_l)}\left[ \log \sigma\left( R_\phi(s, a_w) - R_\phi(s, a_l) \right) \right]
$$

其中 $a_w$ 是被更偏好的回答，$\sigma$ 是 sigmoid 函数。

#### PPO 简述

用奖励模型作为"打分器"，用 PPO 更新策略 $\pi_\theta$，同时用 KL 惩罚防止策略漂移过远：

$$
\text{maximize } \mathbb{E}_{s \sim \rho, a \sim \pi_\theta}\left[ R_\phi(s, a) \right] - \beta \cdot \text{KL}\left( \pi_\theta(\cdot \mid s) \| \pi_{\text{ref}}(\cdot \mid s) \right)
$$

RLHF 本质是把"人类偏好"翻译成优化目标。完整的 PPO 推导见 [[../RL-PPO理论|PPO]]。

#### DPO（Direct Preference Optimization）

RLHF 需要训练 RM + 跑 PPO，工程复杂。DPO（2023）发现：奖励最大化的最优策略有闭式解，可以直接把偏好信号变成**无需显式 RM 的监督式损失**：

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(x, y_w, y_l)}\left[ \log \sigma\left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)} \right) \right]
$$

直觉：提升被偏好回答 $y_w$ 的相对概率，压低 $y_l$。DPO 只需 SFT 的算力，却获得近似 RLHF 的对齐效果，是当下开源微调的主流。

### 6.4 三阶段对比

| 阶段 | 数据 | 目标 | 产出 | 成本 |
|------|------|------|------|------|
| 预训练 | 万亿级原始文本 | next-token 预测 | Base Model | 极高（万卡·月级） |
| SFT | 十万~百万级指令对 | 回复部分交叉熵 | Instruct Model | 高（数百 A100 卡时） |
| RLHF/DPO | 偏好对 | 最大化奖励 / 偏好似然 | 对齐模型 | 中 |

> 现实：绝大多数工程师不参与预训练，只做 SFT/DPO（见 [[03-微调|微调]]）或直接用 API。

## 7. 上下文窗口与长文本

**上下文窗口**是模型一次能"看到"的 token 数。现代模型从 4K → 128K → 1M（Gemini）不断扩张。扩展手段：

- **位置插值（PI）**：将 RoPE 角度按比例缩小，适配更长序列；
- **外推（extrapolation）**：直接加大训练长度，成本高；
- **YaRN / NTK 缩放**：按频率调整旋转基数，兼顾短长序列；
- **长文本注意力变体**：Sliding Window、Sparse Attention、Ring Attention。

上下文窗口不是"变长那么简单"：长文本上注意力质量会稀释（"lost in the middle"），长序列训练与推理显存、算力都暴涨。

## 8. 能力与局限

### 8.1 能力清单

- 自然语言理解与生成（翻译、摘要、改写）
- 代码生成与调试
- 逻辑推理（与思维链提示强相关，见 02 篇）
- 上下文学习、少样本学习
- 工具调用（Function Calling，见 06 篇）

### 8.2 三大根本局限

**幻觉（Hallucination）**：模型会生成看似合理实则错误的内容，因为它的目标函数是"像文本"而非"求真"。缓解手段：RAG（[[04-RAG检索增强生成|RAG]]）、约束解码、事实核查。

**推理能力有限**：复杂符号推理、长链逻辑易出错，本质是 next-token 目标并不直接优化"正确推理"。缓解：CoT、程序化执行（写代码跑结果）。

**知识截止（Knowledge Cutoff）**：知识固定在训练语料时刻，无法感知训练后的世界。缓解：RAG、联网工具、定期重训。

### 8.3 其他工程局限

- 上下文窗口有限（放不下整个项目/全书）；
- 输出的 token 级不确定性（同题不同答）；
- 计算成本与延迟（见 [[07-推理与部署|推理与部署]]）；
- 安全与偏见问题（需对齐与治理）。

## 9. Python 实战：加载一个小模型做推理

用 transformers 加载一个 0.5B 级的开源模型（可 CPU 运行），体验"下一个词预测"的机制：

```python
# pip install transformers
from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "Qwen/Qwen2.5-0.5B-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

prompt = "中国的首都是"
inputs = tokenizer(prompt, return_tensors="pt")

outputs = model.generate(**inputs, max_new_tokens=50, do_sample=False)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
# 输出示例: 中国的首都是北京。北京是中国的政治、文化、国际交往和科技创新中心...
```

**观察预训练 vs 指令微调的行为差异**：

```python
# 尝试不带 Instruct 的 base 模型，体会"接话"与"回答"的区别
# base 模型会倾向于继续补全而非分点回答
model_name_base = "Qwen/Qwen2.5-0.5B"   # 无 Instruct 后缀

# 手动演示下一个词分布（只看第一个生成 token）
logits = model(inputs.input_ids).logits
next_token_logits = logits[0, -1, :]
top5 = next_token_logits.topk(5)
for tok, score in zip(top5.indices.tolist(), top5.values.tolist()):
    print(tokenizer.decode([tok]), ":", round(score.item(), 2))
```

**手动实现"带温度采样"的解码**：

```python
import torch
import torch.nn.functional as F

def sample_next(logits, temperature=1.0, top_p=0.9):
    logits = logits / temperature
    # top-p 过滤
    sorted_logits, sorted_idx = logits.sort(descending=True)
    cumsum = sorted_logits.softmax(dim=-1).cumsum(dim=-1)
    mask = cumsum - sorted_logits.softmax(dim=-1) > top_p
    sorted_logits[mask] = float("-inf")
    logits = torch.zeros_like(logits).scatter(-1, sorted_idx, sorted_logits)
    probs = F.softmax(logits, dim=-1)
    return torch.multinomial(probs, 1)

next_id = sample_next(next_token_logits)
print("采样结果:", tokenizer.decode(next_id))
```
